# 기술·이동 속도를 원작에 맞추기 — 계획 (2026-10-04, 등급 M · 다음 세션)

**요청(사용자 2026-10-04)**: 유튜브 영상에서 기술·이동 속도를 재서 반영. 더 나은 방법도 견줘서.
**성공**: 걷기 한 칸, 평타·기술 몸 동작, 마법 이펙트의 빠르기가 원작과 같다고 근거(숫자 + 출처)를 댈 수 있고,
우리 화면을 같은 장면으로 녹화해 나란히 보면 차이가 눈에 안 띈다.
**안 할 것**: 서버 전투 수치(쿨·데미지) 바꾸기, 새 이펙트.

## 지금 값 (`mobile/src/Lod.Mobile.Core/Tuning.cs`)
- 걷기 한 칸 `StepSeconds = 0.44` — 원작 0.28 로 적어 둔 값에서 사용자가 손맛으로 30%+10% 늦춤.
- 돌기만 하는 짧은 누름 `TurnHoldSeconds = 0.2`, 몸 동작 `MotionSlowdown = 1.1`(서버 `0x1A` 속도 × 1.1).
- 이펙트 번호·속도는 노바가 기준(`data/CLAUDE.md`).
→ 근거가 약한 것: **0.28 의 출처**, **`0x1A` 속도를 1/100초로 읽는 해석**(`docs/original-sprite-animation.md` 314줄, "적힌 곳은 없고").

## 방법 비교 (위가 정확, 아래로 갈수록 보조)
| 방법 | 얻는 것 | 약점 |
|---|---|---|
| **A. 원작 클라이언트 실행 파일 읽기** — `~/Downloads/5.99 클라이언트` 의 exe 를 objdump(서버 exe 를 읽은 방식, 메모리 「5.99 서버 실행 파일」) | 걷기 타이머·프레임 간격·`0x1A` 속도 해석 상수를 숫자로 | 함수 찾기에 시간. 5.99 판 기준 |
| **B. 노바 서버팩 자료** — 기술·마법의 동작 번호·속도 칸 | 서버가 보내는 속도 원값 | 클라이언트가 그걸 어떻게 쓰는지는 A 가 필요 |
| **C. 원작 클라이언트를 우리 서버에 붙여 녹화** — 맥에 wine 없음, 윈도우 PC 필요 | 판이 같은 원작의 실제 화면, 프레임 단위 | 실행 환경 마련, 사용자 PC 필요 |
| **D. 유튜브 영상 재기** — `yt-dlp`(맥에 없음, brew 로 설치) + `ffmpeg`(있음) | 옛 플레이 감각, 다른 판 비교 | 30fps·압축·서버 지연·판 불명 → 오차 ±1프레임(33ms) 이상, 확인용으로만 |

**권하는 순서**: A(숫자) → B(원값 맞추기) → D 로 감각 확인. C 는 A 가 막힐 때만.
영상은 "결정"이 아니라 "검산" — 한 칸 걸음을 10칸 이상 재서 평균, 시간은 프레임 번호로 잰다.

## 단계
1. **영상 고르기(사용자)**: 걷기·평타·무도가 기술이 잘 보이는 유튜브 주소 2~3개(판·연도 알면 함께).
2. **영상 재기**: `yt-dlp` 로 받고 `ffmpeg` 로 프레임을 시각과 함께 떨군다. 칸을 넘는 프레임·동작 시작/끝 프레임을
   사진으로 골라(눈으로 확인) 초를 계산. 자동 추적은 안 한다.
3. **원작 숫자**: 5.99 클라이언트 exe 에서 걷기 이동 간격·동작 프레임 간격 상수 찾기(A), 노바 기술 속도 칸 대조(B).
4. **우리 쪽 녹화**: Godot 녹화 모드(`docs/mobile-client.md` 371줄)로 같은 동작을 찍어 같은 방식으로 재기.
5. **표로 비교 → 반영**: 걷기·동작·이펙트마다 「원작(출처) · 영상 · 우리」 표. `Tuning.cs` 를 바꿀지는 **사용자가 정한다**
   (0.44 는 사용자가 일부러 늦춘 값이라 그대로 둘 수 있다).
