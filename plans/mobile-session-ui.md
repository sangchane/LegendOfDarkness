# 모바일 세션 UI 복구 계획

## 배경

현재 코드와 `docs/mobile-client.md`가 어긋난다. 문서는 계정 생성 화면이 가로에서 세 칸으로
재배치된다고 적었지만, `mobile/client/src/CreateScreen.cs` 는 방향 분기 없이 세로 한 열만
만든다. `GameScreen.cs` 에는 로그아웃 조작과 로그인 화면으로 돌아가는 경로가 없다.
가로의 `MessageLog` 는 조작줄 안에서 방향판 위의 남는 너비를 다 써 월드 중앙을 가릴 수 있다.

## 제안 변경

1. 계정 생성 가로 화면을 `입력 | 미리보기 | 꾸미기(HAIR | COLOR)`로 재배치한다.
2. 로그아웃은 현재 월드 연결을 폐기한 뒤 같은 `Main`의 로그인 화면으로 돌아간다.
3. 임시 메시지는 중앙 월드를 가리지 않는 왼쪽 하단 토스트 폭으로 제한하고, 긴 문구는 줄바꿈한다.

## 수용 기준

- 780×360 계정 생성 화면에서 입력칸·미리보기·성별·HAIR·COLOR·버튼이 모두 화면 안에 있다.
- 360×780 계정 생성 화면의 기존 세로 배치는 유지된다.
- 로그아웃 후 소켓이 닫히고 로그인 화면이 한 번만 나타난다.
- 가로 메시지는 화면 중앙을 횡단하지 않고 기존 4초 유지 + 1.5초 페이드를 유지한다.
- `dotnet build`, 레이아웃 검사, 세로·가로 스크린샷으로 검증한다.

## 작업 순서

1. [테스트 우선] 가로 계정 생성 레이아웃 검사가 현재 잘림을 잡는지 확인한다.
2. 가로 계정 생성 배치만 고치고 빌드·레이아웃·스크린샷을 검증한다.
3. 사용자가 스크린샷을 확인한 뒤 로그아웃을 구현·검증한다.
4. 다음 스크린샷 확인 후 메시지 배치를 고친다.
5. 전체 diff를 독립 리뷰한다.

## 롤백

`CreateScreen.cs`, `Main.cs`, `GameScreen.cs`, `MessageLog.cs`, `LayoutCheck.cs`의 이 작업 diff만 되돌린다.
기술·마법·아이템 산출물과 서버 submodule은 건드리지 않는다.
