# PRD — 생태계 봇
버전: v1.2

## 배경
사람 플레이어가 적어 세상이 비어 있다. 서버 쪽 AI 캐릭터가 사람과 같은 규칙으로 1→99 성장(사냥·판매·물약·장비)하면 세상이 살아 보이고, 경제(금화·물건 흐름)와 밸런스를 사람 대신 대량으로 시험하며, 그 기록이 머신러닝 재료가 된다. 조사·실측은 `01-recon.md` — 봇은 **외부 헤드리스 클라이언트, 프로그램 하나에 봇 여럿**, 오라클 무료 티어에서 약 80~100개.

## 제품 목표
1. 봇이 사람 손 없이 생성→사냥→귀환·판매→물약·장비 구매→착용→다시 사냥을 99레벨까지 되풀이한다.
2. 봇이 서버와 사람 플레이를 해치지 않는다(서버 지연·사냥터 독점 없음, 봇임이 드러남).
3. 서버에 쌓이는 기록(봇·사람)이 머신러닝에 바로 쓸 수 있는 꼴로 남는다.

## 유저 스토리
- **P1** 운영자로서 봇 N개를 켜 두면, 봇이 각자 직업·레벨에 맞는 사냥터에서 사냥하고 물약이 떨어지면 마을에서 사서 돌아오기를 원한다 — 세상이 늘 살아 있게.
- **P1** 운영자로서 봇이 서클(레벨 구간)에 맞는 장비를 상점에서 사서 입기를 원한다 — 성장이 원작 플레이와 같은 길을 밟게.
- **P1** 플레이어로서 봇이 내가 사냥하는 맵을 차지하지 않고, [접속자]에서 봇인 줄 알기를 원한다.
- **P2** 운영자로서 대시보드에서 봇 경제(금화 들어옴·나감, 물약 소비, 레벨 분포)를 보기를 원한다.
- **P2** 데이터 작업자로서 봇·사람 기록을 가명·구조화된 JSONL 로 날짜별로 받기를 원한다.

## 엣지케이스
- Given 봇이 상점에 왔는데 금화가 물약 한 개 값도 없을 때 When 쇼핑 Then 가진 물건을 먼저 팔고, 그래도 없으면 물약 없이 한 층 낮은 사냥터로 간다.
- Given 봇 가방이 가득 When 사냥 중 Then 줍기를 멈추고 마을로 간다(FR-004).
- Given 사람이 봇이 있는 맵에 들어옴 When 다음 판단 Then 봇은 `YieldSeconds` 안에 다른 맵으로 옮긴다.
- Given 서버 재시작 When 접속 끊김 Then 5초~1분 간격 재접속, 캐릭터 JSON 에서 상태를 다시 계산한다(따로 저장한 상태 없음).
- Given 같은 봇 계정이 이미 접속 중(이전 프로그램이 남음) When 로그인 Then 서버 기존 규칙(새 접속이 옛 접속을 밀어냄)을 따른다 — 봇 프로그램은 systemd 서비스 하나라 겹치지 않는다.
- Given 상점에 내 직업·서클 장비가 없음 When 장비 쇼핑 Then 그 부위는 그대로 두고 드랍으로 얻은 것 중 입을 수 있는 것을 입는다.
- Given 사냥터가 전부 사람·봇 상한으로 찼음 When 사냥터 고르기 Then 한 층 낮은 사냥터, 그것도 없으면 마을에서 `WaitSeconds` 쉼.
- Given 봇이 죽음을 `DeathLoop` 번 연속 When 같은 사냥터 Then 한 층 낮춘다.

## 성공 기준
- SC-001: 격리 서버에서 새 봇 3개(전사·무도가·도적)가 사람 손 없이 30분 동안 ① 사냥터 도착 ② 한 번 이상 마을 귀환·판매·물약 구매 ③ 다시 사냥터 — 3개 모두 pass.
- SC-002: 격리 서버에서 레벨을 11로 바꾼 봇이 마을에서 서클 2 이상 장비를 최소 1부위 사서 입는다(직업별 1개씩, 3 pass).
- SC-003: 봇 `MaxEcoBots`/2 개가 `BotsPerMap` 이하로 흩어진 상태에서 서버 CPU 가 `ServerCoreBudget` 이하(이 PC 실측 환산) — `BotLoadTests` 로 판정.
- SC-004: FR-010 뒤 같은 맵 25봇 서버 CPU 가 고치기 전(0.90코어)보다 낮다.
- SC-005: 봇 사건 기록 한 줄도 빠짐없이 JSON 파싱되고, 학습용 사본에 IP·원래 이름이 0건(스크립트 검사).
