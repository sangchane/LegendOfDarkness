# Seed — 생태계 봇(eco-bots)
버전: v1.0

- 원문: 「지금까지 구현한걸 토대로 서버에서 AI 캐릭터들을 생성해서 99레벨까지 성장시키므로써 사냥이나 상점 이용해서 서클에 맞게 아이템 착용을 하고 포션을 구매해서 소비를 하고 생태계를 이루어 볼 수 있도록 만들자 내가 언급하지 않은 컨텐츠나 블라인드 스팟을 찾아서 진행 이게 현재 서버 리소스로 몇개까지 가능한지 봇 프로그램으로 하나씩 할당을 해야하는지부터 조사하고 현업에서 어떻게 구성하는지도 레퍼런스도 조사」(2026-10-06)
- 서비스 유형: 기존 게임(모바일 MMORPG, Hades 서버)의 기능 하나 — 헤드리스 봇 프로그램 + 서버 소폭 확장.
- 주 도메인 / 인접 도메인: MMO 플레이어 봇(playerbots) / 게임 경제(파우셋·싱크), 서버 수용량.
- 감지된 제약: 서버·봇은 같은 클라우드 기계(161.33.43.117, 사양은 이 PC에서 아직 못 봄 — SSH 열쇠 등록 대기) · 서버 게임 루프 단일 스레드(8ms) · 원본 소스는 fork 에서만 고친다 · 1인 운영.
- 로드할 블라인드스팟 프로파일: P7 게임(해당 항목만) + 수용량.
- 강도: lite — 사유: 1인 운영·사용자 소수, 기존 봇 기반(동료 봇·대신 사냥)의 bounded 확장. 단 "몇 개까지"는 추정 대신 실측(01 §실측).
- 해석한 것(사용자가 말하지 않았는데 내가 정한 것, 틀리면 비싼 순):
  1. **봇은 진짜 접속(헤드리스 클라이언트)으로 돈다** — 서버 안에 가짜 세션을 새로 만들지 않는다. 근거: 실측상 서버 비용의 대부분이 소켓이 아니라 시야 갱신이라 서버 내장이어도 줄지 않고, 동료 봇·대신 사냥이 이미 이 길로 운영 중(04 대안 비교).
  2. **봇마다 프로그램 하나가 아니라, 프로그램 하나가 봇 여럿**을 돌린다(대신 사냥 `ProxyHost` 와 같은 꼴). systemd 서비스 1개.
  3. 봇은 **사람임을 숨기지 않는다** — 이름 규칙(`봇` 표시)·[접속자] 목록·활동 통계에서 봇으로 구분된다.
  4. 봇은 **사람 플레이어의 사냥을 방해하지 않는 쪽**이 기본 — 사람이 있는 맵은 피하고, 한 맵에 봇 수 상한.
  5. 성장은 **실제 사냥으로**(통계식 가짜 성장 아님). 99까지 걸리는 시간이 길면 봇 수를 늘리는 게 아니라 시간으로 푼다. 오프라인 통계 성장은 2단계 후보(03 범위 밖).
  6. "서클" = 레벨 구간(1·11·41·71·99 — 이 서버의 기술·드랍 층 경계).
- 기존 시스템: 이 저장소 — 동료 봇 `mobile/bots/Lod.CompanionBot`, 대신 사냥 `mobile/bots/Lod.HuntProxy`(한 프로그램 여러 접속), 알맹이 자동화 `mobile/src/Lod.Mobile.Core/Automation/`(AutoHunt·AutoPotion·AutoLootGate·StatPlan), 상점 프로토콜 `WorldClient.BulkTradeAsync`(0xF2), 서버 `sources/wren11/Dark-Ages-Private-Server`(fork).
