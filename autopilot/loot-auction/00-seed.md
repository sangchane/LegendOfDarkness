# Seed — 그룹 전리품 룰렛 · 경매장
버전: v1.0

- 원문: 「그럼 그룹 사냥중에 나오는 아이템은 룰렛 돌리는 시스템 만들어 그거 중에 필요없는건 판매하거나 경매장에 올리게 하고 경매장은 설정 옆에 메뉴로 만들어」
  + 「경매장은 와우랑 유사한 방식으로하고 브랜치 따로해서 되돌릴 수도 있게해」 (사용자 2026-10-07)
- 서비스 유형: 모바일 MMORPG 기존 시스템 확장(서버 Hades C# + 앱 Godot C# + 생태계 봇 프로그램)
- 주 도메인 / 인접 도메인: 게임 경제(전리품 분배·경매) / 봇 자동화(생태계 봇이 굴리고·팔고·올림)
- 감지된 제약:
  - 경매장 = 와우 방식(보증금 · 입찰가/즉시 구매가 · 기간 선택 · 낙찰 수수료) — 사용자 지정
  - 앱 메뉴: 「설정」 옆에 「경매장」
  - 되돌릴 수 있게: 루트·서버 모두 브랜치 `feature/loot-roll-auction` 에서 작업, main/배포 브랜치와 분리
  - 사람과 봇이 같은 경매장을 쓴다(결정 17)
  - 개발은 맥(격리 서버 시험), 플레이는 클라우드(AGENTS.md)
- 로드할 블라인드스팟 프로파일: 공통 11축 + 게임 경제(복제·스캠·인플레) + 모바일 UI
- 강도: lite — 사유: 게임 안 금화(실제 돈 아님) · 1인 운영 · 기존 시스템의 bounded 확장. 단 아이템 복제·금화 유실은 데이터 손실급이라 A2 질문 1칸 허용, STRIDE 는 경매·룰렛 경계만 전수.
- 해석한 것 (틀리면 비싼 순):
  1. 룰렛 대상 = 그룹(서버 그룹 0x2E)으로 묶인 사람·봇 모두. 혼자 사냥 전리품은 지금처럼(줍는 사람 몫).
  2. 룰렛은 와우 「필요/차비/포기」를 단순화 — 각 파티원이 굴려 가장 높은 수가 가져감. 금화는 굴리지 않고 같은 맵 파티원에게 똑같이 나눔.
  3. 「필요없는 것」 판단은 봇만 자동(지금의 판매 규칙 + 경매 올릴 가치 기준). 사람은 직접 고른다.
  4. 와우의 우편 대신 경매장 창 안 「받을 것」 칸(낙찰품·판매 대금·유찰품·밀린 입찰금)으로 받는다 — 서버에 우편이 없다.
  5. 경매장은 서버 하나에 하나(진영 구분 없음), 어디서나 앱 메뉴로 연다(NPC 경매인 없이).
- 기존 시스템: 서버 `sources/wren11/Dark-Ages-Private-Server`, 앱 `mobile/client`, 알맹이 `mobile/src/Lod.Mobile.Core`, 봇 `mobile/bots/Lod.EcoBots`. 설계 이어받기 `autopilot/eco-bots/`(결정 17·19·20).
