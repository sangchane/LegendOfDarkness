# 테스트 시드 — 도메인 분산 5개

각 시드는 한두 문장 입력 + R2 채점용 필수 표준 체크리스트로 구성된다.

## S1. BEMS
입력: "AI 기반 BEMS 솔루션 초기 기획을 잡고 싶어."
필수 표준 체크: BACnet 또는 Modbus, ISO 50001, 시계열 저장소 논의, Project Haystack/Brick 등 메타데이터 표준, 제어 안전 게이트.

## S2. 물류 SaaS
입력: "중소 화주용 물류 배차 관리 SaaS 만들고 싶어. 토스처럼 사용자 친화적이었으면 해."
필수 표준 체크: 위치 데이터 처리(개인정보), 배차 최적화 접근법, 참조 제품 분해 수행 여부, 모바일 우선 여부 판단.

## S3. 헬스케어 예약
입력: "동네 의원용 진료 예약·대기 관리 서비스 기획해줘."
필수 표준 체크: 의료법·개인정보보호법(민감정보), EMR 연동 논의, 노쇼 처리 정책.

## S4. 사내 지식관리
입력: "회사 문서가 흩어져 있어서 AI 검색되는 사내 위키 같은 걸 만들고 싶어."
필수 표준 체크: 권한 모델, 기존 저장소(Drive/Confluence 등) 연동, RAG 구조 논의, 데이터 보안.

## S5. 핀테크 가계부
입력: "오픈뱅킹 연동되는 자동 가계부 앱 기획하고 싶어."
필수 표준 체크: 오픈뱅킹/마이데이터 규제, 전자금융 관련 인허가 필요 여부, 금융 데이터 암호화.

## 사용 규칙

- v0.x 개선 검증에는 S1~S3만 써도 된다 (토큰 절약). 메이저 채택 판정에는 5개 전부.
- S2는 규칙 6(질적 표현 변환)의 작동 여부를 함께 확인하는 시드다.
