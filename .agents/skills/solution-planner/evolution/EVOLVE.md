# EVOLVE — 하네스 자기 진화 절차 (수동 실행)

사용자가 "evolve 실행", "업데이트 점검"을 요청할 때 이 절차를 따른다.
원칙: 하네스가 사용자 프로젝트에 적용하는 규칙(근거 발견 → A/B 검증 → 승자만 채택)을 하네스 자신에게 적용한다.

## 1. Watch — 변화 감지

`watchlist.md`의 감시 대상과 탐지 쿼리로 웹 검색·GitHub 조사를 수행한다.
upgrade-log의 마지막 점검일 이후 달라진 것만 목록화한다. 각 항목에 출처 URL과 확인일 필수.

## 2. Extract — 기법 단위 추출

도구를 통째로 채택 후보로 삼지 않는다. 개별 기법으로 분해한다.
(예: "BMAD 채택"이 아니라 "constitution 파일 방식", "PASS/CONCERNS/FAIL 게이트" 각각)

각 후보 기법에 대해 변경안을 작성한다.
- 무엇: 기법 요약 + 출처
- 어디를: 우리 하네스의 어느 파일, 어느 규칙을 바꾸는지 (diff 수준으로 구체적으로)
- 왜: 루브릭 6개 항목 중 무엇이 개선될 것으로 예상하는지

이미 upgrade-log에 기각 기록이 있는 기법은 "기각 사유가 해소됐는지"부터 확인하고, 해소 근거가 없으면 재실험하지 않는다.

## 3. Trial — 챔피언/도전자 A/B

- 챔피언: 현재 버전. 도전자: 변경안 적용 사본 (별도 디렉토리에 복사 후 수정).
- `eval/run-ab.md` 절차로 실행하되, 베이스라인 자리에 챔피언, 하네스 자리에 도전자를 넣는다.
- 시드는 최소 S1~S3, 시드당 2회 반복.

## 4. Gate — 채택 판정

`eval/rubric.md`의 판정 규칙 그대로 적용한다.
- 승리 → 채택. 기각 → 변경안 폐기.
- **채택이든 기각이든 반드시 upgrade-log.md에 기록한다.** 기각 기록이 미래의 중복 실험을 막는다.
- 판정이 무승부 구간이면 결과를 사용자에게 보여주고 사람 판단으로 결정한다. 자동 채택 금지.

## 5. Adopt — 버전 반영

채택 시에만 수행한다.
- SKILL.md의 버전을 올린다 (기법 추가 = 마이너, 규칙 형식 변경 = 메이저).
- 변경 내용·근거·A/B 점수를 upgrade-log.md에 changelog로 기록.
- 직전 버전을 `evolution/archive/v<이전버전>/`에 보관한다 (롤백용).
