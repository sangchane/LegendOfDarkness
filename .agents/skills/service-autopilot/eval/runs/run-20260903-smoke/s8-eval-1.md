# 심사 결과 — 요양시설 낙상 감지·알림 서비스 설계 문서 비교

심사 대상: doc1(FALLCARE-DESIGN v0.1) vs doc2(FallGuard-Care 파이프라인 산출물)
판정 기준: 구현 착수에 필요한 정보의 밀도 (길이는 품질이 아님)

---

## [1. 완전성]

**doc1 근거 인용**

- 페르소나를 4종(어르신 / 요양보호사 김OO / 간호사·시설장 / 보호자 딸)으로 두고 "니즈"와 **"두려움"** 열까지 분리했다: "요양보호사 김OO — 야간 1인이 20명 담당, 시설 지급 스마트폰 소지, 장갑 자주 착용 … 두려움: 알림 폭탄, 놓쳤을 때 책임".
- 보안: §7.2 STRIDE 표 15행(Spoofing 장치/보호자, Tampering 이벤트/펌웨어, R, I 내부자, D 알림/센서, E, 물리)에 각각 대응책. §7.3 개인정보 설계 원칙 6항.
- API/데이터: §8 엔드포인트 18행 + 인가 매트릭스(역할 5 × 행위 6), §7 ERD + 엔티티 18종 "주요 컬럼" 표 + 인덱스 4개.
- 테스트: §9.3 감지 품질 검증 프로토콜이 낙상 6시나리오·오탐(ADL) 6시나리오의 **반복 횟수까지** 지정("서 있다가 전방/후방/측방 낙상 각 20 … 직원이 어르신 이승·기저귀 교체 30").
- 운영: §10.4 합성 카나리 — "게이트웨이마다 10분 간격으로 `kind=TEST` 이벤트를 발행 … **이것이 '알림 경로가 살아 있음'을 증명하는 유일한 지표다**". doc2에 없는 강점.
- doc2에 없는 영역도 있다: 사업 모델(§3 Q5 "설치비 + 침상당 월 구독"), 섀도 모드(F-13 "파일럿 첫 4주 튜닝용"), 벤더 2종 어댑터, M0~M3 마일스톤과 "이 가격에 도입하겠다" LOI 기준.
- 그러나 운영/장애 대응은 얕다. §10.5는 런북 **이름 나열**뿐이다: "시설 오프라인 대응 / 센서 오프라인 대량 발생 / 알림 채널 장애 폴백 확인 / 타이머 지연 / …". 알람↔런북 1:1 대응, 장애별 RTO/RPO, 백업 복원 리허설, 준비도 체크리스트가 없다.

**doc2 근거 인용**

- 엣지케이스를 Given/When/Then으로 흐름 A·B·C 12건 고정: "**Given** 현재 시각에 근무표상 담당 직원 0명, **When** DETECTED, **Then** 60초 대기 없이 즉시 간호사·시설장 전화 + 관리자 화면 '근무표 공백' 경고", "**Given** 같은 수급자에 1시간 내 2번째 CONFIRMED … **Then** 각각 발송(억제 없음 — 안전 통보는 병합하지 않는다)".
- 보안: DFD + trust boundary 5개(TB1 센서LAN / 게이트웨이 / TB2 인터넷 / TB3 단말 / TB4 제3자 / TB5 관리웹) × **STRIDE 6범주 전수 매트릭스**, 대책을 Eliminate/Mitigate/Transfer/Accept로 분류, 그리고 "④ 충분한가 — 상위 리스크 3 재검토 + 잔여"에서 "게이트웨이 교체(MTTR ≤ 4h) 동안 발생한 낙상은 시스템이 모른다 … **Accept(파일럿 한정, 사유 기록)**".
- 운영: 알람 9개 각각 런북 1:1 매핑, 장애 시나리오 7종에 RTO/RPO("게이트웨이 하드웨어 사망 … RTO 4h / RPO 0"), 백업 4종에 복원 리허설 주기("**분기 1회** 스테이징에 복원 → E-61 체인 검증 통과 확인"), R-1 런북 전문(메타·트리거·진단·해결·에스컬레이션·검증·롤백), 준비도 체크리스트 12항.
- 커버리지 감사: "P0·P1 21건(FR-001~016·020·021) 중 미매핑 **0건**", "SC-001~010 → 10/10, P0/P1 FR → 18/18, INV-01~07 → 7/7 … **누락 0**".
- 섀도 모드·합성 카나리·가격 모델은 없다.

**판정: doc2** — 차원이 지목한 6개 영역(사용자·엣지케이스·보안위협·API/데이터·테스트·운영/장애) 전부에서 doc2가 더 깊고, 특히 엣지케이스·런북·커버리지 감사에서 doc1은 목록 수준에 머문다.

## [2. 비모호성]

**doc1 근거 인용**

- 문서 전체에 **[확정] / [가정] / [미확정]** 삼분 표기를 강제하고 그 정의를 §0에 둔 것은 모호성 방지 장치로 강력하다: "레이더는 영상정보처리기기가 아니라고 보는 것이 합리적이나 법적 판단 필요 | **[가정]** 민감정보로 취급, 법무 검토는 M0".
- 타이머·임계값도 구체적이다: "S2 | T0+45s 미응답 | 같은 층 전 직원", "동일 센서·60초 내 재감지는 같은 이벤트로 병합", "유예 창 제공(기본 15분, 0으로 설정 시 즉시)".
- 그러나 문서 내부 참조가 깨져 있다. §0이 "산출물 위치: §3 PRD → §4 알림·에스컬레이션 정책 → §5 아키텍처·ADR → §6 위협모델 → §7 데이터 모델 → §8 API 계약"이라 안내하지만, 본문은 §3 블라인드스팟 / §4 PRD / §5 알림정책 / §6 아키텍처 / §7 위협모델 / **§7 데이터 모델(번호 중복)** / §8 API다. 부록 A 가정 목록의 ID 열도 A1~A7 자리가 전부 "단계"로 깨져 있어 "부록 A에 전체 목록"이라는 §0의 약속을 참조 불가능하게 만든다.
- 검증 불가 표현도 남는다: "LoRaWAN 우선 … **필요 시** Wi-Fi/PoE", "시설 내 Wi-Fi 푸시(**가능 시**) 유지", "주간 정책은 S2를 60s로 **완화 가능**".

**doc2 근거 인용**

- 요구사항이 EARS 형식으로 주어·조건·값이 모두 박혀 있다: "FR-004 | DETECTED 후 **60초** 미확인이면 근무 중 전 직원에게 재알림(30초 간격 최대 3회)하고, **180초** 미확인이면 `escalation_policy.phone_targets` 순서대로 TTS 전화를 걸어야 한다 … 각 대상은 `staff.phone_enc` 필수(없으면 설정 저장 시 **422**)".
- 설정 가능한 값도 범위를 못 박아 모호성을 제거한다: "`zone_timeout_s:60 [30~120], all_timeout_s:120 [60~300] … amend_window_s:300 [60~600]` — 범위 밖·비활성화(0) 불가".
- 상충을 명시적으로 해소한다: "**권위 시각 = 게이트웨이 수신 시각(RTC)**, 단말 탭 시각은 보조 필드", "SC는 파일럿 합격선(소표본 전수), 07의 SLO 99.0%는 운영 월간 목표 — **둘은 다른 지표다**".
- 수치 드리프트를 막는 단일 출처를 만들었다: "NFR-005 보존(**단일 상수 표** — 04/05/07은 이 값을 참조) … 토픽 `fg/` 통일, raw는 게이트웨이만, 감사 3년, RPO 15분/RTO 1h, stale 두 종류 정의".
- 다만 "미결정 **0건**"이라는 선언은 44건을 Assumed로 전환한 결과이며, 본인 리뷰가 이를 "거짓"으로 지적해 패치했음을 스스로 기록해 두었다("최종 검토 #1이 '미결정 0'의 거짓을 지적 → 해소"). 또 "(참고자료)"·"단계" 치환 흔적이 다수 남아 어떤 참조를 썼는지 읽히지 않는다.

**판정: doc2** — doc1의 삼분 표기와 doc2의 [사실]/[추론]/[추천]은 대등하지만, doc2는 여기에 값 범위·에러코드·권위 시각·단일 상수 표까지 얹었고 doc1은 자기 목차와 부록 참조가 깨져 있다.

## [3. 검증가능성]

**doc1 근거 인용**

- §1 성공 지표가 전부 수치다: "낙상 발생 → 직원 단말 알림 도착 **P95 ≤ 30초**", "오탐 **≤ 1건 / 침상 / 주**", "직원이 '알림을 끄고 싶다'고 답한 비율 < 20%".
- §9.3 채택 기준이 pass/fail이다: "**채택 기준**: 민감도 ≥ 95%, 느린 낙상 ≥ 85%, ADL 오탐 ≤ 3%", "라이브 전환 기준: 오탐 ≤ 1건/침상/주, 섀도 기간 시설 보고 낙상 중 미감지 0".
- §9.4 장애 주입 표에 "합격" 열이 붙어 있다: "인터넷 단절 … **10초 내 패널·사이렌, 시설 Wi-Fi 단말에 로컬 푸시, 복구 후 5분 내 이벤트 동기화, 유실 0**".
- 그러나 핵심 SLI의 측정 정의가 흔들린다. "알림 전달 지연(detected_at_sensor → 첫 단말 **ack_received**)"으로 P95 ≤ 30초를 재는데, ack_received는 사람이 반응한 시각이라 "단말 표시 지연"과 "사람 응답 시간"이 한 지표에 섞인다. §9.2 단위 시나리오는 불릿 8개로 SC/FR과 1:1로 묶여 있지 않고, 요구사항↔테스트 누락 검사가 없다.

**doc2 근거 인용**

- SC-001~010이 전부 pass/fail + 측정 방법을 갖는다: "SC-003 | 연기 낙상 50회 중 미탐 ≤ 2회 (침실 20·화장실 15·복도 15)", "SC-008 | 무작위 10건 해시체인 검증 통과 100% … 감사 검증 스크립트".
- 측정 원천을 계약으로 못 박았다: "FR-021 | 직원 단말은 알림을 화면에 표시한 시각(`displayed_at`)을 … 보고해야 하며, **이 값이 SC-001·NFR-002의 측정 원천이다**" + L-90 WS `displayed` + E-17 엔드포인트. doc1이 흐린 지점을 정확히 계약화했다.
- 수용 기준을 시나리오로 변환한 표가 40여 행이며, 각 행에 레이어와 목킹까지 붙는다: "INV-01 부정 | **Given** FALSE_POSITIVE로 종결(낙상 통보 발송 이력 없음) **Then** 낙상·정정 통보 0건 / **Given** CONFIRMED 통보 발송 전(큐 대기) 정정 **Then** 낙상·정정 둘 다 0건 | unit | 상태별 파라미터화".
- 검증 절차 자체에 게이트를 건다: "각 시나리오는 처음 실행 시 **반드시 실패**해야 한다(RED 게이트). 실패 이유가 '미구현'이 아니라 설정 오류면 RED로 인정하지 않는다", "판정: 미탐 ≤ 2/50, 실험실 오탐 ≤ 10/200. 실패 시 임계 조정 후 **전체 재실행(부분 재실행 금지)**".
- 커버리지 목표도 리스크 기반으로 판정 가능하다: "EventEngine(상태기계·병합·타이머·라우팅) | 분기 **100%**", "관리 웹 UI | 주요 화면 4상태 + 리포트, 라인 60%".

**판정: doc2** — 양쪽 다 수치 합격선을 갖지만, doc2는 모든 SC/FR/INV를 시나리오·레이어·측정 원천에 1:1로 연결하고 누락 0을 감사한 반면 doc1은 지표와 테스트가 따로 논다.

## [4. 실행가능성]

**doc1 근거 인용**

- 스택이 선택·근거·대안 3열로 정리돼 바로 착수 가능한 수준이다: "게이트웨이 | 산업용 ARM/x86 미니PC, Ubuntu 22.04 LTS, Docker, ChirpStack(LoRaWAN NS), Mosquitto, 엣지 에이전트(Go), SQLite | 팬리스·장기 지원, Go는 단일 바이너리·저자원 | Raspberry Pi(내구성 우려)".
- 핵심 페이로드는 실제 JSON으로 제시했다: FallEvent 표현(id·version·status·location.bed_guess·escalation.next_fire_at), resolve 요청 본문, SensorEvent v1 스키마, MQTT 토픽 `fc/{facility_id}/gw/{gateway_id}/events`, `dedupe_key = sha256(sensor_id + detected_at_sensor 초 단위)`.
- 그러나 ERD는 mermaid 관계도 + "주요 컬럼" 산문 표까지이고 타입·제약·RLS 정책문·파티셔닝이 없다. Terraform은 모듈 이름 한 문단 나열이고("`network`(VPC, 프라이빗 서브넷), `iot-core`(…), `ingest`(…)"), 18개 엔드포인트 중 요청/응답 본문이 있는 것은 2개뿐이며 에러 코드 체계는 예시 하나(`EVENT_ALREADY_RESOLVED`)에 그친다. 구현 순서 지시도 없다.

**doc2 근거 인용**

- ERD가 컬럼 타입·제약까지 내려간다: "fall_events { uuid id PK \"uuidv7\"; … uuid resident_id FK \"**CONFIRMED면 NOT NULL (CHECK)**\"; int escalation_level; int amend_count }", "guardians { … text phone_enc \"**pgcrypto**\"; bool notify_consent … }".
- DB 규칙이 실행 가능한 문장으로 나온다: "정책 `USING (facility_id = (SELECT current_setting('app.facility_id')::uuid))`", "`event_transitions`·`audit_log`·`notifications`: INSERT만 허용(`REVOKE UPDATE, DELETE`), 트리거로 `hash = sha256(prev_hash || canonical_json)` 검증", "부분 인덱스 `WHERE status IN ('DETECTED','ACKNOWLEDGED')`(미결 큐), `event_transitions USING brin (at)`".
- 엔드포인트 표 30여 행이 요청 핵심 필드·응답·**RFC 9457 에러 type**·권한 스코프 4열을 모두 갖고, OpenAPI 3.1 스케치와 게이트웨이 로컬 API(L-11~L-90) 부분집합까지 있다.
- 컴포넌트를 메서드 시그니처 수준의 classDiagram으로 그렸다: "EventEngine { +mergeWindow 30s; +ack(eventId, staffId, deviceAt) at=RTC now; +amend(eventId, outcome) 5min window, both directions; +tick() escalation timers → phone_targets order }".
- 배포가 실제 파일 형태다: compose 스케치(`read_only: true`, `cap_drop: [ALL]`, healthcheck, `image: …:${GIT_SHA} # :latest 금지`), 게이트웨이 형상("rootfs read-only, `/data`(LUKS…), log2ram, HW watchdog(`RuntimeWatchdogSec=15`), chrony + RTC(DS3231)"), CI/CD 4트랙(PR/main/gateway/app).
- 착수 순서까지 지시한다: "구현 순서: EventEngine 상태기계(unit 100%) → LocalStore/AuditLog 해시체인 → LAN WS + 기기 자격증명 → SyncAgent/outbox → 클라우드 ingest/mirror → NotificationService(INV-01 final-state) → 직원 앱 → 관리 웹 → OTA/HIL".

**판정: doc2** — 다음 담당자가 doc1을 들면 스키마·에러체계·인프라를 스스로 설계해야 하지만, doc2는 테이블 제약·RLS 정책문·에러 type·compose·CI 단계·구현 순서까지 이미 결정돼 있다.

## [5. 근거성]

**doc1 근거 인용**

- 사실과 결정의 인식론적 지위를 문서 전체에 표기한다: "장기요양기관 CCTV 의무화 … 위반 시 과태료 최대 300만 원 | **[확정]**" 대 "의료기기 해당 여부 … **비의료기기로 가정** … **[가정]** 식약처 판단은 [미확정]".

## [6. 범위 절제]

**doc1 근거 인용**

- 범위 밖을 명시하고 의료기기 경계를 피한다: "§4.7 범위 밖 … 낙상 **예방**(위험도 예측, 보행 분석), 생체신호(호흡·심박) 표시 — 의료기기 이슈", "직원 성과 평가 지표(응답 시간의 개인별 랭킹) — 시설 노무 갈등 유발".
- 문서 경제성은 doc1이 앞선다(약 855행 대 doc2 약 1,440행). 메타 문서(자기 검토 절차 서술, 참고자료 사용 기록) 없이 산출물만 담았다.

## 종합 판정: doc2

doc1은 삼분 표기·페르소나·섀도 모드·합성 카나리처럼 제품 판단이 살아 있는 좋은 기획서지만, 자기 목차와 부록 참조가 깨져 있고 스키마·에러체계·런북·요구사항↔테스트 매핑이 목록 수준에서 멈춘다. doc2는 EARS 요구사항·불변식 7개·SC 10개를 시나리오와 1:1로 묶고 커버리지 누락 0을 감사했으며, ERD 제약·RLS 정책문·에러 type·compose·CI 단계·구현 순서까지 결정해 두어 다음 담당자가 추가 설계 없이 착수할 수 있다. 여섯 차원 중 다섯에서 doc2가 앞서고 범위 절제만 무승부이므로 doc2를 선택한다.
