위협모델·테스트 매트릭스·운영 런북을 갖춘 문서를 낸다. 그런 베이스라인을 상대로도 스킬은 **완전성·검증가능성·근거성**에서 두 시드 모두
이겼다 — 이 셋은 v1.1.0 라우팅이 겨냥한 축(research-ops 출처 강제, security-review 위협 전수, tdd/e2e 요구사항→테스트 ID 대조)이다.
스킬이 진 곳은 S1 **실행가능성**(스킬 문서는 GATE CONCERNS와 착수 전 확인 조건을 남겼고 화면 목업이 없었다; 베이스라인은 "월요일에 바로 시작"
가능한 자기완결 문서였다)이다. 범위 절제는 양쪽 다 방향이 달라 tie.

## 이탈 기록 (프로토콜·스킬 규칙과 다르게 한 것)

1. **세션 한도(HTTP 429) 3회**로 B 3건이 중단·재개됐다(컨텍스트 유지 재개). 재개 시 GATE를 "검토 서브에이전트 최대 2명 × 1회 → 타당한 지적 패치 1회 → 08 기록"으로
   제한했고 **단계 전체 재실행 루프는 돌리지 않았다**(스킬 규칙 8의 "FAIL이면 해당 단계 재실행"과 다름). 그래서 GATE 판정이 PASS가 아니라 CONCERNS로 남았다.
2. S4의 GATE 리뷰어 B 결과는 부모 에이전트가 죽은 뒤 메인 세션에 도착해 `s4-rpi-ip-camera/gate-review-b.md`로 전달했고, 리뷰어 C는 소실됐다.
   S8은 리뷰어 B·C 모두 소실 → 재개 시 fresh-context 1명으로 대체.
3. `s4-b.md` 병합은 에이전트가 병합 전에 종료돼 메인 세션이 수행했다(내용 변경 없음).
4. **블라인드 강도**: S1은 초기 규칙(파일명 헤더만 제거)으로 판정돼 본문 안 파일명 인용·"스킬"·"GATE" 표기 17건이 남은 채 판정됐다. S4부터 강화 규칙(잔존 0).
   다만 "9개 절 패키지 vs 단일 문서"라는 구조 차이는 어떤 규칙으로도 숨길 수 없다(7월도 동일).
5. 인간 앵커(PROTOCOL 3단계)는 미실시 — 사용자 미개입 자동 런.
6. judge 출력 형식이 파일마다 달라(`## 1. 완전성`, `## [1. 완전성]`) `aggregate.py`가 세 형식을 모두 파싱하도록 보강했다. S4부터는 프롬프트에 형식을 고정.
