## S1 lite 읽기

- **비용**: 321k → 200k (−38%), 문서 88K자 → 48K자 (−45%), 서브에이전트 0, 검색 5회, 스킬 호출 11회, 도구 호출 48회, 17분.
  SKILL.md에 적었던 "8만 토큰"은 미달성 — 바닥은 문서 분량이 아니라 스킬 본문 읽기와 도구 호출 횟수였다. 상한을 실측 기반(25만)으로 고쳤다.
- **품질**: 베이스라인과 대등. lite가 내준 것은 완전성(STRIDE 전수 생략, 접근성·이관 축약)과 실행가능성(DDL을 스케치로, 테스트 P0만).
  얻은 것은 비모호성(상수 단일 출처, "미결정 0"을 스크립트가 검증), 근거성(사실/추론 구분 + 출처), 범위 절제("그룹웨어 자원 캘린더가 있으면 이 패키지를 폐기하라").
  두 judge가 순서와 무관하게 doc1을 골랐으므로 종합은 tie 처리 — 근소한 차이에서 위치 편향이 판정을 갈랐다.
- **결론**: 쉬운 사내 도구에서 lite는 "Fable 5.1 단독보다 낫다"가 아니라 "비용 60%로 같은 수준 + 근거·검증·범위 판단이 붙는다"다.
  실행가능성을 잃지 않으려면 lite도 A5 ERD를 컬럼 수준(DDL 스케치)으로 유지하는 편이 싸다 — 다음 후보.
- **기계 검증**: `check_package.py` CRITICAL 0 · HIGH 0 (FR 10/10, SC 5/5, register 22/22). GATE 자기 점검이 04의 "Drizzle 또는 Kysely" 위장 미결정을 잡아 확정.
- **블라인드 누수 1줄**: 03 버전 줄에 템플릿 지시문("개정하면 올리고… 규칙 9")이 복사돼 들어감. 템플릿에서 지시문을 코드 블록 밖으로 뺐고 blind_prep 규칙 추가.
