# 설계 문서 심사 판정 — s8 (요양시설 낙상 감지·알림 서비스)

심사관: 두 문서의 작성 과정을 모르는 상태에서, 오직 "구현 착수에 더 적합한 기획·설계 문서"인지만 본다.
판정 기준: 길이가 아니라 **구현 착수에 필요한 정보의 밀도**.

- doc1 = FALLCARE-DESIGN v0.1 (단일 문서, §0~§11 + 부록 A/B/C)
- doc2 = FallGuard 00~08 + decision-log (seed·recon·blindspot·PRD·아키텍처·API/스키마·테스트·배포운영·준비도)

---

## 1. 완전성

**doc1 근거**
- 페르소나가 "두려움"까지 포함해 4종으로 구체적이다: "**요양보호사 김OO** — 야간 1인이 20명 담당, 시설 지급 스마트폰 소지, 장갑 자주 착용 … 두려움: 알림 폭탄, 놓쳤을 때 책임".
- 다른 문서에 없는 **감지 품질 검증 프로토콜**을 갖췄다: "§9.3 … 서 있다가 전방/후방/측방 낙상 | 각 20 … 침대에 눕기·뒤척임·이불 정리 | 30 … **채택 기준**: 민감도 ≥ 95%, 느린 낙상 ≥ 85%, ADL 오탐 ≤ 3%".
- 사용성 검증도 별도 절로 있다: "§9.6 … 요양보호사 5명, 야간 근무 시뮬레이션(조도 낮음, 장갑 착용, 소음) … 합격: 2탭 내 출동, 종결 60초 내, SUS ≥ 70".
- 반면 운영 절차는 목록에 그친다: "§10.5 런북(요약 목록) 시설 오프라인 대응 / 센서 오프라인 대량 발생 / 알림 채널 장애 폴백 확인 / …" — 이름만 있고 절차·명령·판정 기준이 없다.
- STRIDE는 13행 표로 주요 위협을 다루되 경계별 전수는 아니다.

**doc2 근거**
- 커버리지 공백을 문서가 **스스로 검사**한다: "## 커버리지 매핑 — P0·P1 요구사항 → 담당 엔드포인트/이벤트 … 매핑 0건 P0/P1 요구사항: 없음", "**누락 검사**: SC-001~SC-012 전부 ≥1 시나리오 … P0·P1 FR-001~FR-020·022·023·026~029 전부 ≥1 시나리오".
- 위협모델이 전수다: "② 무엇이 잘못될 수 있는가 — STRIDE 전수 (경계 6 × 범주 6)" — TM-01~28에 더해 해당 없는 칸도 "해당없음 — 읽기 전용, 상태 변경 엔드포인트 없음"처럼 근거를 남긴다.
- 블라인드스팟 스캔이 49축 전수이고 마킹 합계가 맞는다: "마킹 집계: Clear 2 · Assumed 42 · Asked 5 (Q1~Q5 전부 Assumed(무응답)로 귀결) = 49". SD카드 마모·전원 차단·시계 드리프트·스토어 심사·기기 분실까지 포함한다.
- 장애 대응이 절차 수준이다: "| 워커 정지(pg-boss·MQTT 구독) | AL-02 데드맨, AL-03 스테일 | … | `docker compose restart worker` → 재기동 시 pg-boss가 DB의 예약 잡을 이어 실행 … | 5분 / 0 |" + 런북 골격 1편 전문(RB-02).
- 다만 doc1에 있는 **센서 감지 품질의 사전 실험실 검증**은 없다. 실측을 파일럿에 미룬다: "SC-005 시설 사고 기록에 적힌 낙상 대비 시스템 감지 recall ≥ `DETECTION_RECALL_MIN`".

**판정: doc2** — 여섯 영역(사용자·엣지케이스·보안위협·API/데이터·테스트·운영) 모두를 다루면서 커버리지 공백 자체를 기계적으로 검사·선언하는 쪽이고, doc1이 앞서는 것은 감지 품질 검증 프로토콜 한 영역이다.

## 2. 비모호성

**doc1 근거**
- 주장 등급 규약이 있다: "모든 주장은 **[확정] / [가정] / [미확정]** 으로 구분한다."
- 그러나 미결정이 문서에 남아 있다: "§11.3 오픈 이슈 [미확정] 1. 채택 센서 모델·벤더 2종 (M0). 2. 가격·과금 단위 (M0 시장 검증). … 7. 화장실 레이더 설치 시 습기·설치 위치 기준(벤더 사양 확인)."
- 임계값이 여러 절에 흩어져 재기입된다: §1 "P95 ≤ 30초", §4.5 "P95 ≤ 30초 … P99 ≤ 60초", §5.2 "S2 | T0+45s", §10.4 "P95 ≤ 30초 (월)" — 단일 출처 표가 없어 값이 바뀌면 갱신 지점이 여러 곳이다.
- 구조적 혼선도 있다: "## 7. 위협 모델·개인정보 설계"와 "## 7. 데이터 모델 (ERD)"가 같은 번호를 쓰고, 7.1/7.2가 두 번 등장한다(§0의 안내 "§6 위협모델 … §7 데이터 모델"과도 어긋난다).

**doc2 근거**
- 값의 단일 출처를 강제한다: "## 상수 표 (단일 출처) — 04~07은 이 이름으로만 참조하고 값을 다시 쓰지 않는다." 이후 FR·SC·테스트·알람이 전부 `ACK_TIMEOUT`·`ALERT_LATENCY_P95` 같은 이름으로만 쓰인다.
- 요구사항 문장이 주어·조건·의무를 갖는 EARS다: "EARS 패턴('~할 때, 시스템은 ~해야 한다'). 상한·기간·임계는 **상수 표의 이름**으로만 쓴다."
- 미결정을 남기지 않고 가정으로 확정해 표기한다: "## 미결정 — 0건 — Q1~Q5는 추천안을 `Assumed(무응답)`로 채택했고, 미확인 사실(01)은 가정 A-1~A-6과 착수 조건(법률 검토)으로 흡수했다."
- 용어를 코드 식별자까지 고정한다: "| 낙상 확정 | confirmed_fall | 직원이 현장에서 낙상으로 판정 |", "| 관리자 알림 | admin_notice | … 채널 = `facility_admin` 사용자 전원 SMS + 콘솔 배너 |".
- 약점: 흐름 A의 엣지케이스 ID가 "EC-단계"로 렌더되어 개별 참조가 깨진다("EC-단계 Given 같은 디바이스가 활성 이벤트 중에 다시 감지함"). 다만 doc1도 부록 A의 첫 7행이 "| 단계 | 고객은 B2B 노인요양시설 30~100인 규모 |"로 같은 결함을 보인다.

**판정: doc2** — 임계값 단일 출처·EARS 문장·코드 수준 용어집으로 해석 여지를 구조적으로 없앤 반면 doc1은 오픈 이슈 7건과 값 재기입·절 번호 중복을 남겼다.

## 3. 검증가능성

**doc1 근거**
- 파일럿 종료 기준이 전부 수치다: "낙상 발생 → 직원 단말 알림 도착 **P95 ≤ 30초** … 파일럿 기간 **미감지 낙상 0건**(시설 낙상 보고서와 대조) … 오탐 **≤ 1건 / 침상 / 주**".
- 장애 주입 표에 합격 조건이 붙어 있다: "| 인터넷 단절 | 게이트웨이 WAN 차단 후 합성 낙상 | 10초 내 패널·사이렌, 시설 Wi-Fi 단말에 로컬 푸시, 복구 후 5분 내 이벤트 동기화, 유실 0 |".
- 인수 기준도 pass/fail이다: "§9.7 … 보호자 설문 만족 ≥ 4/5, 개인정보 민원 0".
- 다만 성공 지표와 테스트가 ID로 연결돼 있지 않아 "이 지표를 무엇이 증명하는가"를 사람이 매번 이어야 한다. "미감지 낙상 0건" 같은 0-목표는 측정 가능하나 SLO로는 판정 불가한 형태로 남아 있다.

**doc2 근거**
- SC마다 측정 방법 열이 따로 있다: "| SC-002 | `acked` 없는 이벤트가 `ACK_TIMEOUT`마다 다음 단계로 넘어가 `ESCALATION_LEVELS` 안에 시설 책임자까지 100% 도달 | 합성 이벤트 20건, 시각 주입 테스트 |".
- 실패 조건까지 실행 가능한 시나리오로 적혀 있다: "TS-052 … Given 서버가 M-01 수신 후 DB 커밋 전에 강제 종료(`SIGKILL`) / When 재기동 / Then 브로커 영속 세션이 재전달, fall_detections 1건(소실 0·중복 0) | I (Mosquitto persistence, manualAck)".
- 자동 테스트로 위장하지 않는다: "파일럿 실데이터로만 판정 가능한 SC(001·004·005·009·012)는 '운영 검증' 레이어로 분리하고 07 대시보드 쿼리·리허설에 연결", "미탐 0은 SLO로 부적절(SRE) → `DETECTION_RECALL_MIN` 90%".
- SC ↔ TS 양방향 매핑이 명시된다: "SC-001: TS-001·002 / 002: 003·004·005 / 003: 006·007 / …".

**판정: doc2** — 양쪽 다 수치 기준을 갖지만, 기준마다 측정 주체·레이어·시나리오 ID가 붙고 "자동으로 못 재는 것"을 따로 분리한 doc2가 판정 가능성에서 앞선다.

## 4. 실행가능성

**doc1 근거**
- 계약 수준까지는 왔다: API 엔드포인트 표(`POST /events/{id}/ack` 등), FallEvent JSON 예시, `SensorEvent 스키마 (v1)`, ERD와 엔티티 컬럼 표, "인덱스 핵심: `fall_event(facility_id, status, detected_at_sensor desc)`".
- 그러나 인프라·저장소는 이름 나열에서 멈춘다: "### 10.2 Terraform 모듈 [가정] `network`(VPC, 프라이빗 서브넷), `iot-core`(thing type, 정책, 인증서 프로비저닝 템플릿), `ingest`(IoT Rule → SQS DLQ 포함), `db`(RDS PostgreSQL Multi-AZ …)".
- 첫 착수 순서가 없다. 마일스톤은 "M1 MVP | 10주 | 엣지 에이전트·어댑터 2종, 클라우드 코어 … " 수준이라 담당자가 무엇부터 열지 알 수 없고, 레포 구조·환경변수·마이그레이션·최초 실패 테스트가 없다.

**doc2 근거**
- 제약이 곧 설계인 DDL이 실물로 있다: "CREATE UNIQUE INDEX fall_events_one_active_per_device ON fall_events (device_id) WHERE status IN ('detected','notified','acked');", "REVOKE UPDATE, DELETE, TRUNCATE ON audit_log FROM app_rw; … CREATE TRIGGER audit_log_no_change BEFORE UPDATE OR DELETE ON audit_log".
- 런타임 형상이 파일로 있다: `docker-compose.yml` 스케치(서비스 5종·볼륨·네트워크 분리·`no-new-privileges`·`read_only`), 멀티스테이지 `Dockerfile`, CI/CD 단계("PR: lint → typecheck → unit → integration(testcontainers …) → contract").
- 착수 자산이 갖춰져 있다: 디렉터리 2단계 트리, "### `.env.example` (키 이름과 설명만 — 값은 어떤 산출물에도 쓰지 않는다)" 21키.
- 첫 3개 작업이 실패 테스트 ID와 완료 조건까지 붙어 있다: "1. **벤더 페이로드 계약 + 수신 보장 스파이크** … RED 먼저: TS-023·025·026·052·053·058·062·063. **벤더 실제 샘플 페이로드 1건을 얻어 어댑터를 맞추는 것이 이 작업의 완료 조건**".

**판정: doc2** — doc1은 "무엇을 만들지"에서 멈추고, doc2는 스키마·컨테이너·CI·환경변수·첫 커밋 순서까지 내려와 있어 다음 담당자가 바로 착수할 수 있다.

## 5. 근거성

**doc1 근거**
- 등급 규약과 가정 목록이 있다: "부록 A. 가정 전체 목록 | # | 가정 | 확인 시점 | … | A9 | 에스컬레이션 기본 타이머 45/90/180/300초 | 파일럿 |".
- 기술 선택에 근거·대안 열이 붙는다: "| 에스컬레이션 타이머 | PostgreSQL 스케줄 테이블 + 워커 1초 폴링 | 안전 기능은 영속성·관측 가능성이 우선 … | BullMQ, Temporal(과함) |".
- 출처는 부록 C에 URL 19건으로 모여 있으나 개별 주장에 붙지 않는다.
- **사실 오류가 있다**: "장기요양기관 CCTV 의무화 | 노인복지법·시행규칙 개정으로 2023-06-22부터 … | [확정]" — [확정]으로 단정한 근거법이 틀렸다.

**doc2 근거**
- 조사 표가 행 단위로 태그·출처·확인일을 단다: "| (a) 개인정보보호법 제23조 | … | [sourced] | [law.go.kr 제23조](…) |", "모두 확인일: 2026-09-07".
- doc1이 틀린 지점을 근거와 함께 바로잡는다: "**정정**: 조사항목은 '노인복지법 개정'으로 표현했으나, 실제 근거법은 **노인장기요양보험법 제33조의2 및 그 시행규칙**. 2023.5.8 공포, 2023.6.22 시행".
- 못 찾은 것을 목록으로 남긴다: "## 미확인 항목 (조사로 못 찾은 것) — 낙상감지 소프트웨어/기기가 식약처 의료기기로 분류된 구체적 판정 사례 … 인지저하 어르신 … 대리 절차를 명시한 정부 가이드라인 …" (13항목).
- 상수마다 근거가 붙는다: "| EVIDENCE_RETENTION | 3 | 년 | 불법행위 손해배상 청구권 단기 시효(민법 제766조 — 안 날로부터 3년) 동안 증거 보존 |", "| DETECTION_RECALL_MIN | 90 | % | 파일럿 대사 기준. 미탐 0은 SLO로 부적절(SRE) |".
- 선택마다 버린 대안이 남는다: "| D3 | EMQX 브로커 | 대시보드·규칙 엔진 내장 | v5.9+ BSL 1.1 라이선스(01) — SaaS 재판매 검토 비용 |", decision-log 53건에 `superseded` 표기까지.
- 자기 한계도 명시한다: "## 판정: **CONCERNS** … **독립 재검토를 하지 않았으므로** 패치의 정합성은 메인 자기 점검으로만 확인됐다".

**판정: doc2** — 주장 단위 출처·확인일, 미확인 목록, 상수별 근거, 대안 폐기 이력을 갖췄고, doc1이 [확정]으로 잘못 적은 근거법을 출처와 함께 정정한다.

## 6. 범위 절제

**doc1 근거**
- 제외 선언은 분명하다: "### 4.7 범위 밖 (MVP에서 하지 않는 것) — 낙상 **예방** … 카메라·영상 저장, 얼굴 인식 … 직원 성과 평가 지표(응답 시간의 개인별 랭킹)".
- 그러나 MVP 런타임이 무겁다: "게이트웨이 | 산업용 ARM/x86 미니PC … ChirpStack(LoRaWAN NS), Mosquitto … | 엣지 플릿 관리 | Mender (OTA·인벤토리) | IoT 인입 | AWS IoT Core → SQS | … `services`(ECS Fargate: api, event-engine, notifier, ws-gateway) … RDS PostgreSQL Multi-AZ" — 파일럿이 "시설 1~2곳, 20~40침상"인데 인프라는 다시설 규모다.
- 투기적 유연성도 P0에 있다: "| F-01 | 레이더 이벤트 수집·정규화 (**벤더 2종**) | P0 |", "팀 규모·기간 미상" 상태에서 벤더 2종 어댑터를 MVP 필수로 못박았다.
- 대신 문서 자체는 군더더기가 적다. 결정 → 근거 → 산출물로 곧장 간다.

**doc2 근거**
- 축소 결정을 반복적으로, 근거와 함께 내린다: "| D2 | Redis + BullMQ … | 이벤트 볼륨이 작아(`MAX_EVENTS_PER_DAY`) pg-boss로 충분 |", "| D6 | TimescaleDB … | heartbeat를 행으로 저장하지 않으므로 시계열 볼륨 자체가 없음 |", "| M14 | 4GB VM에 Prometheus·Grafana·Loki·Vector 동거(컨테이너 9개) — 파일럿 과잉·R4 확대 | 외부 업타임 모니터 + J-09 `ops-alarm` + SQL 뷰로 축소 |".
- 안전 기능조차 범위를 자른 뒤 그 대가를 명시한다: "| D1 | 하이브리드 — 현장 게이트웨이가 인터넷 두절 시 로컬 경보 … | 2~3인 팀·파일럿 1시설 범위 밖. **P1 1순위 후보**. 잔여 리스크 R1로 명시 |".
- 반대로 문서 자체에는 구현과 무관한 장식이 붙는다: "## 절차 이탈 (평가 런 예산 — 명시)", "## 비용 기록 — 검색: 서브에이전트 26회 … 메인 세션(fable): 약 410,000 tok", 각 산출물 머리의 개정 이력("개정 v1.2 … 최종 검토 1차 적대적 검토(FAIL) 반영"), `<model_hints>` 블록. 총량도 "산출물: 00~08 + decision-log, 총 198KB"로 doc1의 두 배 이상이다.

**판정: tie** — doc2는 만들 시스템을 팀 규모에 맞춰 계속 깎아냈지만 문서에 과정 메타데이터를 남겼고, doc1은 문서는 간결하나 파일럿 1~2시설에 다시설급 인프라와 벤더 2종 어댑터를 P0로 얹어, 절제의 실패 지점이 서로 반대편이다.

## 종합 판정: doc2

doc2는 상수 단일 출처·EARS 요구사항·SC↔TS 전수 매핑·실제 DDL과 compose·`.env.example`·RED 테스트 ID가 붙은 첫 3개 작업까지 내려와, 다음 담당자가 이 문서만 들고 첫 커밋을 뗄 수 있는 유일한 쪽이다. doc1은 도메인 조사·페르소나·감지 품질 실험실 프로토콜(민감도 ≥95%, ADL 오탐 ≤3%)과 오프라인 로컬 경보라는 안전 설계에서 doc2보다 낫고 이 세 가지는 doc2가 실제로 비운 자리지만, 구현 착수 관점의 결정 밀도에서는 미결정 7건·값 재기입·근거법 오기가 상쇄한다. 범위 절제만 무승부이고 나머지 다섯 차원에서 doc2가 앞선다.
