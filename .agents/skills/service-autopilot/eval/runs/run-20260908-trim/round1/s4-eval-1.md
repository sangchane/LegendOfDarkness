# 심사 판정 — s4 (doc1 vs doc2) · 원순서 · judge = Opus (fresh-reviewer 타입) · 2026-09-09

시드: "라즈베리파이로 IP 카메라를 제어하고 실시간 모니터링하는 서비스를 만들고 싶다."

## 1. 완전성

**doc1 근거** — 여섯 영역이 모두 채워지고 매핑이 닫혀 있다. 05 커버리지 매핑이 FR-001~026 전부를 엔드포인트/작업으로 지목하고(`| FR-018 | P1 | E-18(프록시 SDP/MSE 오디오 필터) · E-31(audio_enabled:false) |`), 06 말미에 "누락 검사: SC-001~010 전부 … FR-001~020 전부 ≥1행, INV-1~6 각각 T-008·038·011·015·056·040"로 자기 검산을 한다. 07은 런북 RB-01을 진단·해결·에스컬레이션·검증·롤백까지 전문으로 쓰고, 백업 대상·복원 리허설·데드맨 알람까지 있다. 08 검증 재실행 결과가 `## CRITICAL (0) / ## HIGH (0)`이고 15건 지적이 전부 패치됐다.

**doc2 근거** — 영역 폭은 더 넓다(멀티사이트 fleet, 내부 CA·X.509 갱신 FR-030, MQTT 토픽 계약 표, WS 계약, 실제 `CREATE TABLE`·부분 인덱스 DDL, 안내판 PDF E10, 감사 점검 리마인더 FR-029). 그러나 자기 08이 영역 내부의 구멍을 열거한 채 넘긴다: "#12 이메일 발송 인프라 부재 — 07:85,88,89 P1 알람이 이메일을 쓰고 FR-019가 이메일 알림을 요구하지만 compose·`.env.example`에 SMTP 관련 항목이 없다", "#11 릴리스 등록 경로 부재 — E19는 GET", "#17 FR-018 매핑 실체 없음 — 07에 ALERT_DAILY_MAX 언급 0건", "#18 이벤트 capability 없는 카메라 미처리 … US-3(P1)이 성립하지 않는다".

판정: doc1 — 두 문서 모두 여섯 영역을 다루지만, doc2는 P1 알림 채널의 인프라·릴리스 등록 경로·FR-018 구현 지점이 비어 있다고 스스로 적어 넘긴 반면 doc1은 지적 15건을 닫고 남은 것을 절차적 잔여 4건으로만 남겼다.

## 2. 비모호성

**doc1 근거** — 상수 표를 단일 출처로 두고 근거가 약한 값은 별도 하위 표로 분리해 자백한다("### 운영 기본값 (근거 약함 — 운영 관행, 착수 후 조정 가능)", `PAGE_LIMIT_DEFAULT … API 관행(근거 없음)`). 미결정 절이 "0건 … 값이 정해졌으나 실측·확인이 남은 것은 위 '검증 대기 가정' 4건으로 관리 — 결정은 끝났고 검증만 남았다"로 '미결정 0'의 의미를 정의한다. 상수 재기술 위반(08 #2 CRITICAL)을 06은 상수명·파생식(`±1`), 07 compose는 `# = HEALTHCHECK_INTERVAL_S (03)` 주석 + `render.sh` 치환으로 정정했다.

**doc2 근거** — 03에 "## 미결정\n0건."이라 적었으나 자기 08이 "#4 릴레이 강등(FR-006·엣지 17)의 메커니즘이 미설계인데 03은 '미결정 0건' … 서버가 '릴레이로 붙었다'를 아는 경로도 없다(WS 클라→서버는 `ping`만)"고 반박한다. "#6 상수 표 밖 숫자 직접 기입 — 03:98 '30초 안에 모션 5회'(= EVENT_COOLDOWN_SEC) … 07:37 healthcheck `interval: 30s, retries: 3`"는 07 compose 스케치에 그대로 남아 있다(`healthcheck: { … interval: 30s, timeout: 3s, retries: 3 }`). 문서 간 표기 불일치도 살아 있다 — 04 시퀀스 2는 `409 device_offline`·`423 ptz_locked`, 05 slug 표는 `device-offline`·`ptz-locked`; 04 프라이버시 절은 클립 캐시 수명을 `STREAM_TOKEN_TTL_SEC`로, 05 E42는 `CLIP_CACHE_TTL_MIN`으로 쓴다.

판정: doc1 — doc2는 "미결정 0건" 선언이 미설계 구간을 덮고 있고 상수 밖 숫자·slug 표기 불일치가 본문에 그대로 남아 있는 반면, doc1은 같은 결함을 지적받아 상수명·파생식으로 치환했다.

## 3. 검증가능성

**doc1 근거** — SC-001~010이 전부 pass/fail + 측정 방법을 갖고("SC-006 … 24h 정상 운영 중 SD(rootfs) 쓰기 ≤ SD_WRITE_MAX_MB_DAY | `iostat -d` 누적 kB_wrtn"), 상한이 상수 파생으로 검산된다("OFFLINE_DETECT_MAX_S | 60 | s | 목표 상한. 최악 = HEALTH_PROBE_INTERVAL_S × OFFLINE_AFTER_FAILURES + PROBE_TIMEOUT_S = 55"). T-024도 같은 식을 그대로 단언한다. 시뮬레이터로 못 재는 5개를 lab 레이어로 분리하고 T-045~052·T-062로 지정했다.

**doc2 근거** — SC-001~015가 pass/fail이고 측정 조건이 더 촘촘하다("SC-001 … 카메라 앞 밀리초 시계를 촬영, 화면 캡처와 대조 30회 (Wi-Fi·LTE 각 15회)"), INV는 속성 테스트로 증명한다("INV-1~7 | 속성 테스트(hypothesis) 각 1개 이상"). 그러나 자기 08이 "#5 SC-008이 측정 불가 — 'WATCHDOG_TIMEOUT_SEC + 부팅 시간'에서 부팅 시간이 상수가 아니라 pass/fail 상한이 없다", "#20 '프레임 드롭 0' 기준의 flaky 위험 … 06의 flaky 0 정책과 충돌한다. 허용치 상수가 필요하다"(SC-011·SC-015에 걸림)고 판정했다.

판정: doc1 — 두 문서의 SC 품질은 비슷하나 doc2는 상한 없는 SC-008과 flaky 정책과 충돌하는 "프레임 드롭 0" 두 건이 미해결로 남았고, doc1의 기준은 전부 명명된 상수·파생식에 묶여 있다.

## 4. 실행가능성

**doc1 근거** — 07이 compose.yaml(하드닝 옵션 포함)·Dockerfile·`install.sh` 4단계·CI/CD 8단계 표·디렉터리 2단계·`.env.example`(키 이름만)까지 주고, "첫 작업 3개"가 GREEN 조건을 테스트 ID로 못 박는다("① 등록→스트림→그리드 관통 … T-007·T-015·T-016·T-018·T-042 GREEN. 여기서 검증 대기 가정(03) 4개를 함께 해소"). 08 선행 조건 3건은 전부 SPEC 작성 중 대조 또는 첫 작업에서 해소되는 항목이다.

**doc2 근거** — 착수 자산은 동등한 구성(디렉터리·`.env.example`·첫 작업 3개·실기 장비 목록)이지만, 08 판정문이 직접 "04 시퀀스의 구 토픽·경로 잔존, 읽기전용 rootfs와 OTA의 충돌, 릴레이 강등 메커니즘 공백을 '미결정 0건'으로 덮은 것, 측정 불가 SC-008, 저장 상수 모순은 이 문서만 들고 구현을 시작하면 첫 스켈레톤에서 되돌아오게 만든다"고 쓴다. 실제로 07 firstrun은 "compose pull(digest 고정) → Overlay FS 활성 후 재부팅"인데 08 #3은 "이후 `cmd/deploy`의 digest pull은 `/var/lib/docker`(rootfs = RAM 상위 레이어)에 쓰인다 → 재부팅 시 롤백/배포 상태 소실 … FR-023·SC-010·ADR-4가 운영에서 성립하지 않는다"고 한다. 핸드오프 선행 조건 5개가 "SPEC 작성 전에 닫는다"로 걸려 있다.

판정: doc1 — doc2는 SPEC 작성 전에 닫아야 할 선행 조건 5개(설계 공백 1건·아키텍처 충돌 1건 포함)를 남겼고 그 사실을 스스로 명시한 반면, doc1은 남은 4건이 첫 작업 중 검증 항목으로 정리돼 바로 착수 가능하다.

## 5. 근거성

**doc1 근거** — 01이 사실/추론/미확인을 라벨링하고 확인일을 붙인다("**사실**: ONVIF는 Profile S 신규 적합성 인증 접수를 2027-03-31부로 종료 … 출처: … (확인일 2026-09-07)"), 미확인 11항목을 목록으로 남긴다. fit 표가 "왜(요소) / 버린 대안(왜)" 두 열을 갖고 ADR-1~7에 "결과(트레이드오프)" 열이 있다. 근거 없는 값은 그렇게 적는다("MVP_TARGET_WEEKS | 4~6 | 주 | 계획 가정(근거 없음, 02 축 7)").

**doc2 근거** — 소스 규율이 더 촘촘한 구간이 있다: 확정/가능성/미확인을 주장 단위로 붙이고 교차확인 소스 수를 명시하며("3개 독립 소스 교차확인"), 해당 없음도 사유로 닫는다("**GDPR — 해당 없음(확정, 사유 명시)** … 제3조(역외적용) 요건 … 충족하지 않는다"). 상수 표는 근거 유형을 출처 URL/설계 결정 DL-#/미확인으로 나누고 미확인 2건을 격리한다("TURN_RELAY_COST | — | 원/GB | 미확인 … SC에 쓰지 않는다"). 반대편에는 자기 08의 CRITICAL이 있다: "#1 웹 프론트엔드 스택(React + Tailwind + Zustand)·caddy에 근거가 없다 … 검색·fit 요소·기각 대안 없이 04 구조도에 처음 등장한다", "#7 CLIP_STORAGE_MIN_GB와 EVENTS_PER_CAM_DAY_MAX가 서로 모순 — 저장은 50이벤트/일로 산정했는데 선언된 상한은 500이벤트/일".

판정: tie — 양쪽 다 라벨링·출처·확인일·기각 대안을 갖췄고, 각자 한 건씩 대칭적인 결함(doc1: 운영 기본값 14개가 "관행·근거 없음", doc2: 프론트 스택 무근거 + 저장 상수 10× 모순)을 안고 있어 우열을 가릴 수준이 아니다.

## 6. 범위 절제

**doc1 근거** — 시드 범위에 맞춰 만들 것을 좁힌다("search-first 결론: Adopt(go2rtc·Tailscale·ntfy·SQLite) + Build(…). 자체 코드는 '카메라 등록→제어→상태→알림' 도메인 로직에 한정한다"). 기각 사유가 YAGNI로 일관된다("React/Vite SPA — 화면 수 대비 빌드·번들 부담 과잉(YAGNI). 단 화면이 5장 이상으로 커지면 재검토", "Prometheus `/metrics`는 소비자 없음(1인 운영) → P2"). P1 블라인드스팟 기본값도 축소 채택하고 사유를 남긴다("A/B 파티션·서명 검증은 기기 1대·1인 운영이라 non-goal(비용>편익)").

**doc2 근거** — 시드에 없던 중앙 서버·멀티사이트를 해석으로 끌어들여("**원격 시청 경로 = 중앙 서버(클라우드/온프렘) 경유** … — 틀리면 서버 컴포넌트 전체가 불필요/필요", "사이트 ≤10곳") VPS + PostgreSQL + mosquitto + coturn + 내부 CA + cosign OTA + PWA + RBAC·초대까지 확장하는데, 전제 팀은 "팀 1~2명"이다. 자기 08도 "#22 YAGNI — INV-7 전 테이블 `workspace_id`(03:76)는 seed 7 non-goal(다중 테넌트)에 대한 hedge; Event 월 파티션은 … 일 1회 행 DELETE와 중복; CAMERA.password_enc 서버 컬럼은 항상 null; E44·E26은 FR 없는 엔드포인트"라고 적는다.

판정: doc1 — doc2는 시드에 없는 다중 사이트·중앙 서버 전제를 스스로 세워 서버·CA·TURN·OTA 서명·PWA까지 붙였고 non-goal(다중 테넌트) 대비 hedge까지 남겨 자기 검토관에게 YAGNI 4건을 지적받았다.

## 종합 판정: doc1

두 문서 다 같은 단계 구성(정찰→PRD→아키텍처→계약→테스트→운영→준비도)을 갖췄고 조사 품질과 성공 기준의 계량 수준은 대등하지만, 갈린 지점은 "결정이 닫혔는가"다. doc1은 검토 지적 15건을 전부 패치해 상수·상태 정의·자가복구 경로가 03~07에 일관되게 전파된 상태로 마감했고, doc2는 30건 중 2건만 반영한 채 설계 공백(릴레이 강등)과 운영에서 깨지는 충돌(읽기전용 rootfs ↔ Docker data-root OTA)을 핸드오프 선행 조건으로 넘기면서 "이 문서만 들고 구현을 시작하면 첫 스켈레톤에서 되돌아온다"고 스스로 적었다. 여기에 doc2가 시드에 없는 중앙 서버·멀티사이트 fleet을 1~2인 팀 전제 위에 얹은 범위 팽창이 겹쳐, 구현 착수 적합성에서 doc1이 앞선다.
