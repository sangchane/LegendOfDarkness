## [2. 비모호성]

**doc1 근거** — 자기 문서의 검토관이 미해결 모호성을 목록으로 남겼다. "상수 표 밖 숫자 직접 기입 — 03:98 엣지 9 '30초 안에 모션 5회'(= EVENT_COOLDOWN_SEC), '1초'(= LIVE_LATENCY_P95), '60초'; 04:55 '250Mbps × 2'·'약 5%'; 06:55 '30초'; 07:37 healthcheck `interval: 30s, retries: 3`(= HEALTHCHECK_*), '1시간 창', '30일 순환'". "릴레이 강등(FR-006·엣지 17)의 메커니즘이 미설계인데 03은 '미결정 0건'" — 03의 "## 미결정 / 0건."이 실제 공백을 덮고 있다. 표기 불일치도 남았다: D01 경로 `devices/{d}/events/{e}/thumbnail` vs `device/events/{event_id}/thumbnail`, `device_offline`·`ptz_locked` vs slug `device-offline`·`ptz-locked`, 용어 드리프트 "'운영자' — 03은 시설 운영자, 07은 알람 수신 운영 담당".

**doc2 근거** — 같은 유형의 지적을 받고 닫았다. "06·05·07·04 — 03 상수가 값으로 재기술(단일 출처 위반) | 타당 | 06 T-001/002/…를 상수명·파생식(`±1`)으로, 05 detail은 `{상수}` 템플릿, 07 compose는 `# = 상수명` 주석 + `render.sh` 치환 명시". 실제로 compose에 "interval: 30s  # = HEALTHCHECK_INTERVAL_S (03)"로 주석이 붙어 있다. "미결정 0건"을 선언하되 회피하지 않고 분리했다: "검증 대기 가정 (값은 결정됨 — 미결정이 아니라 착수 첫 작업의 검증 항목)" 4건. 용어 모호성도 정의로 제거: "시청 세션 | 활성 스트림(WS)을 하나 이상 가진 로그인 세션 = 뷰어 1명. WS 수가 아니다", 상태 4종 정의, 기산점 통일 "기산점 = `event.ts`로 통일".

**판정: doc2** — doc1은 상수 밖 숫자 9곳·문서 간 표기 불일치·"미결정 0건"이 덮은 미설계가 본문에 남아 있고, doc2는 동일 유형을 단일 출처 참조와 정의문으로 닫았다.

## [3. 검증가능성]

**doc1 근거** — SC-001~015가 전부 pass/fail이고 측정 방법에 회수까지 있다. "SC-001 | 라이브 glass-to-glass 지연 p95 ≤ LIVE_LATENCY_P95 | 카메라 앞 밀리초 시계를 촬영, 화면 캡처와 대조 30회 (Wi-Fi·LTE 각 15회)", 실기 계층을 분리해 "SC-001·002·003·004·008·013 + SC-009·010·015 각 1회 = 릴리스 게이트 | 목킹으로 증명 불가".
그러나 pass/fail이 성립하지 않는 항목이 남았다: "SC-008이 측정 불가 — 'WATCHDOG_TIMEOUT_SEC + 부팅 시간'에서 부팅 시간이 상수가 아니라 pass/fail 상한이 없다", "'프레임 드롭 0' 기준의 flaky 위험 — WebRTC `framesDropped`는 정상 상태에서도 0이 아니어서 06의 flaky 0 정책과 충돌한다".

**판정: doc2** — 양쪽 다 SC가 pass/fail이지만, doc1은 SC-008 상한 부재·프레임 드롭 0의 flaky 충돌이 미해결로 남은 반면 doc2는 판정식을 상수 파생으로 고정하고 전수 매핑을 명시했다.

## [4. 실행가능성]

**doc1 근거** — 착수 자산은 충실하다: 디렉터리 2단계, `.env.example` 키 이름만, 첫 작업 3개가 Impact×Uncertainty 순, 실기 장비 목록, 모델 힌트.
그러나 문서가 스스로 착수를 막는다. "이 문서만 들고 구현을 시작하면 첫 스켈레톤에서 되돌아오게 만든다", "핸드오프 선행 조건 (SPEC 작성 전에 닫는다)" 5개, `<preconditions>위 선행 조건 1~5를 SPEC 작성 전에 닫는다`. 막히는 지점이 구체적이다: "읽기전용 rootfs(Overlay FS)와 앱 계층 OTA가 충돌한다 … 쓰기 구역 목록에 Docker data-root가 없다. FR-023·SC-010·ADR-4가 운영에서 성립하지 않는다", "릴레이 강등 … 서버가 '릴레이로 붙었다'를 아는 경로도 없다".

**doc2 근거** — 같은 유형(rootfs·docker 로그가 SD를 씀)을 이미 닫아 두었다. "07 — docker json-file 로그가 SD로 감 | 타당 | docker `data-root: /data/docker`(SSD). 02·04·07 전파"가 설치 스크립트에 반영돼 있다. compose 전문·Dockerfile 전문·CI 8단계 표·`.env.example`·런북 RB-01 전문이 복붙 수준 명령까지 있다. 선행 조건은 착수를 막지 않고 착수 안에 배치했다: "1. … SPEC 작성 중 대조 2. 첫 작업 1에서 03 '검증 대기 가정' 4건 해소 3. 실기기 lab은 첫 작업 3에서".

**판정: doc2** — doc1은 자기 문서로 "이 문서만 들고 시작하면 되돌아온다"고 판정하고 선행 조건 5개를 SPEC 작성 전 차단 조건으로 걸었으나, doc2는 동급 지적을 본문에 반영해 선행 조건을 착수 과정 안으로 넣었다.

## [5. 근거성]

**doc1 근거** — 근거 밀도가 더 높다. "정량 근거 모음" 표 27행이 항목·값·출처 URL·확인일 4열, "미확인으로 남은 핵심 항목" 9건. 상수 표 60여 개가 전부 근거 열을 갖고 유형이 4분류다: "LIVE_LATENCY_P95 | 1.0 | 초 | 출처 URL … + 설계 결정 DL-011 (2배 여유)", "근거 유형을 넷으로 분리: 출처 URL / 실측 / 설계 결정 DL-# / 미확인". 미확인 상수를 결과에서 격리하는 규칙이 있고 실제로 지켜졌다: "TURN_RELAY_COST | — | 원/GB | 미확인 … SC에 쓰지 않는다"와 검토관 확인 "미확인 상수 격리 … SC/FR/06/07 미사용". 법 상수는 "가능성"으로 낮추고 선행 조건화했다. fit 표 11행이 결정 요소와 기각 대안을 명시.

**doc2 근거** — 라벨링은 정직하다. "사실/추론/미확인" 3단 라벨, 미확인 목록 11건, 근거 약한 상수를 별도 표로 분리 "운영 기본값 (근거 약함 — 운영 관행, 착수 후 조정 가능)". Pi 5 코덱은 포럼 + 공식 제품 페이지 교차확인.
약점은 근거 등급 자체다. 백엔드 언어 선택이 "추론(일반 아키텍처 지식, 이번 세션 벤치마크 검색은 안 함)"이고, 핵심 성능 상수가 단일 커뮤니티 코멘트 기반, 상수 근거에 "추론" 표기가 반복된다.

**판정: doc1** — 출처 표가 27행 대 15행으로 두껍고, 상수마다 근거 유형 4분류가 일관되며 "미확인 상수는 SC에 쓰지 않는다"는 격리 규칙이 검토관 대조로 실제 준수가 확인된다.

## [6. 범위 절제]

**doc1 근거** — 자기 검토관이 YAGNI를 항목으로 지적했고 미해결로 이월했다: workspace_id hedge, 중복 파티션, 항상 null 컬럼, FR 없는 엔드포인트. seed에 없던 중앙 서버·멀티사이트를 해석으로 도입한 뒤 그 위에 VPS + mosquitto + coturn + PostgreSQL 파티셔닝 + 내부 CA + cosign 서명 OTA + 웹 푸시 + 초대/역할 + 감사 점검 리마인더가 쌓인다. 가드 상수도 설계 한도를 넘는다.

**doc2 근거** — 축소 결정마다 사유와 재검토 조건을 붙였다. "read-only rootfs·A/B 파티션·X.509 fleet 신원은 P1 기본값에서 축소 채택(단일 기기·1인 운영·비용>편익) … 재검토 조건: 기기 2대 이상 또는 무인 원격지 설치". 만들지 않을 것을 먼저 정했다: "객체 감지가 목적이면 Frigate가 정답(만들지 않는다)", "Adopt(go2rtc·Tailscale·ntfy·SQLite) + Build(…). 자체 코드는 도메인 로직에 한정". 프론트·관측·멱등키에서도 절제했다.

**판정: doc2** — doc1은 자체 검토가 지목한 YAGNI 4건을 그대로 두었고, doc2는 축소마다 사유·재검토 조건을 달아 요구에 비례시켰다.

## 종합 판정: doc2

doc1은 조사 밀도와 근거 추적(출처 27행·상수 4분류·미확인 격리 규칙)에서 앞서고 다루는 영역도 더 넓지만, 자기 검토관이 찾은 HIGH 5·MEDIUM 15·LOW 8을 본문에 미해결로 남긴 채 "이 문서만 들고 구현을 시작하면 첫 스켈레톤에서 되돌아온다"고 스스로 판정했다. doc2는 같은 등급의 지적 15건을 전부 패치해 본문에 반영했고, 수용 기준을 상수 파생식으로 고정하며 축소 결정마다 사유와 재검토 조건을 달아 요구에 비례시켰다. 길이는 doc1이 크지만 구현 착수에 필요한 정보의 밀도 — 특히 비모호성·검증가능성·실행가능성·범위 절제 — 에서 doc2가 4개 차원을 가져간다.
