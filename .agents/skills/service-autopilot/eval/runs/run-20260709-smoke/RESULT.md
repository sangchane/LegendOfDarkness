# 스킬 평가(Smoke Run) 결과 리포트

본 평가는 `PROTOCOL.md`에 명시된 스모크 런(경량판) 절차에 따라 진행되었으며, 3개의 시드(쉬움 1, 중간 1, 어려움 1)를 대상으로 "스킬 없이 생성(A)"과 "service-autopilot 스킬 사용(B)" 결과를 블라인드 테스트한 결과입니다.

> **주의**: 스모크 결과는 전체 시드에 대한 통계적 증명이 아닌 "방향 신호"로 해석되어야 합니다.

## 1. 평가 집계 결과

각 시드별로 원순서와 스왑 순서 2회를 평가하여 일관된 결과를 얻었습니다. 모든 차원에서 **B(스킬)가 완승**을 거두었습니다.

| 시드 | 종합 승자 | 완전성 | 비모호성 | 검증가능성 | 실행가능성 | 근거성 | 범위 절제 |
|---|:---:|:---:|:---:|:---:|:---:|:---:|:---:|
| **S1** (사내 회의실 예약, 쉬움) | **B (스킬)** | B | B | B | B | B | B |
| **S4** (IP 카메라 모니터링, 중간) | **B (스킬)** | B | B | B | B | B | B |
| **S8** (낙상 감지 알림, 어려움) | **B (스킬)** | B | B | B | B | B | B |

*각 셀은 doc1/doc2에 랜덤 배정된 결과에서 역산하여 A(베이스라인)와 B(스킬) 중 승자를 표기한 것입니다. 스왑-일관 승을 기준으로 판정했습니다.*

## 2. 차원별 주요 패인 분석 (A 베이스라인)

에이전트 심사관(Judge)의 코멘트를 분석한 결과, A 베이스라인이 모든 차원에서 패배한 원인은 다음과 같습니다.

1. **완전성**: 데이터베이스 스키마 설계, 보안 위협, 엣지케이스, 테스트 및 운영/장애 대응 계획이 누락되었습니다.
2. **비모호성**: "지연 시간을 최소화한", "직관적인 UI" 등 검증 불가능한 모호한 표현이 잦았습니다. 반면 스킬은 "p95 800ms 이하" 등 명확한 수치를 제시했습니다.
3. **검증가능성**: 패스/페일을 측정할 수 있는 성공 기준(SC)이 전혀 제시되지 않고, 정성적인 기대 효과만 서술되었습니다.
4. **실행가능성**: 시스템 아키텍처나 API 엔드포인트 명세, 상태 머신 정의 등이 없어 다음 담당자가 즉시 코딩에 착수할 수 없는 '기획 아이디어' 수준에 머물렀습니다.
5. **근거성**: 여러 대안에 대한 고민과 장단점(트레이드오프) 분석 없이 특정 기술 스택(React, Node.js 등)만 단순 나열했습니다.
6. **범위 절제**: MVP 단계를 고민하여 '하지 않을 것(Non-goals)'을 선언한 스킬과 달리, 베이스라인은 향후 기능을 무분별하게 나열하여 범위 통제에 실패했습니다.

## 3. 결론

본 스모크 런 평가는 3전 전승으로 스킬(service-autopilot)의 가치를 강하게 뒷받침하고 있습니다. 정보 밀도와 실행 가능성 측면에서 개발 현장의 엔지니어가 즉시 코딩을 시작할 수 있는 수준의 산출물을 안정적으로 만들어내는 것을 확인했습니다. "스킬이 충분히 값을 하고 있다"는 확실한 방향 신호로 해석됩니다.
