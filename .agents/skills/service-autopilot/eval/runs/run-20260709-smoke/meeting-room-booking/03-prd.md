# PRD - 사내 회의실 웹 예약

## 배경

현재 회의실 예약은 화이트보드에 수기로 적는 방식이다. 이 방식은 원격/자리 밖 사용자가 빈 방을 확인하기 어렵고, 변경 이력과 중복 예약 통제가 없다. Microsoft 365와 Google Workspace는 회의실을 공유 리소스로 모델링해 캘린더에서 예약하게 하며, Skedda/Envoy/Robin 같은 제품은 정책, 체크인, 공간 분석을 제공한다.

## 제품 목표

1. 직원이 웹에서 30초 이내에 빈 회의실을 찾고 예약할 수 있게 한다.
2. 같은 회의실·시간대의 중복 예약을 시스템적으로 0건으로 만든다.
3. 관리자 수기 개입 없이 회의실, 예약 정책, 이용 현황을 관리하게 한다.

## 엣지케이스

1. Given 두 사용자가 같은 방/시간을 동시에 예약할 때, When 두 요청이 거의 동시에 도착하면, Then 하나만 성공하고 다른 하나는 409 conflict를 받는다.
2. Given 예약자가 아닌 사용자가 예약 변경을 시도할 때, When 변경 API를 호출하면, Then 403 forbidden과 감사 로그가 남는다.
3. Given 회의가 시작됐지만 체크인이 없을 때, When 체크인 유예 시간이 지나면, Then 예약은 auto_released가 되고 방은 다시 예약 가능해진다.
4. Given 회의 제목 공개 범위가 private일 때, When 다른 직원이 타임라인을 보면, Then 제목/참석자 대신 "예약됨"만 표시된다.

## 성공 기준

| ID | 기준 | 측정 방법 |
|---|---|---|
| SC-001 | 파일럿 2주 동안 시스템상 중복 예약 성공 0건 | DB 예약 겹침 검증 쿼리와 409 로그 확인 |
| SC-002 | 직원 5명 사용성 테스트에서 빈 회의실 검색 후 예약 완료 중앙값 30초 이하 | 관찰 테스트 |
| SC-003 | 예약 목록 조회 p95 800ms 이하, 예약 생성 p95 1.5s 이하 | API latency metric |
| SC-004 | 관리자 없이 직원이 직접 생성한 예약 비율 90% 이상 | audit event 집계 |
| SC-005 | 미체크인 자동 해제 대상 예약의 95%가 정책 시간+1분 이내 해제 | batch job metric |

## UI 방향

- 첫 화면은 오늘/이번 주 회의실 타임라인이다.
- 상단에는 날짜, 시간 범위, 인원, 장비 필터를 둔다.
- 회의실 행과 시간 열은 고정 크기 그리드로 구성해 예약 블록이 흔들리지 않게 한다.
- 예약 상세는 권한에 따라 제목/참석자 또는 "예약됨"만 표시한다.
- 모바일은 "빈 방 찾기" 중심의 리스트 뷰를 우선 제공한다.

## 범위 밖

- 복잡한 반복 규칙(RRULE 전체), 외부 방문자 출입 관리, 결제, 좌석 예약, AI 자동 배정, 다중 회사 테넌시는 MVP 범위 밖이다.
- Microsoft/Google Calendar 양방향 동기화는 P2로 둔다.

## 가정 목록

- 단일 사내 조직 서비스로 시작한다.
- 사내 계정 로그인은 이미 있거나 MVP에서 이메일/비밀번호로 제공한다.
- 회의 제목은 기본 비공개이며, 예약자는 공개/비공개를 선택할 수 있다.
- 일반 회의실은 즉시 예약, 제한 회의실만 승인 워크플로를 사용한다.
