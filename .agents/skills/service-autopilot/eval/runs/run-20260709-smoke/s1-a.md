# 사내 회의실 예약 시스템 기획 및 설계 문서

## 1. 개요
- **목적**: 기존 화이트보드에 수기로 작성하던 회의실 예약 방식을 웹 기반 디지털 시스템으로 전환.
- **기대 효과**: 
  - 예약 충돌(Double Booking) 방지
  - 언제 어디서든 실시간 예약 현황 파악 및 예약 가능
  - 회의실 사용 빈도 분석 등 관리 효율성 증대

## 2. 주요 기능 요구사항

### 2.1 사용자 (일반 임직원)
- **인증/로그인**: 사내 계정 연동 (SSO 또는 독립 계정)
- **회의실 조회**: 
  - 날짜 및 시간대별 예약 현황을 한눈에 볼 수 있는 타임라인/캘린더 뷰
  - 수용 인원 및 비품(프로젝터, 화이트보드 등) 조건에 따른 회의실 필터링
- **회의실 예약**: 
  - 회의 날짜, 시작/종료 시간, 회의 목적, 참석자 입력
- **예약 관리**: 
  - 본인의 예약 내역 조회, 수정, 취소
- **알림 (옵션)**: 
  - 예약 완료, 변경, 취소 시 사내 메신저 또는 이메일 알림

### 2.2 관리자
- **회의실 정보 관리**: 회의실 신규 등록, 정보 수정, 비활성화/삭제
- **전체 예약 관리**: 모든 예약 내역 조회 및 필요 시 강제 취소 권한
- **통계**: 부서별, 회의실별 사용 빈도 리포트 제공

## 3. 시스템 아키텍처 및 기술 스택 (예시)
- **Frontend**: React.js / Vue.js 기반 반응형 웹 (모바일 지원)
- **Backend**: Node.js (Express) / Spring Boot 등 REST API 서버
- **Database**: PostgreSQL / MySQL (관계형 DB)

## 4. 데이터베이스 스키마 설계 (핵심 엔티티)

1. **User (사용자)**
   - `id` (PK, 사번 등)
   - `name` (이름)
   - `department` (소속 부서)
   - `role` (권한: USER / ADMIN)

2. **Room (회의실)**
   - `id` (PK)
   - `name` (회의실 이름)
   - `capacity` (수용 인원)
   - `resources` (프로젝터, 화상회의 장비 등)
   - `is_active` (사용 가능 여부)

3. **Booking (예약)**
   - `id` (PK)
   - `room_id` (FK, Room)
   - `user_id` (FK, User)
   - `title` (회의 목적/제목)
   - `start_time` (시작 일시)
   - `end_time` (종료 일시)
   - `status` (상태: CONFIRMED, CANCELLED)

## 5. 단계별 추진 계획
- **Phase 1 (MVP)**: 기본 조회 및 예약, 취소 기능 구현
- **Phase 2**: 메신저/이메일 알림 연동, 참석자 초대 기능 추가
- **Phase 3**: 회의실 앞 태블릿 연동(현장 예약 및 체크인/노쇼 관리)
