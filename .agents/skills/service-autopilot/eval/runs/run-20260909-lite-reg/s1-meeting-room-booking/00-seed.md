# Seed — 사내 회의실 예약 (meeting-room-booking)
- 원문: lite 사내 회의실 예약을 웹에서 하고 싶다. 지금은 화이트보드에 수기로 적는다.
- 서비스 유형: 웹 (사내 내부 도구 — 웹 SaaS 프로파일을 단일 테넌트로 축소 적용)
- 주 도메인 / 인접 도메인: 사내 자원(회의실) 예약·스케줄링 / 사내 인증, 캘린더·일정, 시설 관리
- 감지된 제약:
  - 사내용(외부 고객 없음, 판매 없음)
  - 웹으로(설치형 앱·네이티브 앱 아님)
  - 현재 화이트보드 수기 → 회의실·인원 규모가 화이트보드 1장으로 관리되는 수준, 도입 마찰이 낮아야 대체됨
  - 현재 데이터 없음(이관 대상 없음)
- 로드할 블라인드스팟 프로파일: P2 웹 SaaS (테넌시·결제 항목은 사내 단일 테넌트라 "해당없음"으로 마킹)
- 강도: lite — 사유: 사용자가 `lite`로 지정. full 신호 표 대조: 돈·안전·법·민감정보 없음(예약자 이름·사내 이메일만), 외부 연동 0개, 동시 사용자 100명 미만 추정(화이트보드 규모), 하드웨어 없음, 1인 운영 추정, "정식/납품" 언급 없음 → 신호 0개. spike 조건(플랫폼·범위·핵심 루프 미확정) 없음 — 플랫폼=웹, 핵심 루프=빈 시간 찾기→예약→취소가 확정됨.
- 해석한 것 (사용자가 말하지 않았는데 내가 정한 것 — 전부 Assumed, 틀리면 비싼 순):
  1. **규모**: 단일 사무실(사이트 1개), 회의실 ≤ 10개, 임직원 ≤ 50명 — 화이트보드 1장이 감당하던 규모의 축소 기본값. 멀티사이트·수백 명은 확장 해석이라 채택하지 않음 (lite는 질문 0이므로 Assumed로 기록)
  2. **인증 경로**: 사내 이메일 도메인 매직링크(비밀번호 없음). Google Workspace/MS365 SSO 연동은 외부 연동(full 신호)이라 non-goal. 설계상 IdP 교체 가능하게 인증 모듈만 분리
  3. **배포 경로**: 사내 서버 1대(또는 저가 VPS) + Docker Compose, 1인 운영. 클라우드 매니지드·k8s 없음
  4. **사용 맥락**: PC 브라우저(회의 잡을 때)와 폰 브라우저(회의실 앞에서 확인)를 함께 쓰는 반응형 웹. 세션 길이 1~2분. 네이티브 앱·키오스크 없음
  5. **핵심 루프 범위**: 회의실별 오늘/주간 타임라인 보기 → 빈 슬롯 예약 → 내 예약 취소. 반복 예약·초대·캘린더 동기화·장비(빔 등) 예약은 MVP 밖
  6. **권한 모델**: 임직원 전원 예약·본인 예약 취소, 관리자 1명이 회의실 등록·타인 예약 취소
  7. **지역·언어**: 한국어 UI, Asia/Seoul 단일 시간대
  8. **시간 단위**: 예약 슬롯 15분 단위, 최대 1건 길이·선예약 기간은 03 상수 표에서 확정
- 기존 시스템: 없음 (화이트보드 수기 — 코드·데이터 이관 대상 없음. A1 "현재 시스템 감사" 절은 화이트보드 운영 방식의 관찰 기록으로 대체)
