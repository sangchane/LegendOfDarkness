# 블라인드스팟 레지스터 — 사내 회의실 예약
스캔: 공통 11축 + STRIDE 6범주 + 프로파일 P2 웹 SaaS(단일 테넌트 축소) 6항목 = 23항목 · 스캔일 2026-09-09
강도 lite: 질문 0이 기본. 1문항 허용 조건(Impact = 데이터 손실·법)에 해당하는 축이 있는지 아래 "질문 승격 검토"에서 판정했다.

## 왜 만드는가 (product-lens Mode 1 — 7문항, 산출물에 흡수)
1. 누구를 위해: 화이트보드 앞까지 가야 빈 방을 아는 임직원 ≤50명과, 겹친 예약을 중재하는 총무 1명 [추론, 00-seed 해석 1·6]
2. 고통: 매일 회의 잡을 때마다 발생. 사무실 밖에서는 아예 못 봄, 취소가 전파 안 됨, 분쟁 시 기록 없음 [01 업무 흐름]. 오늘의 대안 = 화이트보드 [사용자]
3. 왜 지금: 사용자가 "웹에서 하고 싶다"고 결정함 [사용자]. 무료 OSS(MRBS·LibreBooking)가 존재해 0원 대안이 있다 [01]
4. 10점짜리: SSO + 캘린더 양방향 동기화 + 회의실 앞 태블릿 + 평면도 — 전부 non-goal (full 신호)
5. MVP: 회의실 타임라인 보기 → 빈 슬롯 예약 → 내 예약 취소, 관리자 회의실 CRUD. 그게 전부 [00 해석 5]
6. 안티골: 반복 예약·초대·캘린더 연동·장비 예약·멀티사이트·SSO·결제
7. 성공 측정: 도입 4주 뒤 화이트보드 철거 가능 여부(= 주간 예약의 100%가 시스템에 있음) + 이중예약 0건 → 03 SC로 변환
go/no-go: **go, 단 DL-4 선행 조건(MRBS 데모 30분) 유지**.
