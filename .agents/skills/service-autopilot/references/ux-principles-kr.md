## A. 토스 컨슈머 UX 가이드 (14개 원칙, 3개 적용군)

### A-1. 다크패턴 방지 (5) — 화면 흐름 설계에 적용
| # | 원칙 | 규칙 |
|---|---|---|
| T-04 | 진입 방해 금지 | 진입 즉시 모달/바텀시트/팝업을 띄우지 않는다 |
| T-05 | 이탈 방해 금지 | 뒤로가기/닫기 시 추가 동의·확인을 강제하지 않는다 |
| T-06 | 선택지 강제 금지 | 주 CTA 외의 선택(취소, 나중에)이 항상 가능해야 한다 |
| T-07 | 예상 밖 노출 금지 | 사용 흐름 중간에 맥락 없는 요소를 끼워넣지 않는다 |
| T-08 | 명확한 CTA | 버튼 라벨은 누르면 일어날 다음 행동을 그대로 쓴다 ("확인" 대신 "워프 저장") |

### A-2. UX 라이팅 (5) — 모든 문구에 적용
| # | 원칙 | 규칙 |
|---|---|---|
| T-09 | 해요체 통일 | 사용자 대면 문구는 해요체로 통일 |
| T-10 | 능동형 | "저장됐어요"보다 "저장했어요" — 시스템이 행위 주체임을 감추지 않는다 |
| T-11 | 긍정형 | "안 돼요" 대신 "이렇게 하면 할 수 있어요" |
| T-12 | 캐주얼한 경어 | 과도한 경어·한자어 제거 |
| T-13 | 명사 단순화 | 명사+명사 연쇄 회피, 풀어쓴다 ("워프 목적지 좌표 설정" → "어디로 이동할지 정하기") |

### A-3. 브랜딩/그래픽 (4) — 내부 도구에는 선택 적용
T-01(로고 규격)·T-02(한글 이름)·T-03(브랜드 컬러 대비)·T-14(장식 아닌 정보 전달 목적 그래픽만). 내부 도구 기획에서는 T-14만 필수로 본다.

## B. UX 심리학 10법칙 (측정 기준의 근거로 사용)

| # | 법칙 | 실행 규칙 | 측정 가능 기준 예시 (quality-decomposition target 후보) |
|---|---|---|---|
| L-01 | 제이콥의 법칙 | 사용자가 이미 아는 패턴(업계 표준 도구의 관습)을 따른다 | 동일 태스크의 표준 도구 대비 새로 배울 개념 수 N개 이하 |
| L-02 | 피츠의 법칙 | 클릭 대상은 크고 가깝게 | 주요 액션 클릭 타깃 ≥ 32px, 연속 액션 간 마우스 이동 최소화 |
| L-03 | 힉의 법칙 | 한 화면(패널)의 목적은 하나 | 화면/패널당 사용자 결정 지점 1개 |
| L-04 | 밀러의 법칙 | 한 그룹에 7±2개 이하로 청킹 | 메뉴/툴바 그룹당 항목 ≤ 7, 그룹 간 경계 명시 |
| L-05 | 포스텔의 법칙 | 입력은 관대하게 받고 출력은 엄격하게 | 좌표 등 입력을 클릭·드래그·직접입력 모두 허용 |
| L-06 | 피크엔드 효과 | 실패/에러 경험을 완화한다 | 에러 시 복구 경로 제시율 100% (막다른 에러 0) |
| L-07 | 테슬러의 법칙 | 불가피한 복잡성은 시스템이 흡수 | 사용자가 손으로 계산/기억해야 하는 값 0개 (자동 제안) |
| L-08 | 심미적 사용성 | 첫인상(50ms)이 사용성 인식을 좌우 | 일관된 spacing/컬러 토큰 사용률 (하드코딩 스타일 0) |
| L-09 | 폰 레스토프 효과 | 강조는 화면당 1곳만 | 화면당 강조색 CTA 1개, 배지/경고 남발 금지 |
| L-10 | 도허티 임계 | 0.4초 이내 피드백 | 모든 액션 시각 피드백 ≤ 400ms (초과 시 스켈레톤/로딩 표시) |

## 적용 방법

1. **Propose 단계**: 프론트엔드/화면 흐름 결정 카드를 만들 때, 각 후보안이 위 원칙 중 무엇을 지키고 무엇을 어기는지 tradeoff 란에 명시한다 (예: "탭 5개 추가안은 L-04 위반").
2. **quality-decomposition 변환**: "직관적", "쉬운" 류 표현을 변환할 때 B표의 측정 기준 예시를 target의 출발점으로 쓴다. 기준 ID는 UX-NN으로 새로 발급하되 근거 법칙(L-NN/T-NN)을 병기한다.
3. **05/07 산출물**: 비기능 요구와 완료 기준에 UX-NN(근거 L-NN) 형태로 인용한다. "토스 가이드 준수" 같은 뭉뚱그린 표현 금지 — 개별 원칙 ID로만 인용한다.
