# 안티패턴 · 리뷰 루브릭

REVIEW 단계와 프론트엔드 작업 시 체크리스트로 적용한다. 세 묶음이다:
(A) 에이전트 협업 안티패턴, (B) 거짓 진척 방지, (C) 프론트엔드 slop(디자인 티나는 AI 냄새).

---

## A. 에이전트 협업 안티패턴 (피할 것)

*(Claude Code best practices · gstack)*

- **키친싱크 세션** — 무관한 일을 한 세션에 몰아넣기. → 작업마다 `/clear`.
- **계속 고치기** — 같은 지시를 반복 교정. 2번 실패하면 세션 비우고 프롬프트 재작성.
- **과적재 지침 파일** — CLAUDE.md가 비대해지면 에이전트가 규칙을 무시. 자명한 줄 삭제.
- **믿고 검증 안 함** — 증거 없이 "됐다"를 수용. VERIFY 게이트로 실행 결과를 요구.
- **무한 탐색** — 계획 없이 코드 뒤지기. EXPLORE는 산출물(노트)로 끝을 낸다.
- **아첨(sycophancy)** — "좋은 질문이에요", "흥미롭네요", "여러 방법이 있습니다" 같은
  내용 없는 맞장구. 리뷰어·PM 역할에선 금지. 동의도 근거를 대게 한다.
- **우회로 남발** — 3개 이상 착수 경로/배너로 문제를 덮기. 상태 기반 단일 CTA로 좁힌다.

## B. 거짓 진척 방지 (Definition of Done)

*(Claude Code "close the loop" · spec-kit gold-standard)*

완료로 보고하기 전 아래가 모두 참이어야 한다:

- [ ] 수용 기준을 **pass/fail로 판정**했고 전부 pass다.
- [ ] 테스트가 실제로 **실행**되어 통과했다(작성만 하고 안 돌린 것 금지).
- [ ] 빌드/타입체크/린트 종료코드가 0이다.
- [ ] (UI면) 실제 화면을 띄워 확인했다(스크린샷·수동 확인).
- [ ] 오류를 억누른 게 아니라 근본 원인을 고쳤다.
- [ ] 미완/기술부채는 숨기지 않고 "미완:"으로 명시했다.

하나라도 아니면 완료 상태는 `DONE_WITH_CONCERNS`이며 무엇이 남았는지 적는다.

## C. 프론트엔드 slop 체크리스트 (AI 티 제거)

*(MengTo/Skills — design-taste-frontend "AI Tells / Forbidden Patterns")*

대시보드·관제 UI를 만들 때 아래를 위반하면 반려한다:

- [ ] 순수 `#000000` 대신 근접 무채색(예: Zinc-950)을 쓴다.
- [ ] 네온 글로우·과한 그라디언트 금지. 그림자는 무채색 1종/상태.
- [ ] 기본 폰트 `Inter`/거대 H1 남발 금지. 대시보드/소프트웨어 UI에 **세리프 금지**,
      숫자는 **모노스페이스(`font-mono`)**.
- [ ] 가짜 데이터 금지: "John Doe"/"Acme"/`99.99%` 대신 유기적 값(`47.2%`, `18 of 43`).
- [ ] 마케팅 필러 카피 금지("Elevate/Seamless/Unleash", "직관적인", "간편한").
- [ ] **동적 클래스명 금지**: `"text-" + color` 대신 룩업맵 사용(퍼지 시 사라짐).
      예: `const tone = { danger:"bg-rose-600", ok:"bg-emerald-600" }[status]`.
- [ ] 상태 누락 금지: **빈/로딩/에러 상태**를 모두 구현했다(실시간 데이터는 끊길 수 있음).
- [ ] `h-screen` 대신 `min-h-[100dvh]`, flex 퍼센트 계산 대신 CSS Grid.
- [ ] 애니메이션은 `transform`/`opacity`만(레이아웃 속성 애니 금지).
- [ ] 밀도 높은 관제 화면은 카드 박스 남발 대신 `border-t`/`divide-y`/여백으로 그룹화.

> 정성 표현이 요구사항/기획에 등장하면("토스처럼", "직관적") **측정 가능 기준으로 변환**한 뒤 진행한다
> (solution-planner의 quality-decomposition 원칙과 동일).

## 리뷰 판정 형식

REVIEW 산출은 다음 형식으로만:

```
결함 목록(심각도순):
- [심각도] file:line — 무엇이 왜 문제인가 — 재현/실패 시나리오
검증되지 않은 주장: (있으면)
판정: 통과 | 조건부 통과(수정 후) | 반려
```

근거 없는 칭찬·"괜찮아 보임"은 판정에 넣지 않는다.
