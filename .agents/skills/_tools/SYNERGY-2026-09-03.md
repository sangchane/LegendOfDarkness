## 정적 4 — 서로 강화하는 지점 (가능성 → 경험적 섹션에서 검증)

1. **라우팅이 autopilot의 빈 곳을 채운다.** A5 API 규약, A4 보안 점검, A7 배포 체크리스트는 원래 모델 기억에서 나왔다.
   이제 ecc:api-design·security-review·deployment-patterns의 체크리스트가 근거로 들어간다.
2. **ponytail이 prompt-workflow의 BUILD를 구체화한다.** ETHOS 10 "단순함 우선"은 원칙만 있었고 절차가 없었다. 사다리 7단이 절차다.
3. **Anthropic 형식 정렬이 이식성·평가 가능성을 준다.** `evals/evals.json`은 skill-creator와 `claude plugin eval`이 읽는 형식이라
   나중에 자동 회귀로 옮길 수 있다. `metadata.version`은 다른 PC·툴에서도 같은 의미로 읽힌다.
4. **카탈로그 스크립트가 세 층의 드리프트를 잡는다.** ecc를 업데이트해 스킬 이름이 바뀌면 라우팅 표가 종료코드 1로 깨진다.

  기준에서 단독 문서에 졌다. 정직함이 judge에게는 미완으로 읽힌다.
- **베이스라인이 달라졌다 (확정)**: Fable 5.1 단독 문서는 59~70KB로 7월 베이스라인(2~4KB)의 20배이며 위협모델·테스트 매트릭스·런북을 스스로 갖춘다.
  7월 "6:0 완승"과 이번 결과를 절대 비교하면 안 된다. 조합의 한계 효용은 모델이 강해질수록 줄어들고, 남는 값은 **근거·추적성·게이트**다.

## 경험적 2 — 코드 과제 A/B (ponytail 배선, n=1 → 방향 신호만)

과제: 표준 라이브러리만 쓰는 60줄짜리 할 일 CLI(`todo.py`)의 `list`에 `--since YYYY-MM-DD` 추가. 잘못된 날짜는 에러 종료, 테스트 포함.
같은 수용 기준 3개를 양쪽에 줬고, B에만 prompt-workflow BUILD 템플릿(`<ladder>` 포함)을 씌웠다. 둘 다 Fable 5.1 서브에이전트, ponytail 플러그인은 미설치.

| 지표 | A: 플레인 프롬프트 | B: BUILD 템플릿 + `<ladder>` |
|---|---:|---:|
| todo.py 순증 줄 | +10 | +11 (import 1줄 수정 포함) |
| 테스트 순증 줄 | +25 | +17 |
| 그 외 | README +1 | 없음 (`skipped: README, add when 문서 갱신 요청 시`로 명시) |
| 새 외부 의존성 | 0 | 0 |
| 접근 | `datetime.strptime` + argparse `type=` | `date.fromisoformat` + argparse `type=` |
| 테스트 우선 | 보고 없음 | 실패 테스트 먼저 작성·실행 확인 후 구현 |
| 의도적 단순화 표기 | 없음 | `# ponytail: UTC 날짜 비교, 로컬 필요 시 astimezone()` |
| 테스트 결과 | 4/4 OK | 4/4 OK |
| 토큰 / 시간 / 도구 호출 | 59,971 / 108초 / 8 | 61,230 / 140초 / 6 |

**읽기**: 코드 양은 사실상 같다. 이 과제는 이미 최소 해법이 자명해서 사다리가 깎을 게 없었고, 이는 ponytail 자체 벤치마크가
"already minimal한 코드에서는 near zero"라고 밝힌 것과 일치한다. 차이는 **절차**에서 났다: B만 실패 테스트를 먼저 돌렸고,
건너뛴 것과 추가 시점을 명시했고, 단순화의 상한을 주석으로 남겼다. 시간은 B가 30% 더 걸렸다(테스트 실행 1회 추가).
사다리의 값어치는 과잉설계 유혹이 있는 과제(날짜 선택 UI, 캐시 계층, 재시도 래퍼)에서 나오므로, 그런 과제로 다시 재야 한다 — **미확정**.

## 권고

1. **ponytail 설치 후 1시드 재측정**: `/plugin marketplace add DietrichGebert/ponytail` → `/plugin install ponytail@ponytail` 뒤 S4를 다시 돌려 GATE·judge가 짧은 쪽을 선호하는지 본다.
   기울면 `PONYTAIL_SUBAGENT_MATCHER`로 코딩 에이전트에만 주입.
2. **ecc 업데이트 후 라우팅 재검사**: 설치본 1.10.0(2026-04)은 마켓 HEAD보다 5개월 뒤처져 있다. 업데이트하면 `python _tools/skill_catalog.py`가 이름 변경·삭제를 종료코드 1로 알린다.
3. **컨텍스트 다이어트(사용자 결정)**: 안 쓰는 ecc 도메인 스킬(의료·물류·암호화폐·SNS·투자·에너지 등)을 `skillOverrides`로 끄면 항상-로드 비용이 줄어든다. 설정 변경이라 자동으로 하지 않았다.
4. **세션 메모리는 catch-up 하나만**: `ecc:ck`를 함께 켜지 않는다(SessionStart 이중 주입).
5. **실행가능성 보강은 다음 버전 후보**: A3 UI 방향에 화면 스케치 1개, A7에 디렉터리 구조·`.env.example` 스케치. 근거는 S1 judge 양쪽의 같은 지적. 넣기 전에 스모크 재실행.
6. **코드 사다리 효과는 과잉설계 유혹이 있는 과제로 재측정**: 날짜 선택 UI, 캐시 계층, 재시도 래퍼 같은 과제 3개 × n=2. 이미 최소인 과제로는 아무것도 못 잰다.
