# 서버팩 자료 — 팩마다 무엇이 들었고 무엇을 믿을 수 있나

- 기준일: 2026-09-12
- 만드는 법: `python3 scripts/build-server-pack-data.py` → `build-server-pack-quests.py` → `build-server-pack-vault.py` → `build-server-pack-graph.py`
- 명령표(선택): `python3 scripts/extract-script-commands.py <서버.exe> <팩이름>` — exe 는 저장소 밖에 둔다
- 단일 출처: `data/server-packs/extracted/<팩>/*.json` (커밋됨) · 노트와 그래프는 거기서 나므로 커밋하지 않는다

원작 자료(`docs/game-data.md`)와는 **다른 것**이다. 그쪽은 원작이 배포한 표이고,
이쪽은 남이 원작을 고쳐 돌리던 서버의 데이터베이스다. 섞지 않는다.

---

## 1. 팩마다 따로 두는 이유

| 갈래 | 5.99 | 혼든 | 겹침 | 5.99에만 | 혼든에만 |
|---|---|---|---|---|---|
| 아이템 | 989 | 3,138 | 449 | 540 | 2,689 |
| 괴물 | 242 | 821 | **35** | 207 | 786 |
| 맵 | 804 | 1,711 | 264 | 540 | 1,447 |
| 기술 | 82 | 184 | 58 | 24 | 126 |
| 마법 | 71 | 167 | 48 | 23 | 119 |

괴물은 242종과 821종인데 이름이 겹치는 것이 **35종뿐**이다. 같은 계열이라고 묶으면
어느 쪽 수치인지 알 수 없게 된다. 그래서 JSON·vault·그래프를 팩마다 하나씩 만든다.

`5.99-client` 에는 `db/` 가 없다 — 클라이언트 설정(`.cfg`)뿐이라 여기 대상이 아니다.

## 2. 매니페스트가 정답지다

`db/` 아래 `*_db.txt` 는 서버가 **무엇을 어떤 갈래로 읽을지** 직접 적어 둔 목록이다.

```
npc:db/npc/npc.txt
shop:db/npc/shop.txt
spawn:db/npc/시장_spawn.txt
```

파일 이름으로 짐작하면 틀린다. 같은 "NPC 배치"가 5.99 에선 `Spawn.txt` 이고 혼든에선
`노점_spawn.txt`·`시장_spawn.txt`·`마이소시아/아벨마을_spawn.txt` 다. 처음에 이름으로
찾다가 혼든의 NPC 배치 517개와 기술 184개를 통째로 놓쳤다.

### 선언되지 않은 파일은 서버가 읽지 않는다

디스크에 있어도 매니페스트가 가리키지 않으면 그 파일은 죽어 있다. 그 목록은
`extracted/<팩>/매니페스트에없는파일.json` 에 남겼다 (5.99 36개 · 혼든 44개).

**5.99 에서 이게 크게 걸린다.** `warp/` 에 워프 파일이 17개 있는데 `warp_db.txt` 는
10개만 선언한다. 드라큐라백작의성(212줄)·메카닉(135줄)·수오미(80줄)·크리스마스·
카스마넘·베크나탑·루어스의 워프 **566줄이 안 읽힌다**. 그래서 5.99 는 맵 838개 중
워프로 이어진 것이 303개뿐이다(혼든은 1,817개 중 1,733개). 팩에 남은 흔적일 뿐
그 서버에서 실제로 갈 수 있던 곳은 아니었다는 뜻이다.

## 3. 간선은 자료 안에 이미 있다

짐작할 것이 없다. 다섯 가지가 대상을 이름으로 직접 부른다.

| 간선 | 어디서 | 5.99 | 혼든 |
|---|---|---|---|
| 맵 ─워프→ 맵 | `warp/*.txt` 의 `0,출발맵,x,y,도착맵,x,y` | 198 | 1,821 |
| 맵 ─산다→ 괴물 | `mob/**/*_Spawn.txt` 의 `맵,괴물,마리수` | 570 | 3,658 |
| 맵 ─선다→ NPC | `npc/**/*spawn*.txt` | 156 | 517 |
| 상점 ─판다→ 아이템 | `npc/shop.txt` 의 `추가<TAB>아이템` | 509 | 1,884 |
| 스크립트 ─부른다→ 맵·아이템·괴물 | 본문의 `warp "..."`, `item_add "..."` | 298 | 1,483 |
| 맵 ─함정→ 스크립트 | `Trap_db.txt` | — | 30 |

## 3.5 퀘스트는 표가 아니라 스크립트에 있다

`db/` 어디에도 퀘스트 표가 없다. 퀘스트는 스크립트 안에 있고, 생김새가 일정하다.

```
if(@npc$=="구피"){                                    ← 누가 주나
  if(get_level(@myid)>=41){                           ← 조건
    if(#EestQuest014==1){                             ← 지금 단계
      if(item_exist(@myid,"고블린의조악한무기")>=6){     ← 가져오라는 것
        item_del "고블린의조악한무기", 6;                ← 거두어 간다
        set #EestQuest014, 2;                         ← 다음 단계
```

`#` 로 시작하는 변수는 캐릭터에 남는 값이다. **변수 하나가 퀘스트 하나**이고 정수값이
단계다. 그래서 변수로 모으면 퀘스트가 그대로 나온다. `대평원던전퀘스트` 는 `0→1→2→…→12`
열두 단계가 한 줄로 이어진다.

| | 5.99 | 혼든 |
|---|---|---|
| 영속변수 | 60종 | 255종 |
| 그중 단계가 둘 이상 | 17 | 112 |
| 그중 NPC·보상·요구가 붙은 것 | 3 | 52 |
| 이벤트 묶음 | **0** | 7묶음 · 아이템 528 |

**이름을 짓지 않았다.** 자료에 사람이 읽을 퀘스트 이름이 없다. `EestQuest014` 가
그 퀘스트의 이름 그대로다. 단계의 뜻(무엇을 해야 넘어가나)도 적지 않았다 — 대사에서
읽히기는 하지만 확인된 것이 아니다. 노트에는 대사 앞 여섯 줄을 그대로 붙였다.

**5.99 에는 이벤트가 없다.** `item/Event/` 가 아예 없다. `item/Cash/` 가 있지만 그건
캐시상점이지 이벤트가 아니라서 이벤트로 세지 않았다.

### 여기서 더 늘어난 간선

| 간선 | 어디서 | 5.99 | 혼든 |
|---|---|---|---|
| NPC ─준다→ 퀘스트 | 본문의 `@npc$=="…"`, 또는 스크립트 이름이 NPC 이름과 같을 때 | 6 | 85 |
| 퀘스트 ─가져오라/거둔다/보상→ 아이템 | `item_exist` · `item_del` · `item_add` | 12 | 640 |
| 이벤트 ─묶음→ 아이템 | `item/Event/<묶음>/` | 0 | 528 |

## 3.6 스크립트를 실행하는 로직은 실행파일 안에 있다

`item_add "…",1` 이 무엇을 하고 인자를 몇 개 받는지는 db 어디에도 없다. 뜻은 서버가 쥐고 있다.
`sources/` 의 저장소 16개에는 없다 — 거기서 `item_add`·`get_myid`·`buildin_` 을 찾으면 0건이다.
그쪽은 Dark Ages(미국) 계열이라 혈통이 다르다. 소스도 없다. 팩에 든 것은 PE 실행파일뿐이다.

길은 혼든의 `Trap_db.txt` 주석이 알려 준다.

```
//{ buildin_trap_set, "trap_set", "siisiii" },  // 맵이름, x, y, 스크립트이름, 써클, 이펙트, 지속시간
```

**eAthena 계열 스크립트 엔진의 함수 등록표 생김새다.** 그 표는 컴파일된 뒤에도
`{ 함수포인터, 이름, 인자서명 }` 12바이트 한 칸으로 `.rdata` 에 남는다. PE 를 열어
`.text` 를 가리키는 포인터 + 식별자 꼴 이름 + 서명 꼴 문자열이 나란한 자리를 찾으면
명령표가 통째로 나온다 (`scripts/extract-script-commands.py`). `i`=정수, `s`=문자열.

| | 5.99 (`Novaonline.exe`) | 혼든 (`Yuki.exe`) |
|---|---|---|
| 엔진이 가진 명령 | 401 | 500 |
| 그중 이 팩이 쓰는 것 | 262 | 292 |

뽑은 것이 맞는지는 자료가 스스로 확인해 준다. `trap_set` 의 서명이 `siisiii` 로 나오는데,
이는 위 주석에 적힌 것과 **글자 하나까지 같다**. `item_add`→`si`, `item_exist`→`is`,
`warp`→`sii`, `mes`→`is` 도 스크립트에서 쓰이는 모양 그대로다.

### 두 팩은 엔진부터 다르다

`last_npc` 와 `rand2` 는 **`Novaonline.exe` 에 아예 없다**(문자열조차 없다. Nova 에는 `rand` 만 있다).
그래서 5.99 의 스크립트는 `@npc$=="…"` 로 상대를 확인하는 일이 한 번도 없다 —
쓸 수가 없기 때문이다. 대신 스크립트 이름 자체가 NPC 이름이다. 앞 절에서 5.99 의
퀘스트-NPC 를 이름이 같을 때만 이은 것은 이 때문이다.

### 스크립트가 부르는 이름은 전부 설명된다

`scripts/classify-script-names.py` 가 증거로만 갈라 본 결과다.

| | 5.99 | 혼든 |
|---|---|---|
| 스크립트가 부르는 이름 | 262 | 286 |
| 엔진 명령 | 257 | 281 |
| 제어문 (`if`·`else`·`for`·`while`·`switch`) | 5 | 5 |
| **설명 안 되는 것** | **0** | **0** |

처음 세었을 때는 5.99 가 93개, 혼든이 185개였다. 전부 내 정규식 잘못이었다.

- `if(@type1 == 3)` 의 `@type1` 은 지역변수인데 명령으로 잡혔다. `@`·`#` 접두를 빼야 한다.
- 대사 안의 말이 코드로 잡혔다. 문자열을 먼저 걷어내야 한다.
- 막아 둔 줄이 살아 있는 코드로 잡혔다. `//` 와 `/* */` 도 걷어내야 한다.
  5.99 의 `공통스킬.txt` 86줄에 `//set @mapxs, get_mapxx()-1;` 이 있는데,
  `get_mapxx` 는 **어느 팩 실행파일에도 없다**. 없는 명령이라 막아 둔 것으로 보이지만
  확인된 것은 아니다.

갈래는 짐작이 아니라 증거로 정한다: `@name` 이 있으면 지역변수, `#name` 이면 영속변수,
줄머리 `name:` 이면 라벨, 명령표에 있으면 엔진 명령이다. 어느 증거도 없으면
`가려내지못함` 에 남긴다 — 지금은 양쪽 다 비어 있다.

### 엔진에는 있는데 팩이 안 쓰는 명령

5.99 는 144개, 혼든은 219개다 (`script-names.json` 의 `엔진이가졌지만안쓰는명령`).
`disconnect`·`console_output`·`door_parse` 같은 것들이다. 엔진이 할 수 있는데 이 팩이
그 기능을 안 쓴다는 뜻이지, 명령이 망가졌다는 뜻은 아니다.

### 기계어에서 기계적으로 붙인 증거 (5.99 만)

401개를 손으로 읽는 것은 현실적이지 않다. 대신 **사람 손을 타지 않는 사실만** 전부에 붙였다
(`scripts/disasm-script-commands.py`, capstone + pefile). 명령마다 함수를 따라가며 갈래를
양쪽 다 밟고 `ret` 에서 멈춘 뒤, 참조하는 문자열 · 부르는 함수 · 읽고 쓰는 구조체 오프셋을 적는다.

| | 5.99 (`Novaonline.exe`) |
|---|---|
| 뜯은 명령 | 401 |
| 문자열을 참조하는 것 | 71 |
| 구조체에 쓰는 것 | 156 |
| 갈래를 가르는 helper | 44 |
| 증거가 하나도 안 붙은 것 | 114 |

**문자열이 가장 크게 말한다.** 오류 메시지가 같으면 하는 일이 닮았다.

| 문자열 | 명령 |
|---|---|
| `이미 걸려있습니다.` | 20개 — `belra` `colama` `dell` `enare` `defens` `antimagic` `hide` `immortal` … |
| `buildin_skill_exist: invalid name!` | `skill_add` `skill_add2` `skill_del` `skill_del2` `skill_exist` |
| `buildin_item_add: invalid name!` | `item_add` `group_item_add` |
| `%s: %s` | `mob_say` `mob_say2` `pet_say` `user_say` |
| `몸이 얼어 움직일수 없습니다.` | `item_pickup` `mobsor_delay` `mobsor_delay2` |
| `잠이 쏟아져 옵니다.` | `item_pickup` `mobnar_delay` `mobnar_delay2` |

첫 줄의 20개는 이름이 원작 마법 그대로다(벨라·코마·델·에나레). 같은 "이미 걸려있습니다" 를
내는 것으로 보아 **상태를 거는 계열이 한 무리**라는 것까지는 자료가 말해 준다.

`buildin_del: invalid name` 처럼 함수 이름이 오류 문자열에 그대로 박힌 것도 있다 —
eAthena 혈통이 여기서 또 확인된다.

**구조체 오프셋도 무리를 만든다.** 같은 자리에 쓰는 것끼리 묶인다.

| 쓰는 자리 | 명령 |
|---|---|
| `+0xCC` | `get_hp_add` `set_hp_add` `set_vita` `set_vital` `group_hill` |
| `+0xF0` | `char_disguise` `hide` `pet_rescue` `set_state` `set_state1` |
| `+0xE0` | `money_add` |

다섯이 모두 `+0xCC` 에 쓴다는 것은 사실이다. **그 자리가 체력이라는 것은 코드가 말해 주지 않는다** —
이름에서 그렇게 읽힐 뿐이다. 그래서 표에는 자리만 적었다.

### 여기서 멈춘 곳

**각 명령이 무엇을 하는지는 여전히 적지 않았다.** 위 증거는 "이 함수가 0x10150 에 더한다",
"이 함수가 `이미 걸려있습니다` 를 참조한다" 까지다. 0xCC 가 체력인지, `belra` 가 무엇을 거는
마법인지는 다음 사람이 판단할 몫이다. 짐작을 적으면 그것이 근거로 둔갑한다.

증거가 하나도 안 붙은 명령이 114개 남았다. 문자열도 안 쓰고 갈래를 가르는 helper 도
안 부르는 짧은 함수들이다 — 더 알려면 그 114개는 손으로 읽어야 한다.

혼든(`Yuki.exe`, 500개)은 아직 안 했다. 같은 명령으로 팩 이름만 바꾸면 된다.

## 4. 믿을 수 있는 만큼만

- **칸 이름은 원본 그대로다.** `내구력`·`방어력`·`콘변화` 는 db 에 그렇게 적혀 있다.
  뜻을 짐작해 붙인 이름은 없다. 확인 못 한 칸은 `fields` 에 원문대로 남겼다.
- **불렸는데 정의가 없는 이름이 있다.** 워프가 가리키는데 정의가 없는 맵, `spawn` 에만
  있고 `npc` 에 없는 NPC 같은 것이다(5.99 140개 · 혼든 180개). 숨기지 않고 vault 에
  `정의없음: true` 쪽지로 남겼다. 빠진 자료인지 오타인지는 **확인되지 않았다**.
- **퀘스트는 중괄호 깊이로 귀속한다.** 어떤 보상이 어느 퀘스트 것인지는 그 `set #변수`
  가 어느 `if(#변수==n)` 안에 있는지로 정한다. 깊이를 셀 때 **문자열 안의 중괄호는 빼야
  한다** — 대사에 색상 코드가 박혀 있다(`mes 1,"...{=q강력한 {=a이란..."`). 이걸 그냥
  세면 깊이가 어긋나고, 한번 어긋나면 조건이 파일 끝까지 쌓여 엉뚱한 퀘스트에 보상 46종이
  붙는다. 처음에 실제로 그렇게 나왔다.
- **단계로 읽을 수 없는 값이 있다.** `set #EestQuest006B, localtime(3)` 처럼 정수가 아닌
  값을 넣는 변수가 있다(일일 초기화로 보이지만 확인되지 않았다). 버리지 않고 노트에
  `정수가 아닌 값` 으로 적어 뒀다.
- **아이템 대부분은 아무 데도 안 이어져 있다.** 상점에도 없고 스크립트도 안 부른다
  (5.99 는 노드 2,695개 중 1,540개가 홀로 떠 있다). 그래프 그림에는 이어진 것만 그리지만
  `graph.json` 에는 전부 남아 있다.

## 6. graphify 에 LLM 을 쓰지 않는 이유

graphify 는 `.txt` 를 산문으로 보고 LLM 서브에이전트로 뜻을 뽑는다. 그런데 `db/` 는
산문이 아니라 정확한 표다. 표에 LLM 을 돌리면 값이 크게 들고 결과는 파싱보다 **부정확**하다.
그래서 뽑는 일은 `build-server-pack-graph.py` 가 정확히 하고, graphify 에는 그 결과를
그대로 넘긴다 — 군집 찾기·중심 노드·HTML 만 맡긴다. 토큰은 0 이다.

## 7. 함정

- **macOS 는 파일이름의 대소문자를 구분하지 않는다.** 혼든에는 `루어스은행A` 와
  `루어스은행a` 가 둘 다 있다 — 서로 다른 맵이다. 그냥 쓰면 한 장이 다른 한 장을
  덮어써 조용히 사라진다. vault 는 겹치면 뒤에 `~2` 를 붙이고, 빌드 때 자기 출력
  폴더를 먼저 비운다(대소문자는 보존만 되어 옛 이름이 남기 때문).
- **원본은 CP949 다.** 서버를 실제로 돌릴 때는 여기 것이 아니라 원본 zip 을 쓴다
  (`data/server-packs/README.md`).
