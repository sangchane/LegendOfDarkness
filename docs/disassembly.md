# 역어셈블 — 5.99 서버·클라이언트 실행 파일에서 읽은 것

팩 자료(`docs/server-pack-data.md`)는 **값**을 준다. 그 값을 **어떻게 쓰는지**(식·판정·그리는 순서)는
실행 파일 안에만 있다. 공격력 식, 평타 몸 동작, 장착 규칙, 장비를 겹치는 순서가 모두 그렇게 나왔다.

- **단일 출처:** `data/disassembly/findings.json` — 함수·칸(오프셋)·표·패킷·규칙·비교. **규칙마다 근거 주소**가 붙어 있다
- **근거 발췌:** `data/disassembly/excerpts/*.asm` — 규칙을 증명하는 몇십 줄씩(전체 역어셈블은 커밋하지 않는다)
- **그래프:** `data/disassembly/graph/` (커밋하지 않음 — 아래 명령으로 다시 만든다)

## 실행 파일

| 것 | 경로(저장소 밖) | 크기 · md5 |
|---|---|---|
| 5.99 서버 | `~/Downloads/5.99 서버팩/Novaonline.exe` | 614,400 · `d36015ac…aa71` |
| 5.99 한국 클라이언트 | `~/Downloads/5.99 클라이언트/Legend.exe` | 3,555,391 · `347dc381…d128` |

둘 다 32비트 PE(i386)다. 우리 5.99 클라이언트는 **원작과 다른 곳이 있다** — 무기 27개 번호의 그림이
다른 무기로 바뀌어 있었다(아래 비교). 원작 실행 파일과 대조하면 어느 쪽 규칙인지 가를 수 있다.

## 읽는 법

```bash
objdump -d --x86-asm-syntax=intel Novaonline.exe > nova.asm     # 맥 기본 objdump
```

- **오프셋은 10진수로 나온다** — `[ecx + 376]` 은 `+0x178`, `[eax + 27]` 은 `+0x1B`.
- **문자열 주소**(`push 4754284`)는 PE 섹션 표로 파일 위치를 구해 **CP949** 로 읽는다.
  Legend.exe: `.text 0x427000` · `.rdata 0x680000` · `.data 0x686000(파일 0x286000)` · `.data1 0x846000(파일 0x2c4000)`.
- **칸 뜻은 읽는 쪽과 쓰는 쪽을 맞춰 푼다.** 스크립트 명령 401개가 읽고 쓰는 칸은
  `data/server-packs/extracted/5.99-server/script-command-evidence.json`(`scripts/disasm-script-commands.py`)에 있다 —
  `sosusin` 이 `+0x7C` 를 쓰고 능력치 재계산이 그 칸으로 공격력을 +40% 한다, 식으로 이어진다.
- 서버 아이템 칸과 캐릭터 칸은 같은 오프셋이 다른 뜻이다(`item+0x1B` 공격모션 ≠ 캐릭터 `+0x1B`). 구조체를 헷갈리지 않는다.

### 실행 파일과 아카이브를 맞대어 알게 된 것

- **무기 그림 27개 번호가 다르다** — 5.99 팩 아이템 이름에는 하데스(영문) 그림이 맞다: 3 커틀라스=칼, 6 단검 4종=단검(5.99 쪽은 가시 곤봉),
  7·8 지팡이, 11 매스케이드=Masquerade. 옷장 생성기는 무기·무기 앞 조각만 하데스 아카이브 우선이다.
- **바탕** — 무기·장신구·무기 앞 조각은 111×85, 나머지는 57×85(참고 클라이언트 아틀라스 · `mp127` 칸 위치 = `mw127`).
- **EPF 빈 칸도 번호를 차지한다** — 단검 `mw028e` 는 2·7번이 비었다. 버리면 뒤 칸이 당겨진다.
- **`skill.tbl`** 은 두 클라이언트가 18줄 모두 같다. 갑옷·바지는 파일이 달라도 같은 옷을 다시 그린 것이다.

### 받은 동작을 바꾸나 — 작업지시서 3번

- **서버가 보낸 번호를 그대로 그리지 않는다**(4.51 `0x449300`, 2005 `0x4e1020` 같은 규칙). 1 → 02 파일(평타) · 6 → 03 파일 ·
  21·22 → 03 파일의 다른 구간 · 9~17·23~33 → 앞모습일 때만 감정 말풍선 · 나머지 작은 번호는 무시.
- **기술 동작(0x80+n)은 입은 갑옷 번호가 `Skill.tbl` n 줄의 ST 목록에 있을 때만 재생한다.** 없으면 **아무 동작도 안 한다** —
  평타 동작으로 바꾸지도 않는다. 방패·무기·직업은 보지 않는다. ("방패를 끼면 기본 동작"은 클라이언트에도 없다.)
- 2005 판은 사람이 괴물 모습(`[+0x369]==0`)이면 동작을 `0x4e1314` 로 따로 보낸다. 4.51 에는 없다.
- **옮겼다(2026-09-17):** `BodyMotion.Fits` 가 원작 2005 `skill.tbl`(알맹이에 내장)의 ST 로 거르고, `WorldView.Swings` 가
  옷이 맞지 않는 기술 동작을 그리지 않는다. 동작 중에 온 새 동작도 원작처럼 무시한다(`Actor.Play`, 2005 `0x4e1130`).
  하데스 `skill.tbl` 사본은 줄마다 끝 번호 하나(348~352)가 더 있어 쓰지 않는다.
- **동작 6·21·22 도 옮겼다:** 2005 `0x4e3657` 의 초기값과 `0x4e2383`~`0x4e2526` 의 칸 고르기 — `시작 + (칸 수 − 1) × 앞뒤 + 걸음 − 1`
  (저장된 칸 수는 그림 수 + 1). 6 손 들기 `03` 0 | 1 · 21 키스 2–3 | 4–5 · 22 손 흔들기 6–7 | 8–9, 22 만 속도 ÷3(`BodyMotion.Of`).
  발췌 `original-2005-motion-frames-4e3657.asm` · `original-2005-emote-4e1226.asm`.
- **감정표현도 옮겼다:** 표 `0x869880`(한 줄 64바이트 — 번호·첫 칸·칸 수·칸마다 ms·채팅 글)을 `0x4e1226` 이 앞 줄들을 더해 찾는다.
  앞모습이고 하던 일이 없을 때만(`0x4e1104`). 그림 `emot01.epf`, 첫 H 앞에 그린다(`0x4e7ca7`). 9~15 → 칸 0~6 … 44 → 38~41
  (`Emote.Of`, `docs/original-sprite-animation.md` 3.5절). 발췌 `original-2005-emote-4e1226.asm`.
- **이펙트 칸 순서도 옮겼다:** `effects.txt` 에 `effect.tbl` 순서를 적고 `EffectSheet`·`Flash` 가 그대로 튼다(속도는 한 칸 간격).

### 아카이브를 맞대어 알게 된 것

- **원작 2005 `khan.dat` 의 무기 200 번호 중 197 개가 하데스 `game/khan.dat` 와 바이트까지 같다**(다른 것 200·201·202).
  3·6·7·8·11 도 같다 — 위에서 본 "무기 그림 27개가 다르다"는 **5.99 팩이 `khan.dat` 를 바꾼 것**이다. 옷장 생성기가 무기를 하데스 우선으로 둔 것이 맞았다.
- 4.51 `khan.dat` 무기는 130 번호, 그중 12 개가 하데스와 다르다(초기 그림).
- `Skill.tbl` 은 4.51 이 0~8 줄(직업 5), 2005 는 2차 직업 줄이 늘었다. 0~8 줄의 NO·FN·SI·FC 는 같다.
- 4.51 아카이브는 `Legend.dat`·`khan.dat`·`seo.dat` 셋이고 이펙트 표가 `Legend.dat` 에 있다. 2005 는 `roh.dat` 로 옮겨졌다.

## 그래프 다시 만들기

```bash
~/.local/share/uv/tools/graphifyy/bin/python scripts/build-disassembly-graph.py
```

노드(실행파일·함수·칸·표·패킷·규칙·비교·구현·명령·발췌)와 간선(들어있다·근거·읽는다·쓴다·만든다·보낸다·부른다·옮겼다)은
`findings.json` 이 그대로 정한다 — LLM 으로 뽑지 않는다. 결과: `data/disassembly/graph/graph.html` · `GRAPH_REPORT.md`.

윈도우에서는 `python scripts/build-disassembly-graph.py` 로 바로 된다(graphify 파이썬을 스스로 찾는다).

**그래프에 묻기** — 기본 그래프는 저장소 전체 코드라 `--graph` 로 이 그래프를 가리킨다:

```bash
graphify query "기술 동작 갑옷 Skill.tbl" --graph data/disassembly/graph/graph.json --budget 800
```

`python3 scripts/…` 로 돌리면 맥에서 "graphify Python cannot import graphify" 로 멈춘다 — `graphify_runtime` 이 uv 도구의
`python` 심볼릭 링크를 끝까지 따라가 venv 를 잃는다(서버팩 그래프도 같다). 위처럼 graphify 파이썬으로 바로 돌린다.

새로 알게 된 것은 `findings.json` 에 **주소와 함께** 더하고 그래프를 다시 만든다. 발췌는 규칙을 증명하는 몇십 줄만 넣는다.
