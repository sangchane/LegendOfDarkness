## 2. 막혀 있던 까닭 — 들어가는 길이 없었다

- 5.99 원본 `db/warp/Suomi_Warp.txt` 에 **수오미마을 (99,24~27) → 1존 (33,47)**, 1존 ↔ 2존 ↔ 3존 ↔ 4존 ↔ 5존·6존 워프 37줄이 있다
  (레벨 21~51, 나오는 길은 0~99).
- 그런데 5.99 의 워프 목록 `db/warp/warp_db.txt` 가 이 파일을 **싣지 않는다** — 5.99 서버에서도 포테의숲에 갈 수 없었다.
  같은 이유로 `Baeqnatop`·`Casmanum`·`Christmas`·`DraculaCastle`·`Mechanic`·`Roues` 워프 파일도 빠져 있다
  (`data/server-packs/extracted/5.99-server/매니페스트에없는파일.json`). 추출 자료 `warps.json` 에도 없어서 서버에 워프가 안 들어왔다.
- **Novaonline 팩은 같은 맵 파일(`lod6613`…`lod6620`)을 같은 연결로 싣는다** — 수오미마을 → 1존 → … → 5존·6존. 혼든 팩은 다른 판이다
  (피에트마을 → 대기실 → L·C·R 갈래 4층, 맵 파일 `lod4600~4611`).
- 5.99 `script/script.txt` 에 주석으로 남은 말: "레벨 21 … 노비스를 졸업 … 이제부터는 수오미마을과 포테의숲에서 활동" — 노비스 사냥터
  (레벨 1~22) 다음 단계로 만들어 둔 곳이다.

## 3. 어떻게 넣었나

1. **워프** — `python3 tools/pack-import/import.py --kind suomiwarps --write`: 5.99 가 목록에서 뺀 `Suomi_Warp.txt` 80줄(포테의숲 37 · 수오미 건물 문 43).
   워프 줄 끝 두 칸의 레벨 범위는 **노비스·수오미 파일에만** 옮긴다(`LEVEL_RANGE_SOURCES`) — 다른 파일까지 쓰면 아벨 130장이 51~80,
   밀레스·VOD·광산 등 137장이 99레벨 전용이 된다(결정 필요 시 사용자에게). 서버 워프에 `LevelMaximum` 을 새로 두었고 거절 문구는 5.99 서버
   (`Novaonline.exe` 0x904b0) 그대로 — "아직 들어가기엔 레벨이 낮습니다." · "이곳에 들어가기엔 늙었습니다."
2. **개인 던전(보스존)** — 5.99 `포테의숲오솔길입장`(Npc_Warp.txt)을 그대로 돌린다.
   - 5존 26·27,0 은 **밟으면 스크립트가 도는 워프**(Warp_script.txt 종류 3 → 서버 `WarpTemplate.ScriptNpc`). 창을 띄울 NPC 는 옆 칸 28,0 에
     세웠다(그림 없는 스크립트 NPC — 모바일은 표식). `import.py --kind potedungeon`.
   - `map_create` → 서버 `Systems/Instances`: 원래 맵(숲오솔길 20194 · 대기실 20195 · 보스존 20269)을 캐릭터 이름이 붙은 새 번호(60000~)로 한 벌 더 짓는다.
     클라이언트에는 원래 맵 번호와 5.99 가 보여 주는 이름을 알린다(`Area.ClientNumber`·`ClientName`) — 모바일은 원래 맵 그림을 그대로 쓴다.
     팩 맵 파일 → 서버 맵 번호 표는 `import.py --kind mapfiles` → `static/pack599-mapfiles.tsv`.
   - `warp_create`(끝 칸 1 = 괴물을 다 잡아야 지나감 → `WarpTemplate.RequiresClear`) · `group_warp` · `mob_spawn3` · `mob_clear` · `item_clear` ·
     `get_map_stage`·`get_map_sub_stage`·`map_objmob`·`get_clear_time`·`get_kill_mob`·`exp_add` 를 `Pack599.cs` 에 넣었다.
   - `mob_spawn3 괴물, 맵, 최소공격력, 최대공격력, 체력, 마릿수` — 셋째 수는 체력으로 읽었다(튜토리얼 팜팻 `1, 2` 가 정의의 공격력과 같다). 하데스
     괴물 피해는 식이 정하므로 공격력 둘은 쓰지 않는다. 사본 전용 괴물 사나운은빛늑대·자이언트맨티스는 `AreaID 0` 템플릿(젠 관리자가 안 세움) —
     `import.py --kind potedungeon`. 보스에는 `Monster_리베라토`, 늑대의 `Monster_아듀로` 는 정의가 없어 못 붙였다.
   - 1초마다 도는 `script/Dungeon.txt`(`Dungeon__Script`)를 `build-pack-npcs.py` 가 옮기고(서버 `PackRoutine`) 사본에 붙인다 — 오솔길의 마비 함정
     (걸으면 1/5 로 12초, 엔트자이언트의날개가 있으면 대신 하나), 보스방 클리어.
   - 사본은 사람이 들어왔다 나간 뒤 1분, 한 번도 안 들어간 방은 30분 뒤 없앤다(한꺼번에 지은 보스방이 오솔길을 걷는 사이 사라지던 것을 막음).
     서버가 다시 켜져 사라진 사본에 저장된 캐릭터는 시작 자리로 들어온다(전에는 로그인이 막혔다).
   - 맵별 객체 목록은 서버 시작 때만 만들어져 새 맵에 넣는 것이 말없이 버려졌다 — `ObjectService.AddMap`·`RemoveMap`.
3. **모바일 맵 재료** — `scripts/build-client-maps.py` 기본 목록에 1~6존 · 보스존 · 숲오솔길 · 대기실 · 수오미마을 · 수오미 건물 8.
4. **오솔길 함정 = 혼수** (2026-09-18, 5.99 서버 역어셈블 — `docs/disassembly.md` 혼수). 오솔길에서 움직이면 1초마다 1/5 로 12초 혼수에 빠진다
   (`set_coma` · `set_state 1,1` · `coma_delay 12`, 엔트자이언트의날개가 있으면 대신 하나). 누가 코마디움·코마디아로 살리지 않으면 죽는다(`__COMA_END__`).
   5.99 혼수는 하데스 빈사 디버프(아이콘 89 · 그림 24, 끝나면 죽음)와 같아 그것을 건다 — `PoteDungeonTests.Walking_the_trail_without_a_wing…`.
   죽은 뒤는 하데스 죽음 흐름(유령)이다 — 5.99 는 뮤레칸의방(PK 맵은 빛의신전)으로 보낸다. 하데스 `del_coma` 가 빈사를 지우지 못하던 것도 고쳤다(코마디움).
5. **남은 것** — 수오미마을 NPC 대화 확인 · 그룹 입장(`group_warp` 은 같은 맵 그룹원을 함께 보내지만 그룹으로 시험하지 않았다) · 코마디움으로 살리기 시험.

**시험에서 알게 된 것**: 5존 엔트자이언트의 나르콜리에 잠들면 서버가 대화 대답을 받지 않는다(`IsSleeping`) — 5.99 대로의 동작이라 시험에서만 5존
괴물을 치웠다. 캐릭터 저장 파일의 체력을 100,000 으로 고치면 서버의 스레드 풀이 막혀 패킷이 처리되지 않았다(원인 미확인 — 20,000 은 괜찮음).
