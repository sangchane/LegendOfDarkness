# 역어셈블 작업지시서 — 원작 클라이언트 실행 파일

- 작성: 2026-09-17 (맥 세션)
- 받는 쪽: **원작 LOD 클라이언트 실행 파일이 있는 윈도우 PC 의 세션**
- 끝나면: 아래 브랜치로 **푸시**한다. 맥 세션이 받아 합친다.

## 1. 왜 하는가

5.99 한국 클라이언트(`Legend.exe`)와 5.99 서버(`Novaonline.exe`)를 역어셈블해서, 자료 파일에는 없는 규칙을
주소 근거와 함께 찾았다 — 사람 그림을 겹치는 순서, 파일 이름 짓는 법, 평타 몸 동작 고르는 법 등.
결과는 `docs/disassembly.md` · `data/disassembly/findings.json` 에 정리돼 있다(먼저 읽는다).

그런데 **우리가 가진 5.99 클라이언트는 원작과 다른 곳이 있다** — 무기 그림 27개 번호가 다른 무기로 바뀌어
있었다(6: 단검 → 가시 곤봉). 그래서 5.99 에서 찾은 규칙이 **원작 클라이언트에서도 같은지** 확인해야 한다.
원작 실행 파일은 윈도우 PC 에만 있다.

## 2. 도구 (윈도우)

- 역어셈블: LLVM `llvm-objdump -d --x86-asm-syntax=intel <exe>` (`winget install LLVM.LLVM`). 맥 세션과 같은
  출력이라 주소·오프셋을 그대로 견줄 수 있다. **오프셋은 10진수로 찍힌다**(`+ 152]` = 0x98).
- 문자열: `llvm-strings` 또는 파이썬으로 PE 섹션 표를 따라 파일 위치를 찾고 **CP949** 로 읽는다.
  `push 4784988` 같은 상수가 문자열 주소다.
- 필요하면 Ghidra(헤드리스)도 좋다. 결론에는 **주소와 짧은 어셈블리 인용**을 꼭 붙인다.
- 전체 역어셈블은 수 MB 라 **커밋하지 않는다.** 근거가 되는 짧은 발췌만 `data/disassembly/excerpts/` 에 둔다.

## 3. 할 일 (위에서부터)

각 항목마다 **5.99 `Legend.exe` 에서 찾은 값**(괄호)과 원작이 같은지·다른지를 적는다.

1. **사람 그림 겹치는 순서표** — 5.99: `0x69c200` 에 방향마다 15바이트, 부위 글자표 `"SBNLHUDHAWSCPEF"`
   (`0x86b614`). 뒷모습 `S B N L U D F W A H - E P S C`, 앞모습 `W F B N L H U D - A E P S C`.
   글자표 문자열부터 찾으면 가깝다. 원작의 순서가 같은지, 방향별로 무엇이 다른지.
2. **파일 이름 조립** — 5.99: `0x4e8514`. 성별 글자 `"MW"`, 방패·앞 방패는 늘 `M`, 겉모습 기록의 오프셋
   (S +28 · B +6 · N +14 · L +10 · H/E/F +2 · U +18 · D +20 · A +8 · W/P +22 · C +24), 접미사
   (`'a'+기술` 또는 `%02d.epf` 동작+1). 원작도 같은가.
3. **몸 동작(0x1A)을 받아 그리는 곳** — 서버가 보낸 동작 번호를 **그대로** 그리는가, 아니면 방패·옷(원작
   `skill.tbl` 의 ST 옷 목록)·무기에 따라 **바꿔** 그리는가. (사용자 기억: "방패를 끼면 기본 동작, 양의신권이면
   주먹" — 5.99 서버에는 그런 코드가 없었다. 클라이언트에 있는지가 남은 질문이다.) `skill.tbl` 을 읽는 코드와
   ST 칸을 쓰는 곳도 함께 본다.
4. **방패·감정표현 규칙** — 5.99: 뒤 방패는 방향 0·3 에서만(`0x4e7a0d`), 앞 방패는 1·2 에서만(`0x4e8430`),
   방패 번호 255 는 안 그림. 감정표현(동작 2)은 무기·P·방패를 뺀다(`0x4e78f4`).
5. **EPF 읽기와 위치** — 5.99: 프레임 수와 목차 위치만 읽고 머리말의 너비·높이는 안 읽는다(`0x4e8854`).
   `<이름>.tbl` 에서 프레임별 x/y 를 찾는다. 원작도 같은가. **무기·장신구를 111 폭 바탕 가운데에 맞추는 계산**
   (57 과 111, 또는 27 을 쓰는 곳)이 코드에 있는지.
6. **이펙트 재생** — `effect.tbl`(첫 줄 개수, `ID-1` 번째 줄이 프레임 순서)을 어디서 어떻게 쓰는지, 속도 값의
   뜻(한 칸 시간인지 전체 시간인지). 몸 동작 0x1A 의 속도 값 뜻도 함께.
7. (여유가 있으면) 괴물 그림(MPF) 읽기에서 빈 칸을 어떻게 세는지.

모르는 것은 **"확인 못 함"** 으로 적는다. 추측으로 채우지 않는다.

## 4. 결과를 어디에 어떤 모양으로

- `data/disassembly/findings.json` — 이미 있는 구조를 그대로 따른다. `binaries` 에 원작 실행 파일(파일 이름·크기·
  버전 문자열, **경로는 윈도우 경로 그대로 적되 파일은 올리지 않는다**)을 더하고, 규칙마다 원작 주소와
  "5.99 와 같음/다름" 을 적는다.
- `data/disassembly/excerpts/original-*.asm` — 근거 발췌(각 몇 KB).
- `docs/disassembly.md` — "원작 클라이언트" 절을 더한다. 표 한 장: 항목 · 5.99 주소 · 원작 주소 · 같음/다름 · 메모.
- 그래프를 다시 만든다: `scripts/build-disassembly-graph.py` 를 **graphify 가 깔린 파이썬으로** 돌린다(명령은 `docs/disassembly.md` 의 그래프 절). 그래프 산출물(`data/disassembly/graph/`)은 커밋하지 않는다.
- `WORKLOG.md` 맨 위 History 에 한 줄 요약.

## 5. 지킬 것

- **실행 파일(.exe)·아카이브(.dat)는 절대 커밋하지 않는다.**
- 브랜치: `docs/disassembly-original-client` (지금 브랜치 `test/hades-characterization` 에서 딴다).
- `git add` 는 경로를 적어서 한다(폴더째 담지 않는다). `git status` 는 `--ignore-submodules=all`.
- `sources/` 아래 원본 저장소는 건드리지 않는다. 비밀값 파일 규칙(`AGENTS.md`)을 지킨다.
- 커밋 메시지는 Conventional Commits, 한국어 본문.
- 끝나면 `git push -u origin docs/disassembly-original-client`.
