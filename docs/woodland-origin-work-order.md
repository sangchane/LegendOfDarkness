# 작업지시서 — 원작 우드랜드 확인 (맵 파일 출처와 월드맵 입구)

- 작성: 2026-09-17 (맥 세션)
- 받는 쪽: **원작 설치본(`lodr.exe` 2005 · `lodr4.51.exe` 2001)과 Novaonline 원본 팩이 있는 윈도우 PC 의 세션**
- 끝나면: 브랜치 `docs/woodland-origin` 으로 **푸시**한다. 맥 세션이 받아 합친다.

## 1. 왜 하는가

사용자: "지금 우드랜드는 내가 알던 버전이 아니던데". 맞다 — 서버에 들어간 것은 **5.99 팩의 "우드랜드" 14개 맵**이다.

- 원작 클라이언트 월드맵 표(`Legend.dat` 의 `field001.txt`)에는 **동의·서의·남의·북의 우드랜드** 네 곳이 있다
  (`동의우드랜드 f003 516 176 EX 443 140 22` 따위 — `data/archives-vault/표/Legend — field001.txt.md`).
- 5.99 판은 이름부터 다르고(`우드랜드1-1` …), 맵 파일 하나(`lod703`)를 세 맵이 나눠 쓴다. 팩이 새로 만든 판으로 보인다.
- **혼든 팩**은 `동의우드랜드입구` + `1-1 ~ 20-1`(맵 파일 `lod600~623`, 워프 57개가 사슬로 이어짐),
  **Novaonline 팩**은 동의·북의·(이름 없는) 우드랜드를 각각 입구 + `1-1 ~ 20-1` 로 갖되 아래층을 대기실 하나에 모았다.
  두 팩이 같은 연결은 8개뿐이라 "세 팩이 일치할 때만" 규칙(`AGENTS.md`)으로는 정할 수 없다.

사용자 결정: **원작 확인부터**. 어느 팩의 맵이 원작 파일과 같은지 가려야 어느 팩을 기준으로 옮길지 정한다.
**맵 사이 연결(워프)은 서버 자료라 클라이언트에 없다** — 여기서 가리는 것은 맵 파일과 월드맵 입구뿐이다.

## 2. 비교할 자료

- 맥에서 뽑아 둔 것: `data/map-origins/woodland-candidates.json` — 혼든 28 · 5.99 14 맵의 이름·번호·크기·맵파일·md5.
  (예: 혼든 `동의우드랜드입구` = `lod600.map` md5 `0df8aa89…`. 미국판 ETDA `lod600.map` 은 `af3aba0a…` 로 다르다.)
- Novaonline 은 윈도우의 원본 팩(`sources/novaonline/`)에서 직접 뽑는다 — 어느 맵이 어느 파일인지는
  `data/server-packs/extracted/novaonline/maps.json` 의 `맵파일` 칸.

## 3. 할 일 (위에서부터)

1. **원작 설치본의 맵 파일** — 두 설치본(InstallShield 6, `unshield x data1.cab` — 역어셈블 때와 같다)에 `maps/lod*.map` 이
   들었는지. 있으면 우드랜드 후보 번호(`lod600~623` · `lod681` · `lod686~723`)의 크기·md5. **없으면 "설치본에 맵 없음"** 이라고 적는다
   (원작 클라이언트는 서버에서 맵을 받아 `maps/` 에 쌓는다 — 설치본에 없을 수 있다).
2. **7.41 클라이언트 쪽**(`D:\_personal\LOD_`)에도 같은 번호 맵이 있으면 같은 칸을 채운다.
3. **Novaonline 원본 팩**의 우드랜드 맵 파일 md5.
4. **비교표** — 맵 파일 번호마다: 원작2005 · 원작4.51 · 7.41 · 혼든 · Novaonline · 5.99 의 md5 와 "원작과 같음/다름/없음".
5. **월드맵 입구(역어셈블)** — 2005 `Legend.exe`(= 5.99 클라이언트, md5 같음)가 `field%03d.txt` 줄의 `EX x y 번호` 를 어떻게 쓰는지.
   셋째 수(`동의우드랜드` 22 · `서의우드랜드` 24 · `북의우드랜드` 23)가 **맵 번호인지, 다른 월드맵 번호인지, 무엇인지**. 글자 `EX` 를 찾는
   곳부터 보면 가깝다. 모르면 "확인 못 함".
6. (여유가 있으면) 원작 아카이브(`Legend.dat`·`setoa.dat`)에 맵 번호 → 맵 이름 표가 있는지 — 이름에 `우드랜드` 가 든 표.

모르는 것은 **"확인 못 함"** 으로 적는다. 추측으로 채우지 않는다.

## 4. 결과를 어디에 어떤 모양으로

- `data/map-origins/woodland-origins.json` — 맵 파일 번호마다 위 여섯 출처의 md5·크기와 판정. 설치본 경로는 윈도우 경로 그대로 적되
  **파일은 올리지 않는다.**

  어느 팩의 우드랜드 맵이 원작 파일과 같은지 · 월드맵 `EX` 셋째 수의 뜻 · 원작에 서의·남의 우드랜드 맵이 있는지.
- 역어셈블 근거는 `data/disassembly/excerpts/original-2005-field-ex-*.asm`(몇 KB), `data/disassembly/findings.json` 에 규칙 한 줄.
- `WORKLOG.md` 맨 위 History 에 한 줄 요약.

## 5. 지킬 것

- **실행 파일(.exe)·아카이브(.dat)·맵(.map)은 절대 커밋하지 않는다.**
- 브랜치: `docs/woodland-origin` (지금 브랜치 `test/hades-characterization` 에서 딴다).
- `git add` 는 경로를 적어서 한다(폴더째 담지 않는다). `git status` 는 `--ignore-submodules=all`.
- `sources/` 아래 원본 저장소는 건드리지 않는다. 비밀값 파일 규칙(`AGENTS.md`)을 지킨다.
- 커밋 메시지는 Conventional Commits, 한국어 본문.
- 끝나면 `git push -u origin docs/woodland-origin`.
