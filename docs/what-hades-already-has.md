# Hades 에 이미 있는 것 — 만들 것과 채울 것

> 셈한 날 2026-09-12 · 커밋 `f26280a` 기준.
> **먼저 물어라, 뒤지지 마라.** 이 문서가 있는 이유는 같은 것을 또 grep 하지 않기 위해서다.

## 한 줄

**Hades 는 규칙이 있고 내용이 없다. 서버팩은 내용이 있고 규칙이 남의 것이다.**
그래서 이식은 "시스템을 만드는 일"이 아니라 **"도는 시스템에 자료를 붓는 일"** 이다.

## 순서 — Hades 부터 본다

**팩부터 뒤지지 마라.** 팩은 운영자가 손댄 사본이고 Hades 쪽에 원작이 남아 있는 일이 잦다.
확인하지 않고 팩을 쓰면 원작 복원이 아니라 **그 팩 복원**이 된다.

  1. `database/server/` — 이미 들어간 자료·스크립트
  2. `database/archives/*.dat` — **원작 표가 여기 들어 있다** (아래)
  3. `data/game-data/` — 원작에서 뽑아 둔 것
  4. 그래도 없으면 `data/server-packs/` — 그때도 **출처를 남긴다**

## 어디에 물어야 하나

| 묻는 것 | 어디 | 어떻게 |
|---|---|---|
| Hades 코드가 뭘 하나 | `graphify-out/` (코드·문서 그래프) | `graphify explain "<기호>"` · `graphify query "<기호> <기호>"` |
| 팩에 뭐가 들었나 | `data/server-packs/vault/<팩>/` | Obsidian 으로 연다 (`docs/server-pack-data.md`) |
| 원작 수치 | `data/game-data/` | `docs/game-data.md` |

**그래프는 기호로 물어야 한다.** 한국어 문장으로 물으면 글자가 겹치는 엉뚱한 노드에서 출발한다
(실측: "이미 구현된 상점 NPC 스크립트는?" → `Sprite.cs` 로 샜다. `explain "shop1"` → 정확히 맞혔다).

`graphify-out/` 은 추적하지 않는 로컬 산출물이라 **낡아 있을 수 있다.**
`graph.json` 의 `built_at_commit` 을 HEAD 와 견줘 보고, 벌어졌으면 다시 만든다.

### 이미 돌아가는 것들 (다시 만들지 마라)

- **상점** — `scripts/Mundanes/shop1.cs` 가 사기(`0x0001`)·팔기(`0x0002`)·수리(`0x0003`)를 다 한다.
  파는 목록은 `Mundane.Template.DefaultMerchantStock` 에서 읽고, `ScriptKey = "shop1"` 이면 붙는다.
  → 새 시스템을 만들 일이 아니다. **다만 목록만 채우면 되는 것도 아니다** —
  팩 상점 이름 47종은 `각반사기`·`귀걸이사기` 같은 **목록 이름**이라 NPC 정의 31종과 **하나도 안 겹친다.**
  "어느 NPC 가 어느 목록을 여는가"는 팩 **스크립트 안에** 있어 먼저 복원해야 한다.
  또 47개 중 `물건팔기` 7개는 NPC 가 **사 주는** 목록이라 `DefaultMerchantStock` 이 아니다
  (사는 쪽은 목록을 안 쓰고 인벤토리를 받는다).
- **은행** — `Banker.cs` (`DepositMenu`, `CompleteTrade`)
- **기술·마법 배우기** — `LearnSkills.cs` · `ClassChooser.cs`
- **대화창** — `GameClient.SendOptionsDialog()` · `SendItemShopDialog()`
- 그 밖: `ArenaMaster.cs`, `simple_generic_npc.cs`, `MunedaneReactorExample.cs`, `StateExample.cs`

### NPC 가 세상에 없는 진짜 이유

`Mundane Templates Loaded: 0` 은 스크립트가 없어서가 아니다.
스크립트 25장은 대기 중이고, **`templates/mundanes/` 가 비어 있다.**
JSON 한 장을 넣으면 붙는다 — 그게 NPC 대화를 여는 가장 짧은 길이다.

## 팩 스크립트는 옮기는 게 아니라 읽는 것

팩 서버는 `Novaonline.exe` / `Yuki.exe` — 네이티브 엔진이고 스크립트는 그 엔진 전용 언어다
(`warp "맵"`, `item_add "아이템"`, `#변수`, `if(#변수==n)`). Hades 는 C# 을 컴파일한다.
**번역기를 만들 일이 아니다.** 엔진 명령 401개는 "옮길 목록"이 아니라
**"위 115장에 대응하는 게 뭔가 맞춰 볼 목록"** 이다 (`vault/<팩>/명령/`).

## 맵 파일이 어디 있나

팩 `maps.json` 은 맵 **807개**를 선언하지만 실제 파일은 **521개**다 — 재활용하기 때문이다.
혼돈의탑 71개 방이 한 파일, 승급캐슬 대기실 20개가 한 파일, 네 마을 은행이 한 파일.
합쳐야 **8.4MB**, 아카이브 5,017개 중 **10%** 다.

**맵의 신원은 번호가 아니라 파일 경로다.** 번호는 폴더 안에서만 세는 지역 번호라
맵 807개가 정수 번호 **445개**를 나눠 쓴다 — 번호 1 하나를 **11개 맵**이 쓴다.
(`0001` 과 `1` 을 다른 것으로 세면 463처럼 보인다. 문자열이 아니라 정수로 세야 한다.)
번호를 열쇠로 삼으면 맵이 사라진다. 팩 번호 1·2·3 은 Hades 가 이미 쓰는 번호와도 겹친다.

이 저장소에 있는 `.map` 은 **7.18 계보**다. 팩(5.99)과는 안 바뀐 맵만 겹친다:

| 견준 것 | 수 |
|---|---|
| `database/assets/MapFiles` 보유 | 2,241 |
| 팩이 쓰는 이름 448개 중 — 이름·크기 다 맞음 | **131** |
| — 이름만 같고 다른 맵 | 93 |
| — 없음 | 224 |

5.99 본체는 `5.99 서버팩.zip` 안에 있고, **풀린 것이 `~/Downloads/5.99 서버팩` 에 있다**(맵 2,766개).
`data/server-packs/` 에는 텍스트 238개만 꺼내 두었다(`data/server-packs/README.md`) — 바이너리는
이식에 필요한 **521개만** `data/map-source/5.99-server/` 로 따로 들여왔다.

**팩의 `너비`·`높이` 를 믿지 마라.** 807개 선언 중 12개가 파일과 어긋난다.
`lod3713.map` 은 실제 50×50 이라 `해안가 3` 이 맞고 `집털 1-1~1-4` 가 틀렸다. 파일이 정답이다.

### 모자란 맵은 이제 조용히 안 들어온다

맵 파일은 `너비 × 높이 × 6` 바이트여야 한다. 예전에는 모자라면 남은 칸을 벽으로 채우고
`Ready = true` 를 찍어, **한 덩어리 벽이 된 맵이 정상으로 보였다.** 호출부도 실패를 빈 중괄호로 버렸다.
지금은 길이가 안 맞으면 이름을 대고 거른다:

```
Map 2 (Refugee Camp): lod2.map is 0 bytes, expected 29400 for 70x70. Not loaded.
Map Templates Loaded: 3
```

지키는 시험: `tests/hades-characterization/MapIntegrityTests.cs`

## 수치는 표에 없다 — 돌려 보고 재 본 것

`python3 scripts/build-formula-vault.py` → `data/formula-vault/` (Obsidian). 근거 줄과 재 본 값,
그리고 그걸 지키는 시험이 노트마다 적혀 있다. **괴물 공격력 표를 찾지 마라 — 없다.**

| 알아낸 것 | 그래서 |
|---|---|
| **괴물 템플릿의 체력은 버려진다** — 젠할 때 `50 + Lv×(Lv+40)` 로 덮어쓴다 | 팩이 17,550 을 준 `가스` 가 **91** 로 선다. 배치 565개가 전부 1수준이라 전부 91 |
| **공격력도 표가 없다** — `Formulas/damage.cs` 가 수준과 사람과의 차이만 읽는다 | 1수준 괴물의 한 방 = 맨 7점 → 사람에게 **10점** |
| **방어는 피해를 줄이지 않는다** — `ac.cs` 가 맨 피해와 방어를 거친 피해 중 **큰 쪽**을 준다 | 방어가 -2 보다 크면 언제나 더 아프다. 새 캐릭터는 **+100**(`100 - 수준/3`), 1수준 괴물은 **+69** |
| **기술은 휘두를 때마다 한 단계 오른다** — `(int)(0.10 / LevelRate)` 가 0 | 연속으로 휘두르면 매번 더 아프다. 예측하려면 몇 번째인지를 알아야 한다 |
| **새 캐릭터는 150 중 60, 200 중 30** 으로 깨어난다 | 깎인 양은 최대가 아니라 **그때 체력** 기준으로 재야 한다 |
| **헛친 것도 알려준다** — serial 0 의 체력 0 | 체력 보고를 세면 몇 번 휘둘렀는지가 나온다. 0 을 괴물로 세면 "한 방에 죽었다" 로 잘못 읽는다 |
| **속성 없는 쪽끼리는 0.50 배** | 이식한 괴물 565개가 전부 None 이라 늘 절반이다 |
| **젠은 벽에 걸린 시도도 한 번으로 센다** | 정의가 둘뿐인 방은 1분에 여섯 번만 굴린다. 집 안은 대부분 벽이라 몇 분을 기다려도 빌 수 있다 |

지키는 시험: `tests/hades-characterization/CombatSmokeTests.cs` — 값을 **먼저 계산하고** 실제로 때려 본다.
"체력이 좀 깎였다" 로는 한 대에 1% 가 깎이든 90% 가 깎이든 똑같이 통과한다.
