## 1. 서버 주소를 어디서 읽나

### 1.1 고르는 순서 (`0x46e5b0` 설정 만들기 안, `0x46e6f8` 의 대행사 분기)

설정 객체는 전역 `[0x734e48]`이다. 주소는 `+661`(4바이트), 포트는 `+1056`(2바이트) + `+1058`(보탤 값, 처음 0)에 둔다.

| 순서 | 조건 | 주소·포트 | 근거 |
|---|---|---|---|
| 0 | 대행사 번호 `+141` 이 0 이 아님(`.nfo` 파일로 정함) | 대행사별 함수가 정한다(아래 표) | 점프표 `0x852a00` |
| 1 | 명령줄에 실행 파일 경로(따옴표) 뒤로 5글자 넘게 있음 | 숫자로 시작하면 점 IP, 아니면 `gethostbyname`. 뒤에 `" 포트"` 가 있으면 그 포트, **없으면 23** | `0x46e711` `0x46e785` `0x46e85d` `0x46e89f` |
| 2 | 명령줄이 없음 | 먼저 `210.101.85.25:2610`(넥슨 공식)을 넣고, 서버 표에서 고른 칸(`+1358` ≠ 255)이 있으면 **그 칸의 IP·포트로 덮는다** | `0x46e8c4` `0x46e912` |
| 3 | 명령줄 호스트를 못 찾음 | `210.101.85.25:2610` | `0x46eae4` |

- `hook.ini` 의 `CommandLine=192.168.0.4` 는 창 모드 도구(DxWnd 류)의 설정이다. 이것이 명령줄로 그대로 들어가면 **포트가 없어 23 으로 접속한다**(위 1번). 그래서 개인 서버는 보통 명령줄 없이 `mServer2.tbl` 로 접속한다 — **추정**(도구가 명령줄을 실제로 넘기는지는 확인 못 함).
- 대행사(`usa.nfo` `japan.nfo` `Unitel.nfo` `LG.nfo` `SK.nfo` `Thrunet.nfo` `GameOK.nfo` `Bixel.nfo` `Excitegame.nfo` `KornetWorld.nfo` `mihosoft.nfo` …)는 2000년대 포털·PC통신 전용판이다. 각자 다른 함수(`0x46f7d4` … `0x473924`)로 주소를 정하고, 접속 직후 대행사 머리말을 먼저 보낸다(예: 대행사 7 은 `210.101.85.31\t2622\t<아이디>…\n` 문자열, `0x600345`; 9 는 `cjconnector.dll` 의 `ConnectorKey`, `0x6002da`). 모바일에는 필요 없다.

### 1.2 `mServer2.tbl` / `mServer.tbl` 형식 (`0x5f7ae4` / `0x5f7770`)

`mServer2.tbl` 을 먼저 열고, 못 열면 `mServer.tbl` 을 연다. 둘 다 **줄마다 `%d`** 로 읽는 글 파일이다(줄 끝 CRLF). 읽은 것은 설정 `+1356` 부터 들어간다.

| 줄 | 들어가는 곳 | 뜻 | 우리 파일 값 |
|---|---|---|---|
| 1 | `+1356` | 확인 못 함 | `0` |
| 2 | `+1357` | 서버 칸 수 | `1` |
| 칸마다 ① | 칸 `+0` | 서버 번호 | `0` |
| 칸마다 ② | 칸 `+4` | IP 를 **32비트 정수**로(메모리 그대로) | `67152064` = `192.168.0.4` |
| 칸마다 ③ | 칸 `+8` | 포트 | `8525` |
| 칸마다 ④ | 칸 `+268` | `mServer2.tbl` 에만 있다. 뜻 확인 못 함 | `0` |
| 칸마다 ⑤ | 칸 `+12` (256바이트) | 서버 이름 — **글자 섞기** | `신 온라인;서비스시작 15년 06월` |
| 칸마다 ⑥ | 칸 `+269` (10000바이트) | 설명 — 글자 섞기 | `{=u====…` |
| 끝 | `+1358` | 처음 고를 칸 번호(255 = 없음) | `0` |

- 한 칸은 10272바이트다(`0x5f7a95`).
- **글자 섞기 풀기**(`0x5f7d08`): 0번 바이트는 두고 1·2, 3·4, 5·6 … 번 바이트를 서로 맞바꾼다. 같은 일을 다시 하면 원래대로 섞인다.
- 서버가 `0x00` 인사에서 보낸 **서버 목록 CRC** 가 이 표로 계산한 값과 다르면, 서버 고르기 창을 "목록 새로 받기"로 연다(`0x521c7c`). 새 목록은 `0x57`(보냄) → `0x56 SMulti`(받음) 로 오간다 — **추정**(`0x5f9737` 이 `57 01 00` 을 보내고, `0x56` 을 `ServerSelectDialogPane` 이 받는 것까지 확인).

### 1.3 `Legend.cfg` 는 통신 주소와 상관없다

`Legend.cfg` 를 쓰는 곳(`0x46eb6d`)을 보면 `Version: 9728` 은 **설정 파일 형식 번호(고정값)** 이고, `Port: 5`·`Speed: 57600`·`Tel1~4`(천리안·하이텔·유니텔·나우누리 전화번호)는 **모뎀 전화 접속용**(COM 포트·속도)이다. 게임 버전도 서버 주소도 아니다.
`Legend.prf`(0~17 번호와 값)는 통신 코드에서 읽지 않는다 — 확인 못 함(통신과 무관한 것으로 보인다).

## 2. 소켓 — 만들기, 접속, 읽기·쓰기

### 2.1 소켓 스레드와 명령

소켓 객체(`Socket`, vtable `0x89e224`, 전역 `[0x734e40]`)는 **자기 스레드**에서 돈다. 화면 쪽은 명령을 줄에 넣고 세마포어로 깨운다(`0x625230`). 소켓 핸들은 객체 `+0x480CC` 에 있다.

| 명령 | 넣는 함수 | 스레드에서 하는 일 | 근거 |
|---|---|---|---|
| 2 | `0x5fde80` | 접속 시작. 방식 `+491736` 이 5 면 TCP(`0x5fff40`), 아니면 모뎀(COM, `0x601534`) | `0x5ffeb4` |
| 3 | `0x5fdea0` | 끊기(소켓·COM 닫기) | `0x601464` |
| 4 | `0x5fded0` | 새 주소로 다시 접속(서버 옮기기) | `0x6017b4` |
| 5 | `0x5fdef0` | 읽기(FD_READ 가 오면) | `0x5fe2f4` |
| 6 | `0x5fdf00` | 패킷 보내기 | `0x601844` |
| 7 | `0x5fdf70` | 원본 그대로 읽기 표지 `+491740` | `0x5ffc72` |
| 8 | `0x6014b0` | 글자열 그대로 보내기(대행사 머리말) | `0x6022f4` |

### 2.2 TCP 접속 (`0x5fff40`, 발췌 `connect-5fff40`)

1. 소켓이 이미 있으면 아무것도 안 한다. 없으면 `WSAStartup(1.1)` → `socket(AF_INET, SOCK_STREAM)` → `setsockopt(SOL_SOCKET, SO_SNDBUF=0x1001, 16384)` (`0x5fffde`~`0x60004f`).
2. 주소 `+661`, 포트 `htons(+1056 + +1058)` 로 `connect`(`0x6000f0`). **막히는(blocking) 접속**이다.
3. 대행사 번호에 따라 머리말을 보낸 뒤 `WSAAsyncSelect(소켓, 창, 0x402, FD_READ|FD_CLOSE)`(`0x60016a`). 이후 읽기는 창 메시지로 온다.
4. **실패하면**:
   - 서버 고르기 화면에서 연 접속이면(`0x6000b7` 조건) "Connection failure... retry.." 를 띄우고 **서버 표의 다음 칸으로 넘어가 계속 다시 시도**한다(`0x6001ae`~`0x6002b1`, 칸 번호 `(+1358 + 1) % 칸 수`). 기다리는 시간은 없다.
   - 아니면 `usa.nfo` 가 있으면 `da0.nexon.net:2610`, `japan.nfo` 가 있으면 `yami0.nexon.net:3460` 으로 한 번 더 해 보고, 성공하면 `iplookup.tbl` 에 `"%d %d"`(IP 정수, 포트)를 적는다(`0x601034`, `0x6011c4`). 둘 다 없으면 프로그램을 끝낸다.
   - 소켓 만들기 실패는 `networkError: …` 문구 표(`0x601293`)로 알린다.

### 2.3 읽기 (`0x5fe2f4`, 발췌 `recv-5fe2f4`)

- 창 메시지 `0x402` 의 FD_READ(1) → 명령 5, FD_CLOSE(32) → `0x5fe100`(`0x50e643`).
- `recv(소켓, 버퍼, 98304)` 로 한꺼번에 받아 **한 바이트씩** 상태 기계에 넣는다(`0x5fe72b`). `recv` 가 0 이면 소켓을 닫는다(`0x5fe770`).
- 상태 기계(`+491737` 상태, `+360660` 센 수, `+295048` 길이):

| 상태 | 받은 바이트 | 하는 일 |
|---|---|---|
| 0 | 아무것이나 | **머리 바이트로 치고 버린다 — `0xAA` 인지 확인하지 않는다**(`0x5fe366`). 상태 1 로 |
| 1, 센 수 0 | 길이 윗자리 | 길이 = 바이트 × 256 |
| 1, 센 수 1 | 길이 아랫자리 | 길이 \|= 바이트 |
| 1, 그 뒤 | 몸통 | `+295121` 부터 쌓다가 길이만큼 모이면 상태 0 |

- 다 모이면 첫 바이트(opcode)가 `0x00`·`0x40`·`0x03` 이면 그대로, 아니면 복호화(`0x5fed04`)한 뒤 `0x4afad0` 으로 **화면 스레드의 이벤트 줄**(이벤트 종류 19)에 넘긴다(`0x5fe40c`~`0x5fe457`).
- 모뎀(글자) 방식에서는 `*`·`+` 로 시작하고 `.` 로 끝나는 **6비트 글자 꾸러미**를 푼다(`0x5fe524`, 보낼 때 `0x6018e9` — 한 바이트 3개를 `+59` 더한 글자 4개로). PC통신 전화 접속 시절의 것이다.

### 2.4 쓰기 (`0x601844`, 발췌 `send-frame-601844`)

- 화면 쪽은 `0x5fdf00(버퍼, 길이)` 하나로 보낸다(호출 191곳). 서버 옮기는 중 표지(`+491742` = 1, `0x5fde70`)가 켜져 있으면 **`0x10` 말고는 버린다**(`0x5fdf0b`).
- 스레드에서: opcode 가 `0x00`·`0x48`·`0x10` 이면 그대로, 아니면 암호화(`0x601d64`). 그다음 `AA` + 길이(2, 큰 자리부터, `0x601d48`) + 몸통을 `send` 한 번(`0x601a80`~`0x601ab8`). `send` 실패는 조용히 버린다.

## 3. 패킷 틀과 암호화

### 3.1 틀

```
AA | 길이 hi | 길이 lo | opcode | 순번 | 몸통 …        (암호화하는 패킷)
AA | 길이 hi | 길이 lo | opcode | 몸통 …               (암호화 안 하는 패킷)
```

- 길이 = 머리 3바이트를 뺀 나머지 바이트 수.
- **체크섬은 없다.** 패킷 틀에도 암호화에도 검사 값이 없다(보내기·받기 함수 전체에서 찾지 못했다).

### 3.2 암호화 (`0x601d64`, 복호화는 같은 일을 거꾸로 `0x5fed04`. 발췌 `encrypt-601d64`)

| 단계 | 하는 일 | 근거 |
|---|---|---|
| 순번 | 전역 바이트 `0x77a060` 을 넣고 1 올린다. **보낼 때마다 +1, 다른 서버로 옮겨도 0 으로 돌리지 않는다** | `0x601d84` |
| 1 | 몸통 i 번째 바이트 ^= 열쇠[i % 열쇠 길이] (4바이트씩 묶어서 하지만 결과는 같다) | `0x601e03` |
| 2 | 몸통을 열쇠 길이(9바이트)씩 덩어리로 나눠, 덩어리 번호 b(1바이트로 자름) 가 **순번과 다를 때만** ^= 씨앗표[b] | `0x601f7a` |
| 3 | 몸통 전체 ^= 씨앗표[순번] | `0x602181` |

즉 `몸통[i] ^= 열쇠[i%9] ^ 씨앗표[순번] ^ (b≠순번 ? 씨앗표[b] : 0)` (b = i/9). 하데스 `SecurityProvider`·우리 `HadesCipher.Transform` 과 **같은 결과**다(우리는 씨앗 0 만 한다).

- **기본 열쇠**는 `NexonInc.`(9바이트, `0x5fdc74`). 서버 `0x00` 인사가 새 열쇠와 씨앗을 주면 바꾼다(명령 11·12, `0x521b61` `0x521b87`).
- **씨앗 표 10종**(`0x5ffccc`, 표 `0x6b3340`, 칸마다 같은 바이트를 4번 채운 dword):

| 씨앗 | 표[i] (i = 0~255, 결과는 1바이트) |
|---|---|
| 0 | i |
| 1 | 128 + (i 홀수면 −, 짝수면 +) × ((i+1)/2) |
| 2 | 255 − i |
| 3 | 128 + (i 홀수면 −, 짝수면 +) × ((255−i)/2) |
| 4 | (i/16)² |
| 5 | (2i) mod 256 |
| 6 | 255 − (2i mod 256) |
| 7 | i ≤ 127 이면 255 − 2i, 아니면 2i − 256 |
| 8 | i ≤ 127 이면 2i, 아니면 511 − 2i |
| 9 | 255 − (((i−128)/8)² mod 256) |

- **암호화 안 하는 opcode**: 보낼 때 `0x00`(버전) `0x10`(입장권) `0x48`(나가기 직전 `FF FF`), 받을 때 `0x00`(인사) `0x03`(서버 옮기기) `0x40`(쓰는 곳 확인 못 함).
- **대화 답(0x39·0x3A)에 두 번째 암호가 없다.** 원작은 `3A | 종류 | id(4) | 스크립트(2) | 단계(2)` 를 다른 패킷과 똑같이 보낸다(`0x5678e9`, 길이 10). 우리 `HadesCipher.EncodeDialogSecured` 의 "6바이트 머리 + 두 번째 섞기"는 하데스(7.x) 쪽 요구다.

## 5. 서버가 보내는 패킷 — 받는 쪽 분기표

### 5.1 어떻게 가르나

- 받은 패킷은 이벤트(종류 19)로 화면 스레드에 온다. 이벤트 `+20` = 원본 버퍼, `+24` = 길이, `+28` = 패킷 객체.
- **패킷 공장**(`server_pck_factory`, 생성 `0x63b8d0`, 만들기 `0x63ccd0`)이 opcode 로 `S이름` 클래스를 만들어 `+28` 에 넣는다. 각 클래스는 생성자에서 opcode 를 정하고(`push opcode → 0x63b7d0`, 객체 `+12`), vtable 3번째 함수가 몸통을 읽는다. 읽는 도구: 바이트 `0x63b5c0`, 2바이트 `0x63b5e0`, 3바이트 `0x63b610`, 4바이트 `0x63b640`, 길이(1)+글 `0x63b690`, 길이(2)+글 `0x63b730` — 모두 큰 자리부터.
- 화면(창)마다 vtable 20번 칸(`+0x50`)의 "패킷 받기" 함수가 `0x63b800`(opcode 꺼내기)로 비교해 자기 것만 처리한다. **한 패킷을 여러 창이 같이 받는다**(예: `0x08` 은 9곳).
- 클래스가 없는 opcode 는 원본 버퍼 첫 바이트를 직접 비교한다(`MainMenuPane 0x521900`, `MapPane 0x547230`, `GUIBackPane 0x64b710`).
- 4.51 판의 opcode 점프표(`0x510a54`, findings)와 달리 **2005 판에는 opcode 하나짜리 점프표가 없다.**

발췌 `factory-63d180` 에 클래스 하나(0x3F), 공장, 세계 화면 분기 첫머리를 넣었다.

### 5.2 전체 표

"읽기"는 클래스의 몸통 읽기 함수, "처리"는 그 패킷을 받는 창의 함수다. 창 이름은 RTTI 그대로다.

## 6. 클라이언트가 보내는 패킷

`0x5fdf00` 을 부르는 191곳 중 몸통을 정적으로 확인한 것이다. "모양"의 b=1바이트, w=2바이트, d=4바이트, s=길이(1)+글.
같은 opcode 를 여러 곳에서 보내면 대표 주소만 적었다(전체 목록은 다시 뽑을 수 있다 — 아래 "다시 하기").

## 7. 심장박동 · 시간 · 끊김 · 재접속 · 보내기 제한

### 7.1 심장박동 `0x3B` → `0x45` (`0x52c7a0`, 발췌 `heartbeat-52c7a0`)

- 서버 `0x3B` 몸통 2바이트 `[p, q]` 를 큰 자리부터 읽어 `W = p·256 + q`.
- CRC16(다항식 0x1021, 표 `0x6a1220`) 계산 모양이지만 표의 0번 칸(값 0)만 쓰게 되어 있어 **결과는 `(q·256 + p)`, 즉 두 바이트를 맞바꾼 것**이다.
- 답 `0x45 [q, p]` 를 **암호화해서** 보낸다(길이 3).
- 클라이언트 쪽에서 심장박동이 끊기는지 재는 곳은 **찾지 못했다**(확인 못 함). 끊김은 TCP 가 알려 줄 때(FD_CLOSE)만 안다.

### 7.2 시간 확인 `0x68` → `0x75`

서버 `0x68 SCheckTime`(4바이트 T) → 클라이언트 `0x75 | T(4) | 내 timeGetTime(4)` (`0x5ca14f`). 서버가 왕복 시간·속도 조작을 잴 수 있게 하는 것으로 보인다(**추정**).

### 7.3 끊김과 재접속

- FD_CLOSE → `0x5fe100`: 소켓·COM 을 닫고 **`ReconnectDialogPane`**(msg.tbl 32번 글)을 띄운다.
- 그 창을 닫으면 설정을 새로 만들고(`usa.nfo` 가 있으면 `Darkages.cfg`, 없으면 `Legend.cfg`) **접속 화면(`TerminalPane`)부터 다시** 시작한다(`0x5e747c`~`0x5e74f5`). 캐릭터 상태를 이어 붙이는 **자동 재접속은 없다**.
- 접속 자체가 안 될 때의 반복 시도는 2.2 절.

### 7.4 보내기 속도 제한 (발췌 `walk-attack-5c8cfb`)

| 무엇 | 규칙 | 근거 |
|---|---|---|

- 받을 때 암호 없이 받는 `0x40` 을 누가 처리하는지
- 원본으로만 처리되는 서버 `0x1B` `0x1D` `0x24` `0x35` `0x4F` 의 뜻, `0x36` 이 접속자 목록인지

- 계정 만들기 `0x02` 몸통, 로그인 `0x03` 의 선택 바이트(`[0x764f70]`)가 무엇인지
- `mServer2.tbl` 첫 줄(`+1356`)과 칸마다 넷째 수(`+268`)의 뜻
- 버전 값이 0 이 되는 조건(Version.nfo `pg`)과 자원 6번 "501" 을 쓰는 경우
- 클라이언트 쪽 무응답 시간 제한(타임아웃) — 찾지 못함
- 패킷 공장 사용 여부 표지 `PacketPreprocessor+436` 은 처음에 1(공장 끔)로 놓이는데(`0x4aaf24`), 0 으로 바꾸는 곳 — 클래스 처리가 실제로 켜지는 때
