# 5.99 서버 게임 규칙 — 전투·성장·괴물 (Novaonline.exe)

- 기준일: 2026-10-04
- 대상: `~/Downloads/5.99 서버팩/Novaonline.exe` (32비트 PE, 614,400바이트). 디버그 빌드라 함수마다 `push ebp; mov ebp, esp` 로 시작하고 지역 변수를 `0xCCCCCCCC` 로 채운다
- 읽는 법·도구·이미 찾은 것: [`docs/disassembly.md`](../disassembly.md) · 단일 출처 `data/disassembly/findings.json`
- 근거 발췌: `data/disassembly/excerpts/manual-server-rules-*.asm` (13개). 발췌마다 맨 위 주석에 그 파일이 증명하는 식을 적었다
- 관련 문서: 괴물 값이 하데스에서 어디에 있는지는 [`monster-behaviour.md`](../monster-behaviour.md), 속도 단위는 [`speed-reference.md`](../speed-reference.md), 팩 자료는 [`server-pack-data.md`](../server-pack-data.md), 우리 쪽 통역은 서버 fork `database/server/scripts/Pack599/Pack599.cs`

**적는 방식.** 식 옆 괄호 안의 `0x…` 는 그 식이 있는 기계어 주소다. 기계어로 확인하지 못한 것에는 **추정**을, 찾지 못한 것에는 **확인 못 함**을 붙였다.
`rand()` 는 C 런타임 난수(`0x476d82`)다. `|rand%100| ≤ x` 꼴의 비교는 등호를 포함하므로 실제 확률은 **(x+1)%** 다.

## 0. 구조체 셋 — 먼저 가려 둔다

같은 오프셋이 구조체마다 다른 칸을 가리킨다. 칸 지도를 볼 때는 어느 구조체인지부터 확인한다.

| 기호 | 무엇 | 찾는 법 | 담는 것 |
|---|---|---|---|
| **P** | 접속자(사람 객체) | `[0x4AD200 + 4×id] + 0x20` | 장비·버프를 더한 **실제로 쓰이는 값**(최대체력, AC 합, 실제 능력치). 능력치 재계산 `0x45d4be` 가 채운다 |
| **C** | 캐릭터 칸 | `[P + 0x10]` | **저장되는 값**(레벨, 기본 능력치, 현재 체력, 상태 남은 초). 저장 로더 `0x404ebf` 의 키와 1:1로 맞는다 |
| **T** | 괴물 템플릿(0xB0바이트) | 전역 목록 `0x4EF164` | `mob/*.txt` 한 블록 |
| **M** | 살아 있는 괴물(116바이트) | 맵 객체(40바이트)의 +4 | 현재 체력, 표적, 상태 |

예: `P+0x8C` 는 AC 합(byte)이고 `C+0x8C` 는 공격력(dword)이다. `P+0x98` 은 재생력 합이고 `C+0x98` 은 마법 공격력이다.
findings.json 에 "캐릭터 +0x…" 로 적힌 칸은 지금까지 모두 C 다(평타 잠금 `+0x18`, 공격력 `+0x8C`, 상태 `+0xF0`).

## 2. 체력·마력 자연 회복 — 21초마다 (`0x46d1a5`)

```
v = (최대체력 P+0x90 ÷ 100) × (기본 콘 C+0xA3 ÷ 4.3)        상수 [0x4812a8]=100.0 · [0x4812e0]=4.3
v = clamp(v, 최대체력×15%, 최대체력×25%)                    콘 ≥ 108 이면 바로 25%
휴식 중(C+0x62, set_rest)이면 v = (v >> 1) × 3             곧 ×1.5
현재 체력 C+0xCC += v + P+0x98(장비 재생력 합)              최대체력에서 자른다
```

- 마력도 같은 식이다. 위즈 `C+0xA2`, 최대마력 `P+0x94`, 현재 마력 `C+0xD0` 를 쓰고, 재생력 `P+0x98` 도 그대로 더한다.
- 유령(`C+0xF0 == 1`)이거나 포만도 `C+0xDC == 0` 이면 회복하지 않는다.
- 괴물은 자연 회복 처리가 1초 처리 안에 없다. 다른 곳에 있는지는 **확인 못 함**.

발췌 `manual-server-rules-regen-hunger.asm`.

## 4. 전투

### 4.1 평타 — 사람 → 괴물

평타 함수는 `0x4160f7` 이다. 몸 동작과 잠금은 `disassembly.md` 에 이미 정리돼 있다. 피해는 `0x4166b1` 부터 이 순서로 계산한다.

| 순서 | 식 | 주소 |
|---|---|---|
| 1 원값 | d = 공격력 `C+0x8C` + rand%10 − rand%10 (−9~+9) | `0x4166b1` |
| 2 치명타 | rand%100 ≤ 치명타 `C+0x9C` 이면 d × 2 → 실제 확률 (치명타+1)% | `0x4166eb` |
| 3 오기 | `C+0x74`(damage_per_delay) 가 켜져 있으면 d += 최대체력 `P+0x90` >> 3 (**추정** — 칸 이름만 맞춤) | `0x416703` |
| 4 공격수정 | d += `P+0xA0`(장비 공격수정 합) | `0x415173` |
| 5 방어(AC) | 아래 식 | `0x4150f2` |
| 6 속성 | 목걸이 `C+0x18C` 의 공격속성(`item+0x65`)이 1~5 이면 d × 13/10 | `0x415cff` |
| 7 방어무시 | `C+0x15A` 가 켜져 있고 rand%100 ≥ 80(20%)이면 d 를 4 이전 값으로 되돌린다 | `0x424215` |
| 8 버프 | 속성강화 `C+0x15E == 1` → ×1.5 · 슈페이아움 `C+0x160 ≠ 0` → ×그 값 · 괴물이 잠(`M+0x3A`) → ×2 하고 깨운다 | `0x424215` |
| 9 막기 | 템플릿 보호데미지 `T+0x88` → d = 1 · `M+0x48 ≠ 0` → d = 0 | `0x424488` · `0x4244a2` |
| 10 빼기 | 괴물 체력 `M+0x10` −= d (0 에서 멈춘다) | `0x424598` |

- **명중·회피 판정은 없다.** 평타는 늘 맞는다. 장비 명중수정 합 `P+0x9F` 는 상태 패킷 `0x45f346` 에 실리기만 하고 판정에는 쓰이지 않는다.
- 데미지체크 `T+0x89` 가 켜진 괴물은 "이름: 피해" 를, 비타체크 `T+0x8A` 가 켜진 괴물은 "이름: 남은 체력" 을 알린다.
- 스크립트 명령 `damaged` 도 같은 함수 `0x424215` 로 들어온다. 이 경로에서는 치명타를 굴리지 않는다 — 부르는 쪽이 미리 곱해서 넘긴다.

### 4.2 방어(AC) 식 — `0x4150f2`

```
AC ≠ 0 이면   d = d + trunc(d × AC × k)        k = 0.01 (AC > 0) · 0.009 (AC < 0)
                                              상수 [0x481298]=0.01 · [0x4812a0]=0.009
```

- AC 는 **낮을수록 좋다.** AC −70 이면 d × (1 − 0.63) = **×0.37**. AC +10 이면 ×1.1.
- 괴물의 AC 는 `M+0x00`(템플릿 방어력 `T+0x0D` 를 복사한 값)이다.
- 사람의 AC 는 `P+0x8C` = 기본 방어 `C+0xC8` + Σ 장비 방어력 `item+0x43` 이다(`0x45d4f8`, `get_ac 0x443d4f`).
- AC 가 −112 아래로 내려가면 배수가 음수가 되어 피해가 부호 없는 큰 수로 넘칠 수 있다(**추정** — 실제 장비 합으로 그 값에 닿는지는 확인 못 함).

> **findings.json 과 어긋나지 않는다(2026-10-04 다시 봄).** `0x4150f2(피해, AC, 배수)` = `(피해 + ⌊피해×AC×k⌋) × 배수`(k 상수 `0x481298`=0.01 · `0x4812a0`=0.009). AC 적용과 배수 곱하기를 한 함수가 한다. findings 「후방 공격」의 배수 2 는 이 셋째 인자로 들어가는데, 그렇게 넘기는 길(여러 대상 무기 공격 `0x415d86`)은 아무도 부르지 않고, 평타는 늘 1 을 넘긴다. 그래서 실제 게임에서 등 뒤 ×2 는 일어나지 않는다.

### 4.3 범위 난수 — `0x415173`

```
d = 최소 + (rand × rand × rand) mod (최대 − 최소)        최대가 0 이거나 최소 이하면 최대 = 최소 + 1
그다음 d 에 AC 를 적용한다(4.2)
```

평타에서는 최소와 최대 자리에 같은 d 를 넘기므로 범위는 0 이다. 괴물 평타에서 이 범위가 실제로 쓰인다.

### 4.4 괴물 → 사람 — `0x424bb4` → `0x425d4c`

```
d = 0x415173(최소공격력 T+0x30, 최대공격력 T+0x34, 받는 사람 AC P+0x8C)
d = 속성(괴물 공격속성 M+0x65) → 1~5 이면 ×1.3
받는 사람 피해 넣기 0x415341 (4.6)
```

- 템플릿 공격속성·방어속성이 0 이면 괴물을 만들 때 **1~4 중 무작위**로 정한다(`0x422bc5`). 그래서 **괴물 평타는 사실상 언제나 ×1.3** 이다.
- 받는 사람의 방어속성(허리띠 `C+0x1A0`)은 읽지 않는다.
- 치명타·명중 판정이 없다.
- 괴물이 잠(`M+0x3A`)이거나 `M+0x42` 상태면 공격하지 않는다. `M+0x3C` 상태면 공격 동작만 하고 피해는 없다.

### 4.5 속성 상성 — 표가 없다

`0x415cff(d, 공격속성, 받는속성)` 는 **세 번째 인자를 읽지 않는다.** 공격 쪽 속성이 1~5 중 하나이기만 하면 무조건 ×1.3 이다.
그러니 "불은 물에 약하다" 같은 상성표는 실행 파일에 없다. 원소 이름 문자열도 실행 파일에 없어 1~5 가 각각 어느 원소인지는 **확인 못 함**.

| `group_damaged*` (`0x44c631` 등) | 그룹원마다 같은 고정 피해. AC·치명타 없음. 혼수 `C+0x6D` 인 사람을 만나면 멈춘다 |

### 4.8 기술·마법 피해 — 식이 스크립트에 있다

실행 파일에는 기술별·마법별 피해 식이 없다. 스크립트가 값을 직접 만들어서 4.1·4.7 의 함수로 넣는다.
`get_mgc_damage(@myid)*4`, `get_att_damage*2`, `if(get_critical) ×2` 같은 꼴이다. 괴물 마법(`Mob_Spell.txt`)은 `group_damaged2 @myid, group_bighp()/4` 처럼 쓴다.

| 스크립트가 읽는 값 | 칸 | 만드는 곳 |
|---|---|---|
| `get_att_damage` `0x444676` | `C+0x8C` | 재계산 — 식은 `disassembly.md` 「공격력」 줄 |
| `get_mgc_damage` `0x4446f3` | `C+0x98` | 재계산 — 「마법 공격력」 줄 |
| `get_critical` `0x444770` | rand%100 ≤ `C+0x9C` 이면 1 | 재계산 — 숨기(`C+0x136`) 중이면 +40 (`0x45d935`) |

**마법 저항(MR).** 아이템 마법방어 `item+0x44` 는 로더가 읽지만 능력치 재계산은 쓰지 않는다. 피해 경로에도 MR 처리가 없다. 다른 곳에서 쓰는지는 **확인 못 함**.

발췌 `manual-server-rules-damage-to-monster.asm` · `manual-server-rules-damage-to-player.asm` · `manual-server-rules-mob-attack.asm`.

### 5.1 템플릿 (`mob/*.txt` → `0x4099fe`)

로더는 0xB0바이트 칸을 만든다. 체력·최소공격력·최대공격력이 0 이면 1 로 고친다(`0x409b4f`). 칸 지도는 9.3절에 있다.

| 키 | 값의 뜻 | 근거 |
|---|---|---|
| `속도` | 행동 간격 ms(5.3) | `0x409f3e` |
| `타입` | 0 공격 안 함 · **1 선공** · **2 비선공** · 4·5 칠 수 없음 | `0x426812` · `0x42428c` |
| `젠타임` | 다시 서기까지 **초** | `0x426a74` |
| `골드 a b` | a 원을 **(b+1)%** 확률로 떨군다. 범위가 아니다 — `골드 20 30` 은 31% 확률로 20원 | `0x423f4a` |
| `드롭아이템 확률 이름` | 5.4절 | `0x40a794` |
| `스킬 스크립트 확률` | 쫓거나 때린 차례마다 (확률+1)% 로 그 스크립트를 쓴다. 여러 줄이면 마지막 줄만 남는다(**추정**) | `0x40a576` · `0x426508` |
| `면역` | 침묵(`M+0x44`)을 무시한다 | `0x426473` |
| `하이드체크` | 숨은 사람(상태 2)도 노린다 | `0x426682` |
| `보호데미지` · `데미지체크` · `비타체크` | 받는 피해 1 · 피해 숫자 알림 · 남은 체력 알림 | 4.1 |
| `공격속성` · `방어속성` | 0 이면 1~4 무작위 | `0x422bcd` |
| `낫무브` · `마비여부`(두 번) · `절망여부` · `스펠번호` · `다이번호` | 칸에 적기만 한다. 읽는 곳 **확인 못 함** | `0x40a394~` |

### 5.3 행동 — 250ms 타이머 `0x426812`

```
지금 ≥ M+0x70 이면  M+0x70 = 지금 + 속도(T+0x10)  그리고 행동 한 번
→ 행동 간격 = 속도 ms 를 250ms 단위로 올림(속도 1000 → 1초, 1500 → 1.5초)
```

이동 한 칸과 공격 한 번이 같은 시계를 나눠 쓴다. 따로 도는 공격 시계는 없다.

| 타입 | 5.99 팩 수 | 표적이 없을 때 | 표적이 있을 때 |
|---|---|---|---|
| 0 | 10 (샌드백·주민·스톤) | 표적을 찾아도 50% 배회만 — 쫓지도 때리지도 않는다 | 같음 |
| 1 | 188 | 표적 찾기 → 있으면 쫓는다 = **선공** | 쫓기·공격 |
| 2 | 45 | 배회만 한다 = **비선공** | 쫓기·공격 |

| 무엇 | 규칙 | 근거 |
|---|---|---|
| 어그로 | 사람이 괴물을 치면 `M+0x18 = 1`, `M+0x1C = 때린 사람`. 마지막으로 친 사람이 표적이 된다 | `0x4242ab` |
| 표적 찾기 | 같은 맵, 괴물 중심 ±9칸(맵 끝에서는 18칸 화면 상자, `0x416b63`). 점수 = max(1,\|dx\|) × max(1,\|dy\|) 가 가장 작은 사람. 유령(상태 1)은 빼고, 숨은 사람(상태 2)은 하이드체크 괴물만 본다 | `0x426572` |

### 5.4 죽음·금화·드롭 — `0x424658` · `0x423c00` · `0x423f4a`

| 순서 | 하는 일 |
|---|---|

### 7.2 경험치 주기 — `0x424665` → `0x4696e4`

| 경우 | 규칙 |
|---|---|
| 혼자 | `add_exp(잡은 사람, T+0x20)` 한 번 |
| 그룹(`P+0x14`) | 그룹 12자리 중 **잡은 사람과 같은 맵에 있는 모두**가 경험치를 **나누지 않고 전부** 받는다(`0x41a229`). 레벨차·거리·인원 보정은 없다 |
| 어빌 경험치 `T+0x24` | 같은 방식(`0x41a2cb` → `0x46a165`) |

나누는 함수 두 개(`0x419f4b` 레벨 비례, `0x41a067` n 분의 1 ×1.2)가 실행 파일에 있지만 **아무도 부르지 않는다.**

`add_exp` 가 경험치에 곱하는 것(순서대로):

| 조건 | 결과 |
|---|---|
| noexp `C+0x14C ≠ 0` | 0 |
| 서버 배율 `[0x4AD0C4]` ≥ 2 | × 배율 |
| exp_per 모드 `C+0x150` 이 1·3 | × `C+0x14E` |
| 귀걸이 `C+0x188` = 별의귀걸이 / 퀸셰어의귀걸이 | ×1.2 / ×1.5 |
| 상태 `C+0xF0` 가 0·2·6 이 아님(유령 등) | 0 |
| 전직무시 0 이고 직업 0 이고 레벨 = 전직레벨(6) | 0 ("직업을 선택하셔야…") |
| 맵 `+0x2A ≠ 0` / 맵 `+0x2C ≠ 0` | ×2 / ÷4(승급 전)·÷2(승급 후) |
| rand%100 이 30~32(3%) | ×2, 이펙트 341 |

### 7.3 레벨업

```
레벨 < 99 일 때:
  보유경험치 C+0xBC += exp
  C+0xBC ≥ 표[직업][레벨+1] 이면 레벨 +1    (한 번에 1 만 — 반복하지 않는다)
    포인트       C+0x6C += 표의 포인트 칸 (팩은 모두 2)
    기본최대체력 C+0xB0 += 기본 콘 C+0xA3 + 30
    기본최대마력 C+0xB4 += 기본 위즈 C+0xA2 + 25
    현재 체력·마력을 최대로 채운다
    "레벨이 올랐습니다!" · 이펙트 79(속도 75) · __LEVEL_SCRIPT__
```

- 직업별 차이도, 난수도 없다.
- **최대 레벨 99.** 99 이상이면 보유경험치만 쌓이고, 32비트를 넘으면 "더 이상 경험치가 오르지 않습니다."
- 99 를 처음 찍으면 팩 스크립트가 경험치를 더 준다: (기본최대체력 또는 기본최대마력) × 50000, 2.5억~8억 사이로 자른다.
- **어빌리티**(`0x46a165`): 승급 `C+0x7E == 2` 이고 상태 0 이고 어빌레벨 < 99 일 때만 받는다. `C+0xC4` 에 쌓여 표[직업][어빌레벨] 이상이면 +1, 이펙트 191. 맵 ×2 가 더한 **뒤에** 곱해져서 메시지 숫자에만 반영된다(원본 버그).
- 능력치 포인트를 쓰는 서버 처리는 **확인 못 함**(스크립트 `set_point` 말고는 `C+0x6C` 를 줄이는 곳이 없다).

**경험치 칸이 둘이다(원본 그대로).** 사냥 경험치와 레벨업 판정은 저장 키 "보유경험치" `C+0xBC` 를 쓴다. 반면 화면 %(`0x45de22`)·다음 레벨까지(`0x45df11`)·죽음 벌칙·`exp_del` 은 저장 키 "경험치" `C+0xD4` 를 쓴다. 사냥으로는 `C+0xD4` 가 늘지 않는다. 실제로 돌려서 확인하지는 못했다.

발췌 `manual-server-rules-exp-levelup-4696e4.asm` · `manual-server-rules-group-exp-424658.asm`.

## 11. 확인 못 한 것

- 원소 1~5 의 이름. 실행 파일에 문자열이 없다
- 마법 저항: 아이템 마법방어 `item+0x44` 를 쓰는 곳
- 격발동확률 `item+0x74`: 평타에서 굴려 `0x424215` 의 셋째 인자(255/0)로 넘기지만 피해에는 영향이 없다. 체력바 패킷 `0x414f21` 로만 간다(소리로 **추정**)
- 사람 쪽 "저주"·"마비" 칸. 괴물 템플릿 마비여부·절망여부·낫무브·스펠번호·다이번호를 읽는 곳
- magic 3·4·6·7·8 의 게임 속 이름
- 괴물 체력 자연 회복, 펫 AI `0x424bb4`, 맵 객체 종류 4
- 능력치 포인트를 쓰는 서버 처리, 유령이 되살아나는 길, PK 살인자 칸 `C+0x61` 을 켜는 곳
- 바닥 물건에 주인을 정하는 곳
- `C+0xBC`(보유경험치)와 `C+0xD4`(경험치)가 실제로 따로 노는지(돌려 보지 않았다)
- 맵 `+0x2A`·`+0x2C`(경험치 ×2·÷4)를 켜는 맵 파일 키, 직업 4 의 뜻
- `젠타이` 오타 줄을 로더가 조용히 넘기는지
- 1초 처리가 줄이기만 하는 `C+0x72`·`+0x73`·`+0x89`·`+0x63` 의 쓰임
- `C+0x65` 가 종족인지 오라인지(저장 키와 타이머가 다르게 읽는다)
