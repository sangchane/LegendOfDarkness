# 09. 추가 분석에 필요한 정보

## 실행 검증에 필요한 것

- 실제 사용하려는 레거시 클라이언트 버전과 합법적으로 사용할 수 있는 설치 파일/데이터
- Hades 운영용 `database/server/aislings` 샘플(개인정보 제거), 실제 `LoruleConfig.json`, 서버 로그
- Medenia의 실제 `.env`, 생성된 `db.sqlite`, 배포 구성, 로그인·맵 입장 패킷 trace
- 각 솔루션을 빌드할 Visual Studio/SDK 버전과 누락된 외부 DLL
- `DAMapEditor`가 기대하는 정확한 DALib 커밋/경로

## 제품 결정을 위해 필요한 것

- 목표 모바일 방식: PWA/WebView, Unity/Godot, 완전 네이티브 중 선택
- iOS/Android 동시 지원 여부, 세로/가로 모드, 최소 기기 사양
- 원작과의 콘텐츠·상표·그래픽·음원 사용 권리
- 동시 접속자 목표, 지역, 지연시간, 과금/결제, 채팅·커뮤니티 요구
- 원작 프로토콜 호환이 필요한지, 새 프로토콜로 전환 가능한지
- 아이템·스킬·NPC·퀘스트의 최종 권위 데이터가 어느 저장소인지

## 현재 미확인 또는 충돌하는 부분

- Hades 설정은 클라이언트 버전 `718`, 여러 도구는 `741`, Medenia는 `913`을 사용한다. 같은 패킷 정의라고 가정할 수 없다.
- Hades 저장소의 테스트 `Hades.Client`는 미완성이며 배포 문서는 외부 게임 클라이언트를 가리킨다.
- Medenia는 맵·이동·로그인 골격은 있으나 MMORPG 콘텐츠 전체가 구현된 상태가 아니다.
- DAGL은 방대한 클래스가 있지만 README가 품질을 명시적으로 경고하고 실행점이 없다.
- Archivist는 UI 골격 외 기능이 없다.
- 루트 라이선스가 없는 `DAGL`, `bmp2epf`, `da`, `Dark-Ages-AI-Bot`, `ETDA`는 재사용 권한 확인이 필요하다.

## 이번 단계에서 하지 않은 일

- 코드 변경, 리팩터링, 의존성 설치
- 빌드·테스트·서버 실행
- 외부 게임 클라이언트 실행 또는 패킷 캡처
- 모바일 기술 스택 확정

현행 구조 분석과 로컬 자료 정리만 완료했으며, 다음 구현 단계는 시작하지 않았다.
