# 원작 캐릭터 동작 구조 — 방향·프레임 구간

- 문서 버전: 1.0
- 기준일: 2026-09-10
- 근거: 이 저장소의 `game/khan.dat`·`khan2.dat`·`hades.dat`·`roh.dat` 직접 해독 + 저장소 안의 참고 클라이언트 `sources/FallenDev/dark-ages-ts`
- 도구: `tools/dat-extract` (`epf` `mpf` `pose` 명령)

> **왜 이 문서가 필요한가.** 걷기에서 "북과 서가 같은 방향을 보고 동과 남이 같다"는 문제가 나왔다.
> 그건 버그가 아니라 **원작이 원래 그렇게 만들어져 있기 때문**이다. 같은 구조가 스킬·주문·감정표현에서
> 그대로 반복되므로, 매번 다시 알아내지 않도록 여기 한 곳에 적어 둔다.

---

## 1. 한 줄 요약

원작은 캐릭터를 **네 방향으로 그리지 않는다. 두 벌만 그리고 나머지 둘은 좌우로 뒤집어 쓴다.**
그리고 한 파일 안에 여러 동작이 이어 붙어 있어서, **어느 칸이 어느 동작인지는 파일이 알려주지 않는다.**

---

## 2. 방향 — 두 벌 + 좌우 뒤집기

원작 화면은 마름모(아이소메트릭)라서 게임의 동서남북이 화면에서는 대각선 네 방향이 된다.

| 게임 방향 | 화면에서 | 쓰는 그림 | 좌우 뒤집기 |
|---|---|---|---|
| 북 | 오른쪽 위 | **등을 보이는 벌** | 아니오 |
| 서 | 왼쪽 위 | **등을 보이는 벌** | **예** |
| 동 | 오른쪽 아래 | **앞을 보는 벌** | 아니오 |
| 남 | 왼쪽 아래 | **앞을 보는 벌** | **예** |

저장소의 참고 클라이언트가 같은 규칙을 그대로 쓴다:

```ts
// sources/FallenDev/dark-ages-ts/.../atlas-sprite-animator.ts
public directionFrame(direction: number) {
  if (direction === 0 || direction === 3) {   // UP_RIGHT(북), UP_LEFT(서)
    return this._animation.startUp + this._frame;
  } else {                                     // DOWN_RIGHT(동), DOWN_LEFT(남)
    return this._animation.startDown + this._frame;
  }
}
```

```ts
// sources/FallenDev/dark-ages-ts/.../paper-doll-container.ts
case Direction.UP_RIGHT:   this.sendToBack(this.pieces.shield);  this.setScale( 1, 1); break;
case Direction.DOWN_RIGHT: this.bringToTop(this.pieces.shield);  this.setScale( 1, 1); break;
case Direction.DOWN_LEFT:  this.bringToTop(this.pieces.shield);  this.setScale(-1, 1); break;
case Direction.UP_LEFT:    this.sendToBack(this.pieces.shield);  this.setScale(-1, 1); break;
```

### 2.1 함께 따라오는 두 가지

1. **겹치는 순서가 방향에 따라 바뀐다.** 등을 보일 때는 방패가 몸 뒤로, 앞을 볼 때는 몸 앞으로 간다.
   무기·망토도 같은 처리가 필요하다. 방향만 바꾸고 순서를 안 바꾸면 방패가 등을 뚫고 나온다.
2. **뒤집는 축은 그림 칸의 한가운데가 아니라 발이 닿는 자리다.** 원작 조각은 칸 안에서 한쪽으로 치우쳐
   있어서, 칸 중심을 축으로 뒤집으면 캐릭터가 옆으로 밀린다. 우리 시안에서는
   `transform-origin: calc(50% + var(--ox)) center`로 축을 발 위치에 맞췄다.

## 3. 동작 파일 — 한 부위에 여덟 벌

부위 하나(예: 몸 `mb001`)는 파일 여덟 개로 나뉜다. 접미사가 동작 묶음을 뜻한다.

| 접미사 | 흔한 칸 수 | 내용 | 확인 방법 |
|---|---|---|---|
| `01` | 10 | **서기 + 걷기** | 참고 클라이언트 + 눈으로 확인 |
| `02` | 4 | **평타(기본 공격)** | 참고 클라이언트 + 눈으로 확인 |
| `03` | 10 | **감정표현** — 절, 만세, 하트 등 | 눈으로 확인 |
| `b` | 20 | 스킬 동작 — 가리키기·던지기·팔짱 | 눈으로 확인 |
| `c` | 30 | 스킬 동작 — 주먹·발차기·자세 | 눈으로 확인 |
| `d` | 20 | 스킬 동작 — 무기 휘두르기(칼날 그림 포함) | 눈으로 확인 |
| `e` | 40 | **주문 시전** — 두 손 모으기 + 발차기 | 눈으로 확인 |
| `f` | 20 | 스킬 동작 — 팔 들기 | 눈으로 확인 |
| `04` | 8~32 | 드묾(전체 10,417개 중 80개). 미확인 | — |

그림: [`ui/assets/motion/`](ui/assets/motion/) — 위 표의 각 접미사를 실제로 그린 것.

### 3.1 절반 규칙

**선언된 칸 수의 앞 절반이 "등을 보이는 벌", 뒤 절반이 "앞을 보는 벌"이다.**

```
startUp   = 0
startDown = 선언된 칸 수 / 2
```

참고 클라이언트가 손으로 적어 둔 값과 정확히 일치한다.

| 동작 | 파일 | 칸 수 | startUp | startDown | 한 동작의 길이 |
|---|---|---|---|---|---|
| 서기 | `01` | 10 | 0 | 5 | 1 |
| 걷기 | `01` | 10 | 1 | 6 | 4 |
| 평타 | `02` | 4 | 0 | 2 | 2 |

`c`(30칸 → 15+15), `e`(40칸 → 20+20), `03`(10칸 → 5+5)도 눈으로 확인했다.

**예외가 있다.** `b`와 `f`에 15칸짜리가 각각 256개, `c`에 15칸짜리가 50개 있다. 홀수라 절반으로
안 나뉜다. 또 `01`·`02`·`03`에 1칸짜리가 100여 개씩 있는데, 이건 방향과 무관하게 늘 같은 그림을
쓰는 작은 장식으로 보인다. **절반 규칙은 기본값으로 쓰되, 홀수 칸 파일은 따로 확인해야 한다.**

### 3.2 한 파일 안에 여러 동작이 들어 있다

`c`의 앞 절반 15칸은 **하나의 동작이 아니라 여러 스킬 동작이 이어 붙은 것**이다. 어느 칸부터 몇 칸이
어느 스킬인지는 **파일 안에 없다.** 참고 클라이언트도 서기·걷기·평타 세 개만 손으로 적어 두었다.

> **그래서 스킬·주문에서 같은 문제가 반복된다.** 파일을 열어도 "이 스킬은 몇 번 칸부터"를 알 수 없다.
> 우리가 **동작 표를 직접 만들어야 한다.** 만드는 방법은 아래 4절.

## 4. 스킬·주문 동작 표를 만드는 절차

1. `dat-extract epf <khan.dat> mb001c out.png 15 3` 으로 그 파일의 모든 칸을 한 장에 뽑는다.
   열 수를 `칸 수 / 2`로 주면 **윗줄이 등, 아랫줄이 앞**으로 정렬돼 비교하기 쉽다.
2. 이어지는 자세를 눈으로 묶어 한 동작의 시작 칸과 길이를 정한다.
3. 그 값을 `docs/` 아래 동작 표에 적는다. 형식은 참고 클라이언트와 같게 둔다:
   `{ 파일접미사, startUp, startDown, 칸수, 반복여부 }`.
4. 같은 번호를 서버가 보내는 동작 번호(6절)와 연결한다.

부위마다 칸 수가 다를 수 있으므로(같은 `c`라도 30칸과 15칸이 섞여 있다) **표는 부위별이 아니라
동작별로 만들고, 부위 파일이 그 길이를 못 채우면 그 부위는 그 동작에서 안 그린다**고 처리한다.

---

## 5. 주문 효과 그림은 몸 동작과 별개다

몸이 시전 자세를 취하는 것과, 화면에 터지는 효과 그림은 **다른 자산**이다.

| 대상 | 어디에 | 형식 |
|---|---|---|
| 몸 동작 | `khan.dat` / `khan2.dat` 의 `e` 등 | EPF |
| 효과 그림 | `roh.dat` 의 `efct###.epf` 257개 · `efct###.efa` 100개 | EPF / EFA |
| 효과 재생 순서 | `roh.dat` 의 `efct###.tbl` 261개 | 한 줄에 칸 번호를 나열한 글자 파일 |

효과 표 형식은 `sources/wren11/da-lib/DALib/Drawing/EffectTable.cs` 가 이미 읽는다 — 첫 줄이 개수,
이후 각 줄이 **그 효과가 재생할 칸 번호의 나열**이다. 몸 동작과 달리 **효과는 재생 순서가 파일에
적혀 있다.** 우리가 표를 만들 필요가 없다.

## 6. 서버가 보내는 번호

| 패킷 | 뜻 | 내용 |
|---|---|---|
| `0x1A` (`ServerFormat1A`) | **몸 동작** | 대상 serial + 동작 번호(1바이트) + 속도 |
| `0x29` (`ServerFormat29`) | **효과 그림** | 시전자/대상 serial + 효과 번호 + 속도, 또는 좌표 |

감정표현은 클라이언트가 0~35를 보내고 서버가 **+9** 해서 되돌린다
(`GameServerHandlers.Format1DHandler`). 즉 **0~8은 내장 동작 자리**이고 9~44가 감정표현이다.
0~8이 각각 무엇인지는 아직 확인하지 못했다 — 3절의 접미사와 연결하는 것이 다음 할 일이다.

스킬·주문 템플릿에는 효과 번호가 들어 있다(`SkillTemplate.TargetAnimation`,
`SpellTemplate.Animation`). **몸 동작 번호는 템플릿에 없다** — 서버가 스킬을 실행할 때 별도로
`0x1A`를 보내는 구조다.

## 7. 부위 글자

| 글자 | 부위 | 확인 |
|---|---|---|
| `s` | 방패 | 참고 클라이언트 |
| `m` | 몸 | 참고 클라이언트 |
| `n` | 바지 | 참고 클라이언트 |
| `u` | 갑옷 | 참고 클라이언트 |
| `w` | 무기 | 참고 클라이언트 |
| `l` | 신발 | 참고 클라이언트 |
| `h` | 모자·투구 | 참고 클라이언트 |
| `c` | 장신구 | 참고 클라이언트 |
| `a` | 팔(맨살) | 눈으로 확인 |
| `b` | 몸 | 눈으로 확인 (`m`과 다른 파일) |
| `g` | 날개 | 눈으로 확인 |
| `i` | 도포(한 벌 옷) | 눈으로 확인 |
| `o` | 얼굴 가리개 | 눈으로 확인 |
| `p` | 작은 장식 | 눈으로 확인 |
| `e` `f` `j` | 미확인 | — |

파일 이름은 `<성별><부위><번호 3자리><동작접미사>.epf`. 남자는 `m…`(`khan.dat`),
여자는 `w…`(`khan2.dat`). 여자 아카이브에는 팔레트가 없고 `khan.dat` 것을 함께 쓴다.

색은 부위 글자별 표에서 찾는다 — `palh.tbl`(모자), `palc.tbl`(장신구) …. 표의 셋째 값이
`-1`이면 남자 전용 줄, `-2`면 여자 전용 줄이다.
