# 근거 기반 아이템 드랍 분배 명세

## 배경

서버에는 아이템 템플릿 2,296개가 있지만 아이템 정보만으로 어느 괴물이 떨어뜨리는지는 알 수 없다. 현재 괴물 템플릿에는 103종 아이템의 655개 드랍 연결이 있고, 그중 14종은 `DropRate`가 없어 목록에 적혀 있어도 절대 떨어지지 않는다. 반대로 괴물 연결 없이 `DropRate`만 남은 925종은 배포팩 잔재이며 드랍 근거로 사용할 수 없다.

## 현재 상태

| 근거 | 현재 값 | 판단 |
|---|---:|---|
| `database/server/templates/items/**/*.json` | 2,296종 | 아이템 정의·수치 근거 |
| `database/server/templates/monsters/**/*.json`의 `Drops` | 103종·655개 연결 | 실제 배치 근거 |
| 위 연결 중 양수 `DropRate` | 89종 | 이미 작동 |
| 위 연결 중 `DropRate` 없음/0 | 14종·155개 연결 | 복구 대상 |
| 괴물 연결 없는 양수 `DropRate` | 925종 | 배치 근거 없음, 제외 |
| `data/server-packs/extracted/5.99-server/mobs.json` | 14종 모두 동일 괴물-아이템과 확률 존재 | 현재 Hades 연결의 원본 확률 근거 |
| 서버팩 3종 공통 괴물-아이템 연결 | 0개 | 새 연결을 만들 근거 없음 |

## 제안 변경

- 기존 Hades 괴물 `Drops`에 이미 있고 5.99 원본에서도 같은 괴물-아이템 연결과 확률이 확인되는 14종만 작동시킨다.
- 원본 확률을 현재 서버의 `DropBoost = 1.5`와 목록 길이에 맞춰 `DropRate = 원본확률 × 목록길이 ÷ 1.5`로 환산한다.
- 한 아이템이 원본에서 여러 확률을 가지면 전역 `DropRate` 하나로 모두 표현할 수 없으므로 가장 낮은 환산값을 사용한다. 근거보다 많이 떨어지는 구역이 없게 하는 보수적 선택이다.
- `LootType.Table`인 단일 목록은 양수 가중치 하나가 사실상 100% 선택이 되므로 `Random`으로 바꾸고 Gold 등 다른 비트는 보존한다.
- 이미 작동하는 89종의 연결·확률은 바꾸지 않는다.
- 연결 근거가 없는 나머지 아이템은 괴물에게 새로 배치하지 않는다.

## 검증 방법

1. 생성기 미리보기에서 14종·155개 연결 외 변경이 없는지 확인한다.
2. `--쓰기` 후 다시 미리보기를 실행해 변경 0을 확인한다.
3. 드랍 볼트와 그래프를 다시 생성해 103종 연결이 모두 기능 상태인지 확인한다.
4. characterization 테스트 전체를 실행한다.

## 롤백 계획

## 결과

- 아이템 2,296종을 감사해 현재 Hades 괴물 `Drops`가 실제로 가리키는 103종·655개 연결만 유지했다. 연결 근거 없이 `DropRate`만 남은 925종은 새로 배치하지 않았다.
- 죽어 있던 14종·155개 연결을 5.99의 동일 괴물-아이템 양수 확률과 교차 확인하고 복구했다. 원본 확률은 현재 서버의 `DropBoost 1.5`와 목록 길이에 맞춰 환산했고, 여러 확률이 있으면 낮은 쪽을 써 근거보다 많이 나오지 않게 했다.
- 단일 `Table`이 양수 가중치 하나로 100% 선택되는 문제를 막기 위해 해당 139개 괴물 템플릿을 `Random`으로 전환했다. `Drops` 목록은 하나도 추가·삭제하지 않았다.
- 생성기는 적용 뒤에도 14종의 정확한 값과 139개 Random 상태를 계속 검사·교정한다. 재실행 결과 `바뀔 DropRate 0종 · 단일 Table → Random 0개`였다.
- 드랍 볼트/그래프를 재생성했다: 사냥터 117, 괴물 569, 관련 아이템 368, 그래프 노드 1,085·간선 2,897. graphify에서 2갱도열쇠→광산드워프/그림록/드라코/오크가드, 고사목뿌리→고사목, 거북이등껍질→터틀 연결을 확인했다.
- 검증: 새 집중 테스트 5/5, 드랍 관련 characterization 21/21, `build-drop-cap.py` 변경 0·최대 79.99%, Lorule.GameServer 빌드 오류 0(기존 Newtonsoft.Json 취약 버전 경고 1).
- 전체 characterization 실행에서는 기존 봇 혼수/뮤레칸 시나리오 `CompanionComaTests`가 단독 재실행에서도 타임아웃으로 실패했다. 드랍 관련 실패는 없었지만 전체 통과로 기록하지 않는다.
