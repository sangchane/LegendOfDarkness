# 보안 유지보수

## 현재 구현 상태

기준 서버는 .NET 5와 파일 기반 저장을 사용하며, 공개 운영을 위한 인증·암호화·권한·감사 체계가 완료됐다는 근거는 없다. Microsoft 지원이 종료된 런타임은 보안 패치를 기대할 수 없으므로 공개 환경 전 업그레이드가 필요하다.

## 공개 전 필수 통제

### 인증과 세션

- 비밀번호는 평문·가역 암호화로 저장하지 않고 현대적인 적응형 비밀번호 해시와 사용자별 salt를 사용한다.
- 기존 계정은 로그인 시 재해시하거나 강제 재설정하는 명시적 이관 경로를 둔다.
- 로그인과 모든 세션 트래픽에 TLS를 적용하고 인증서 검증을 우회하지 않는다.
- 세션 토큰은 충분한 엔트로피, 짧은 만료, 서버 측 폐기, 재사용 탐지를 갖춘다.
- 로그인·계정 생성·복구·게임 명령에 위험 기반 rate limiting과 남용 탐지를 적용한다.

### 권한과 운영 도구

- 플레이어, 운영자, 관리자, 배포자를 RBAC로 분리하고 기본 권한을 최소화한다.
- 관리자 기능은 일반 게임 계정 인증과 분리하고 강한 추가 인증을 요구한다.
- 제재, 아이템 지급, 데이터 수정, 설정 변경은 행위자·대상·이유·결과를 감사 로그로 남긴다.
- 대량 또는 되돌리기 어려운 작업은 미리보기, 범위 제한, 재확인, 이중 승인을 제공한다.

### 입력과 프로토콜

- 네트워크 패킷, 파일, 관리 화면 입력은 모두 불신하고 길이·범위·상태 전이를 검증한다.
- 전투, 이동, 보상, 인벤토리 결과는 서버 권위로 판정한다.
- 비정상 순서, 재전송, 속도 초과, 손상된 저장 데이터를 명시적으로 거부하고 관측한다.
- 오류 응답은 사용자에게 안전한 설명만 주고 스택, 경로, 비밀을 노출하지 않는다.

## 로그와 탐지

- 인증 성공/실패, 권한 거부, 관리자 변경, 데이터 무결성 실패, 배포·설정 변경을 구조화해 기록한다.
- 요청·세션·캐릭터·서버 이벤트를 상관관계 ID로 연결하되 원시 토큰은 기록하지 않는다.
- 비밀번호, 토큰, 쿠키, 비밀키, 개인 식별자는 로그 마스킹 또는 제외 규칙을 적용한다.
- 로그 접근 권한·보존 기간·삭제 정책을 데이터 민감도와 법적 요구에 맞춰 정한다.
- 중요한 감사 로그는 운영 서버와 다른 독립 저장소로 즉시 전송하고 append-only 또는 동등한 변경·삭제 제한을 적용한다.
- 모든 기록 주체의 시간 동기화를 감시하며 누락, 순서 역전, 서명·체크섬 불일치를 무결성 이상 경보로 호출한다.
- 로그 주입, 저장소 고갈, 수집기 장애를 시험하고 로그 실패가 게임 서버를 무한 중단시키지 않도록 한다.

## 비밀 관리

- 저장소, 문서, 이슈, 클라이언트 번들에 비밀을 넣지 않는다.
- 환경별 비밀 저장소와 최소 권한 ID를 사용하고 시작 시 필수값의 존재만 검증한다.
- 노출이 의심되면 즉시 폐기·회전하고 로그와 이력을 포함해 동일 비밀의 재사용을 조사한다.
- 개발·테스트·운영 자격 증명을 분리하고 정기적으로 접근권한을 재검토한다.

## 의존성과 런타임

1. 지원되는 .NET LTS 목표 버전과 업그레이드 책임자를 정한다.
2. 서버·클라이언트·도구별 직접/전이 의존성을 SBOM으로 생성한다.
3. 취약점 경보를 심각도뿐 아니라 실제 노출 경로와 함께 분류한다.
4. 지원 종료일, 패치 주기, 라이선스, 대체 가능성을 의존성 inventory에 기록한다.
5. 보안 업데이트는 호환성 테스트 후 신속히 배포하며, 장기 예외는 만료일과 보완 통제를 둔다.
6. 릴리스마다 산출물 provenance와 SBOM을 보존해 어떤 버전이 어디에 배포됐는지 추적한다.

## 정기 유지보수 주기

| 주기 | 활동 | 완료 근거 |
|---|---|---|
| 매 릴리스 | 비밀 스캔, 의존성·SBOM, 입력 경계 테스트, 권한 변경 검토 | CI 결과와 릴리스 manifest |
| 월간 후보 | 런타임/패키지 패치, 계정·권한 검토, 로그 경보 표본 점검 | 변경·검토 기록 |
| 분기 후보 | 복원·장애 훈련, 위협 모델 갱신, 관리자 기능 감사 | 훈련 보고서와 후속 이슈 |
| 연간/정책 변경 시 | 개인정보·보존·스토어·법적 요구 재검토 | 승인된 정책 버전 |

주기는 위험과 인력에 맞춰 **결정 필요**이며, 캘린더 일정만 만들고 실행 근거가 없으면 완료로 보지 않는다.
