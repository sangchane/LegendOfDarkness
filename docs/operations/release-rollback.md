# 릴리스·롤백

## 현재 구현 상태

Git submodule과 Graphite stacked PR 작업 규칙은 있으나, 게임 서버·모바일 클라이언트·콘텐츠를 하나의 검증된 릴리스로 승격하고 자동 롤백하는 체계는 **미구현**이다.

## 릴리스 단위

한 릴리스 manifest가 다음을 묶어야 한다.

- 상위 저장소 커밋과 각 submodule 커밋
- 서버, 모바일 클라이언트, 에셋/데이터 변환기 버전
- 프로토콜·저장 스키마·콘텐츠 스키마 버전
- 빌드 환경·신뢰된 빌더 ID와 테스트 결과
- 의존성 목록(SBOM), 산출물 digest와 서명된 provenance
- 비밀값을 제외한 설정 스키마와 기능 플래그 기본값

Graphite는 변경 검토와 병합 순서를 관리한다. 배포 시스템은 Graphite 브랜치 이름이 아니라 **병합된 불변 커밋에서 생성된 동일 산출물**을 환경 간 승격해야 한다.

## 호환성 매트릭스

| 조합 | 반드시 확인할 것 |
|---|---|
| 신규 모바일 + 신규 서버 | 전체 핵심 사용자 여정 |
| 구형 모바일 + 신규 서버 | 지원 기간 내 프로토콜·콘텐츠 호환성 |
| 신규 모바일 + 구형 서버 | 롤백 직후 접속·기능 저하 방식 |
| 신규 서버 + 기존 데이터 | 읽기, 쓰기, 재시작, 마이그레이션 |
| 구형 서버 + 마이그레이션 데이터 | 롤백 가능 여부 또는 forward-fix 전용 선언 |

지원하지 않는 조합은 앱에서 명확히 차단하고 최소 지원 버전과 업데이트 이유를 안내한다.

## 배포 전 게이트

- 관련 단위·통합·E2E 테스트와 보안 검사가 통과했다.
- 산출물 digest로 무결성을 확인하고, 허용된 신뢰된 빌더 또는 서명자가 서명한 provenance를 검증했다.
- 데이터 변경은 forward와 rollback 경로를 시험했다.
- 백업과 최근 복원 리허설 근거가 유효하다.
- 관측 대시보드와 경보가 새 기능의 실패를 포착한다.
- 기능 플래그, 점진 배포 범위, 중단 조건, 책임자가 정해졌다.
- 릴리스 노트가 사용자 영향과 운영 변경을 설명한다.

## 배포 흐름

1. 병합된 커밋을 신뢰된 빌더에서 한 번 빌드하고 manifest를 고정한다.
2. 격리 환경에서 데이터·프로토콜 호환성과 핵심 여정을 검증한다.
3. 각 환경에서 digest와 서명한 provenance를 검증한 뒤 내부→비공개 테스트→점진 공개 순으로 같은 산출물을 승격한다.
4. 각 단계에서 오류율, 지연, 로그인·월드 진입·저장 성공률을 관찰한다.
5. 관찰 기간을 통과한 뒤 다음 단계로 진행한다.
6. 완료 후 배포 ID, 판정 근거, 수동 개입, 알려진 문제를 기록한다.

## 롤백 트리거

- 데이터 손상 또는 보안 경계 우회가 감지됨
- 로그인·월드 진입 같은 핵심 여정이 합의 임계값을 벗어남
- 오류율·지연이 지속해서 악화되고 빠른 완화가 없음
- 클라이언트/서버 호환성 실패로 사용자가 고립됨
- 관측 불능으로 안전 여부를 판단할 수 없음

## 롤백과 forward fix 선택

| 조건 | 기본 선택 |
|---|---|
| 이전 버전과 데이터가 호환되고 롤백이 검증됨 | 롤백 |
| 되돌릴 수 없는 데이터 변환이 이미 수행됨 | 쓰기 중지 후 forward fix 또는 복원 |
| 모바일 앱 배포가 회수 불가능함 | 서버 호환 계층·기능 플래그로 완화 |
| 침해 가능성이 있음 | 접근·토큰·비밀 회전까지 포함한 보안 대응 |

롤백 시 코드만 되돌리고 데이터·설정·프로토콜을 방치하지 않는다. 복원은 [백업·복구](backup-restore.md), 심각 장애는 [장애 대응](incident-response.md)에 따라 진행한다.

## 긴급 변경

긴급 변경도 검토·테스트·기록을 생략하지 않는다. 최소 두 번째 검토자가 없으면 IC가 이유와 위험을 기록하고, 변경 직후 정규 검토와 재현 테스트를 수행한다. 스택 작업 상세는 [WORKFLOW](../../WORKFLOW.md)를 따른다.
