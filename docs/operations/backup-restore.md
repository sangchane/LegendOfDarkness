# 백업·복구

## 현재 구현 상태

Hades 기준선은 JSON 파일 저장을 사용한다. 자동 백업, 오프사이트 보관, 암호화, 복원 리허설의 완료 근거는 확인되지 않았으므로 현재는 **부분/미구현**으로 본다.

## 먼저 결정할 것

- **RPO(허용 가능한 데이터 손실 시간): 결정 필요**
- **RTO(허용 가능한 복구 시간): 결정 필요**
- 보존 기간, 서비스 국가, 개인정보 삭제 요청과 백업 만료 방식: 결정 필요
- 복구 승인자와 데이터 손실을 사용자에게 알릴 기준: 결정 필요

초기 측정 후보로 `RPO 24시간, RTO 4시간` 같은 값을 시험할 수 있지만 이는 승인된 약속이 아니다. 실제 저장량·변경 빈도·복원 시간을 측정한 뒤 제품 책임자와 서비스 책임자가 확정한다.

## 보호 대상

| 대상 | 포함 내용 | 주의점 |
|---|---|---|
| 계정·캐릭터 데이터 | 계정 상태, 캐릭터, 인벤토리, 퀘스트 진행 | 백업 중 쓰기 일관성과 개인정보 |
| 월드 운영 데이터 | 맵/스폰/이벤트 설정, 운영 상태 | 코드 버전과의 호환성 |
| 배포 정의 | 설정 스키마, 마이그레이션, 빌드 메타데이터 | 비밀값 자체는 별도 비밀 저장소 |
| 감사·장애 근거 | 보안 이벤트, 변경 이력, 복구 기록 | 접근 통제와 보존 기간 |

소스 코드는 Git과 원격 저장소로 보호하되, Git을 런타임 데이터 백업으로 취급하지 않는다.

## 백업 실행 기준

1. 저장 대상과 쓰기 중지/스냅샷 방식이 데이터 일관성을 보장하는지 확인한다.
2. 생성 시각, 데이터 스키마 버전, 서버 빌드 ID, 파일 수·크기, 체크섬을 manifest에 기록한다.
3. 전송 중·보관 중 암호화하고 운영 서버와 다른 장애 영역에 복제한다.
4. 버전 보존 또는 object lock 같은 불변 보관을 적용해 운영 자격 증명으로 수정하거나 삭제할 수 없는 복구 지점을 만든다.
5. 백업 저장소의 관리 경계를 운영 환경과 분리하고, 백업 계정은 쓰기 전용 또는 최소 권한으로 제한하며 복원·보존정책 변경 권한과 분리한다.
6. 완료 경보는 파일 생성이 아니라 업로드·체크섬·불변 보존 정책 적용까지 확인한다.
7. 실패 시 성공처럼 표시하지 않고 담당자를 호출한다.

## 복원 절차

복원은 먼저 **격리된 비운영 환경**에서 수행한다.

1. 장애 시점과 목표 복원 시점을 정하고 승인자를 기록한다.
2. 호환되는 서버 빌드, 데이터 스키마, 설정 버전을 선택한다.
3. 백업 manifest와 체크섬으로 무결성을 검증한다.
4. 빈 격리 환경에 복원하고 원본 운영 데이터를 덮어쓰지 않는다.
5. 계정 조회, 로그인, 월드 진입, 캐릭터 상태, 인벤토리·퀘스트 표본을 검증한다.
6. 레코드 수, 참조 관계, 중복·누락, 저장 후 재로드를 검사한다.
7. 측정한 복원 시간과 실제 데이터 손실 범위를 RTO/RPO 후보와 비교한다.
8. 운영 반영 전 IC 또는 서비스 책임자의 승인을 받고 운영 쓰기 차단 시각과 범위를 공지한다.
9. 백업 이후 변경분을 폐기·재적용·병합 중 어떻게 처리할지 결정하고 중복 적용을 막는다.
10. 전환 직전 안전 복사본을 별도 복구 지점으로 만들고 무결성을 확인한다.
11. 현재 데이터를 직접 덮어쓰지 않고 원자적 교체가 가능한 새 경로로 전환한다.
12. 핵심 여정과 저장 재시도를 확인하고 오류·불일치가 중단 조건에 해당하면 이전 경로로 되돌린다.
13. 관찰 기간 후 쓰기를 재개하고 이전 상태의 보존 위치와 폐기 예정일을 기록한다.

## 복원 리허설

- 공개 테스트 전 1회 이상 전체 복원을 성공시킨다.
- 이후 주기는 데이터 변경량과 약속한 RTO/RPO에 맞춰 결정한다.
- 사람·자격 증명·문서가 모두 필요한 실제 조건으로 훈련한다.
- 운영 자격 증명이 탈취됐다고 가정하고 불변 복구 지점을 지울 수 없는지 삭제 내성 시험을 수행한다.
- 성공 기준은 서버 프로세스 시작이 아니라 핵심 사용자 여정과 데이터 무결성 통과다.
- 실패한 리허설은 장애 후보로 등록하고 다음 승격을 막는다.

## 복원 기록 템플릿

```text
백업 ID / 생성 시각:
대상 데이터 / 스키마 / 빌드:
복원 환경:
시작 / 완료 시각:
무결성 검사 결과:
사용자 여정 검사 결과:
추정 데이터 손실 범위:
실패·수동 개입:
승인자 / 후속 작업:
```

보안 통제는 [보안 유지보수](security-maintenance.md), 서비스 승격 기준은 [서비스 준비도](service-readiness.md)를 따른다.
