# LOD 운영·유지보수 기준

이 디렉터리는 LOD를 **분석 가능한 코드 저장소**에서 **운영 가능한 게임 서비스**로 전환할 때 필요한 판단 기준과 반복 절차를 모은다. 문서가 있다는 사실은 기능 구현이나 운영 준비 완료를 뜻하지 않는다.

## 현재 상태

- 현재는 로컬 분석·실행 검증 단계다.
- Hades/Lorule은 서버 기준선이며, 그대로 공개 운영할 수 있는 완성 시스템으로 판정하지 않는다.
- 수치 목표, 담당자, 승인자는 아직 정해지지 않은 항목이 있으므로 `결정 필요`로 표시한다.

## 상태 표기

| 표기 | 뜻 | 판정에 필요한 것 |
|---|---|---|
| 확인됨 | 실행 또는 문서 근거로 현재 사실을 확인 | 명령 결과, 테스트, 코드 위치 또는 로그 |
| 부분 | 일부만 구현·검증 | 남은 범위와 위험 기록 |
| 미구현 | 목표는 있으나 구현·검증 없음 | 이슈와 완료 조건 |
| 결정 필요 | 제품·운영 책임자의 선택이 선행 | 선택지, 영향, 결정자, 기한 |

## 문서 지도

1. [서비스 준비도](service-readiness.md) — 어느 단계까지 공개할 수 있는지 판단하는 게이트
2. [장애 대응](incident-response.md) — 감지부터 사후 검토까지의 역할과 흐름
3. [백업·복구](backup-restore.md) — 무엇을 얼마나 자주 보존하고 실제 복구를 어떻게 증명할지
4. [릴리스·롤백](release-rollback.md) — 빌드 출처, 호환성, 배포 승인과 되돌리기
5. [보안 유지보수](security-maintenance.md) — 인증, 권한, 비밀, 로그, 의존성 수명 관리

실제 로컬 기동은 [실행 절차](../run-procedure.md), 현재 구조의 근거는 [현행 분석](../current-system-analysis/README.md), 변경 흐름은 [WORKFLOW](../../WORKFLOW.md), 다음 구현 우선순위는 [NEXT](../../NEXT.md)를 따른다.

## 운영 원칙

- 대시보드는 상태를 요약하지만, 모든 녹색 판정은 재현 가능한 근거로 연결한다.
- 사람 이름보다 역할을 기록한다. 최소 역할은 제품 책임자, 서비스 책임자, 당번 운영자다.
- 자동화 실패 시 조용히 통과시키지 않는다. 차단하거나 명시적으로 위험을 승인한다.
- 비밀값, 개인정보, 세션 토큰은 이 문서·이슈·대시보드·일반 로그에 기록하지 않는다.
- 복구 절차는 백업 생성 성공이 아니라 격리 환경의 복원 성공으로 검증한다.
- 공개 범위를 늘릴 때마다 준비도 게이트를 다시 판정한다.

## 검증 증거

이 문서 묶음의 사용자 여정은 “개발·운영 책임자가 현재 준비 수준을 과장 없이 파악하고, 장애·복구·릴리스·보안 결정을 같은 기준으로 수행한다”이다.

| 단계 | 실행 명령 | 결과 | 보장 범위 |
|---|---|---|---|
| 최초 RED | `node --test tests/operations-docs.test.js` | 7 실패 / 0 통과 | 문서가 없을 때 검증이 실제로 실패함 |
| 리뷰 RED | `node --test tests/operations-docs.test.js` | 5 실패 / 6 통과 | 불변 백업·서명된 출처·보안 사고·안전 전환·근거 판정 누락을 포착함 |
| 재리뷰 RED | `node --test tests/operations-docs.test.js` | 1 실패 / 10 통과 | 감사 로그의 독립 보존·변조 탐지 누락을 포착함 |
| GREEN | `node --test tests/operations-docs.test.js` | 11 통과 / 0 실패 | 필수 문서·안전 기준·상태 고지와 로컬 링크가 유효함 |
| 전체 회귀 | `node --test tests/*.test.js` | 22 통과 / 0 실패 | 기존 대시보드 검증과 새 운영 문서 검증이 함께 통과함 |

문서 내용의 존재와 로컬 링크는 자동 검증하지만, 실제 인프라·복원 시간·당번 호출·보안 통제의 동작은 아직 검증하지 않는다. 각 문서에서 `미구현` 또는 `결정 필요`로 관리한다.
