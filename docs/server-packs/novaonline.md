# NovaOnline 서버팩

원본 `sources/novaonline/` · 서버 `Legend.exe` · 방법은 [server-pack-data.md](../server-pack-data.md)

**세부는 `data/server-packs/vault/novaonline/`를 Obsidian으로 열어 본다.** 노트 7,004장과
Graphify 그래프 7,003노드·10,353간선을 만들었다. graph·vault는 재생성 산출물이라 커밋하지 않고,
UTF-8 입력 사본과 정규화 JSON만 `data/server-packs/` 아래에 둔다.

## 무엇이 추가됐나

이전 자료는 서버팩 둘(`5.99-server`, `honden-community`)과 클라이언트팩 하나였다.
NovaOnline을 더해 **서버팩 셋 + Hades 기준선 하나**를 비교할 수 있게 됐다.

`Legend.exe`는 32비트 Windows PE 실행파일이다. 따라서 이 팩은 C# 소스인 Hades와 달리
**네이티브 바이너리로 배포된 서버팩**이라고 말할 수 있다. 소스와 심볼이 없으므로 C와 C++ 중
어느 언어로 구현됐는지는 실행파일만 보고 확정하지 않는다.

| | | | |
|---|---|---|---|
| 아이템 3,508 | 맵 748 | 괴물 607 | 스크립트 467 |
| 워프 4,370 | 괴물 젠 1,605 | NPC 배치 340 | 상점 122 |
| 기술 155 | 마법 156 | NPC 409 | 월드맵 1 |
| **엔진 명령 322** | 퀘스트 변수 48 | 이벤트 0 | 문 1 |

위 수는 매니페스트에 실린 원자료 행 수다. 이름이 겹치는 정의를 한 노트로 합친 vault에서는
맵 744·괴물 598·NPC 403이다. `*_db.txt`가 선언하지 않은 텍스트 파일은 87개이며 활성 데이터
수에는 넣지 않는다. 선언했지만 없는 파일은 0개다.

## 가져오기와 출처

`db/**/*.txt` 350개만 엄격하게 디코딩했다: CP949 334개, UTF-8 계열 16개. 실행파일·DLL·맵·
세이브·로그는 복사하지 않았다. `data/server-packs/novaonline/source.json`에 입력 경로와 인코딩,
`Legend.exe`의 SHA-256을 남긴다. 원본 폴더는 현재 Git 저장소나 submodule이 아니라 로컬 자료이므로,
재현 가능한 원본 보관까지 하려면 나중에 출처 URL 또는 별도 아카이브 정책을 정해야 한다.

## 퀘스트와 명령

독립 퀘스트 표는 없다. 스크립트에서 영속변수 48개를 찾았고 그중 16개가 여러 단계를 가지며,
11개는 NPC와 이어지고 5개는 보상을 가진다. 퀘스트 정본으로 승격하지 않고 NPC·아이템·워프
간선과 함께 조사 단서로 쓴다.

`Legend.exe`의 명령표에서는 엔진 명령 322개를 복원했다. 팩 스크립트가 부르는 것은 226개이고
제어문 5개가 별도다. Nova에는 아직 기계어 disassembly 증거가 없어, 명령 노트는 이름·인자서명까지만
확정하고 내부 구조체 필드의 뜻은 추정하지 않는다.

| 아이템 | 989 | 3,138 | 3,508 | 449 | 601 | 1,164 | 357 |

| NPC | 31 | 438 | 403 | 3 | 3 | 24 | 2 |
| 기술 | 82 | 184 | 155 | 58 | 55 | 62 | 49 |

셋 모두 이름이 같은 항목도 그림 번호까지 전부 맞지는 않는다. 괴물은 22개 중 16개, 아이템은
357개 중 320개, NPC는 2개 중 1개, 기술은 49개 중 40개, 마법은 44개 중 38개만 그림 번호까지
일치한다. 이름 하나만 보고 자동 병합하면 충돌을 숨긴다는 뜻이다.

또한 5.99와 Nova는 NovaOnline 계보를 공유할 가능성이 높다. 두 팩의 일치를 **독립된 두 표의
합의**로 세기 전에 배포 계보를 확인해야 한다. 혼든과의 일치도 운영자가 복사한 결과일 수 있으므로
팩 합의는 원작 정본보다 항상 아래에 둔다.

## Hades 한글화·보강에 쓰는 판정 규칙

Hades 원본에 괴물이 3개뿐이라는 말은 맞다. 현재 작업본의 568개는 Hades 원본 3개와 앞서 가져온
팩 정의 565개를 합친 수다. 따라서 이미 568개가 있다는 사실이 그 값의 신뢰성을 보장하지 않는다.

판정 등급은 네 단계로 고정한다.

1. `VERIFIED` — Hades 또는 원작 7.18 자료가 직접 말한다.
2. `PACK_CONSENSUS` — 계보가 독립적이라고 확인된 팩 둘 이상이 여러 식별 신호에 합의한다.
3. `EXTRACTED_SINGLE` — 팩 하나에서만 추출됐다.
4. `CONFLICT` — 이름·그림·배치·관계 중 하나라도 충돌한다. 자동 반영하지 않는다.

갈래별 식별 신호는 다음과 같다.

- 괴물: 이름 + 그림 + 출현 맵/젠 문맥. 체력·공격력·방어력 같은 운영 수치는 동일성 증거로 쓰지 않는다.
- 맵·워프: 맵 ID + 이름 + 맵 파일, 출발/도착 좌표와 연결 위상. 중복 ID는 충돌로 남긴다.
- 아이템: 이름 + 타입/하위타입 + 그림 + 착용 부위. 그림 재사용 때문에 단순 1:1 매칭하지 않는다.
- 기술·마법: 아이콘 + 실행 스크립트 + 요구 조건. Hades 영문 이름의 한글 별칭은 이 조합이 맞을 때 붙인다.
- NPC: 이름 + 그림 + 배치 맵/좌표 + 호출 스크립트.
- 퀘스트: 영속변수 + 단계 전이 + NPC·아이템·워프 관계 그래프.

다음 구현은 Hades 파일을 바로 덮어쓰는 일이 아니다. 먼저 팩 수를 고정하지 않는 N팩 비교기를 만들어
각 후보의 출처·일치 신호·충돌 사유·신뢰 등급을 JSON으로 내보내고, 사람이 검토한 승인표만 Hades
한글 별칭과 콘텐츠 보강 입력으로 사용한다.
